An iRule spends much of its time building values: a redirect location from a host and a path, a log line from several fields, a pool name from a header. Tcl (Tool Command Language) has no string operators for this. It builds values while it splits a command into words, and the rules for that are short. iRules run Tcl 8.4.6 (F5 K6091), whose manual page `Tcl` states them.

## Three ways to write a word

- **Double quotes** substitute: `$name` becomes the variable's value, `[command]` becomes the command's result, and backslash sequences are replaced. The quotes then disappear, and the result is one word, spaces and all.
- **Braces** do not substitute anything. `{$a $b}` is the six characters `$a $b`, exactly.
- **Brackets** run a command and put its result in place: `[string tolower [HTTP::host]]`.

The manual adds the rule that settles most arguments: each character is processed exactly once while the words are built. A value that happens to contain `$` or `[` is not substituted again by the word rules. In this tclsh session, each command follows the `%` prompt and its result is on the next line:

```tcl
% set a "foo"
foo
% set b "bar"
bar
% set c "$a$b"
foobar
% set d "$a $b"
foo bar
% set e {$a $b}
$a $b
```

## Where a variable name ends

`$name` takes the longest run of letters, digits and underscores, so `"$host_pool"` looks for a variable called `host_pool`, and fails with "can't read host_pool: no such variable" if there is none. Braces mark the end of the name: `"${host}_pool"` is the value of `host` followed by `_pool`. The DevCentral iRules Style Guide asks for the braced form inside expressions for the same reason.

## append, concat and lappend

Three commands build longer values, and they do different things with spaces:

```tcl
set x " a "
# The text is added exactly as given: x is now " a  b"
append x " b"
# Each argument is trimmed, then joined with one space: y is "a b"
set y [concat " a " " b"]
set l {}
# Each argument becomes one list element: l is {{one two} three}
lappend l "one two" three
```

`append` is for text, and the manual notes it is the efficient way to grow a long value. `concat` trims the white space at both ends of every argument, drops empty ones, and joins what is left with single spaces. `lappend` adds each value as one list element, quoting it if it contains spaces.

## A value with spaces is a list

Tcl lists are strings split on white space (with braces and quotes for grouping). So `foreach item "red green blue"` runs three times, once per word. That is convenient for values you built as lists and surprising for values that merely contain spaces, such as a header. Build lists with `list` and `lappend`, keep free text out of `foreach`, and use `split` with an explicit separator when a value is delimited by something else:

```tcl
foreach part [split [HTTP::path] "/"] {
    log local0. "segment: $part"
}
```

## incr reads octal too

`incr` requires an integer and reads it the way `expr` does, so a variable holding `010` is octal eight and `incr` makes it `9`. Zero-padded counters and codes are worth converting with `scan $v %d v` before they are used as numbers.

## Double substitution

Some commands evaluate their arguments again: `expr`, and the conditions of `if` and `while`, parse their argument as an expression and substitute inside it a second time. If that argument is not braced, a value from the request takes part in the second round:

```tcl
set count [HTTP::header value X-Count]
# Never do this: unbraced, the header value goes through a second round of substitution
set next [expr $count + 1]
# Braced: ${count} is only ever a value
set next [expr { ${count} + 1 }]
```

If a client sends an `X-Count` header that contains `[...]`, the unbraced form runs the bracketed text as a command during the second substitution. F5's K15650046 describes this as a coding-practice exposure rather than a product vulnerability, and K57410758 documents the validator warning "use curly braces to avoid double substitution". The fix is the same in both: brace expressions, as in `if { $ua eq "curl" }`, and put `--` before a value passed to `switch`, so a value starting with a dash cannot be read as an option.
