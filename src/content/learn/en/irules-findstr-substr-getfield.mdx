Tcl already has `string first`, `string range` and `split`. F5 added three commands of its own to iRules for the most common cut: find a marker, skip past it, and stop at another. They are short to write, and their reference pages leave a few cases open, which matters when a value from a request is not shaped the way you expected.

## findstr: find, skip, stop

`findstr string search ?skip? ?terminator?` finds the first occurrence of `search`, moves `skip` characters on from the **start of the match**, and returns everything up to the terminator. F5's tmsh reference gives two examples:

```tcl
# returns sip.example.com
findstr "<sip:+12065551234@sip.example.com>" "@" 1 ">"
# returns 123456x
findstr "aaa123456xxyz" "aaa" 3 "xyz"
```

In the second example the result stops before the first `xyz`, so the `x` before it stays in the result. The usual iRules use is a query parameter, where the skip is the length of the marker:

```tcl
# returns abcdefg
findstr "/login.php?user=abcdefg&lang=en" "user=" 5 "&"
```

## substr: start at an index

`substr string skip ?terminator?` starts at index `skip`, where 0 is the first character, and returns up to the terminator. F5's examples, all on the same string:

```tcl
# returns cdefghijklm: there is no x after index 2, so it runs to the end
substr "abcdefghijklm" 2 "x"
# returns cdef
substr "abcdefghijklm" 2 "gh"
# returns cdef
substr "abcdefghijklm" 2 4
# returns cdefghijklm
substr "abcdefghijklm" 2 20
```

## The terminator is a length or a text

For both commands, a terminator that is an integer is a **length**: that many characters, or up to the end of the string, whichever is shorter. Any other terminator is **text** to stop just before; if that text does not appear, `substr`'s page says the rest of the string is returned. The integer test is Tcl's, so a terminator written `010` is octal eight.

## getfield: split and pick

`getfield string separator field` splits at every occurrence of the separator, which may be one character or a whole string, and returns the field, counting from 1:

```tcl
# returns b
getfield "a:b:c" ":" 2
# returns user=abc
getfield "/login.php?user=abc" "?" 2
# returns three
getfield "one--two--three" "--" 3
```

## The same jobs in plain Tcl

- two-argument `findstr` is, in F5's own description, `string range` from `string first` to `end`;
- `substr` with a length is `string range $s $skip [expr {$skip + $len - 1}]`;
- `getfield` with a one-character separator is `lindex [split $s $sep] [expr {$n - 1}]`, since list indexes count from 0. With a longer separator there is no direct equivalent, because `split` treats every character of its second argument as a separator of its own.

## What the pages leave open

Reading the reference pages closely turns up cases they do not settle. Check these on a BIG-IP before you depend on them:

- **`findstr` when the search text is absent.** No page says what is returned. F5 calls two-argument `findstr` equivalent to `string range` with `string first`, but that equivalent returns the **whole** string when the text is absent (because `string first` returns -1), which is unlikely to be what `findstr` does.
- **A count of 0.** The rule says an integer terminator returns that many characters, which would make 0 return nothing. F5's own `substr` example with 0 returns the rest of the string (`substr "abcdefghijklm" 2 0` gives `cdefghijklm`), and a contributor note on the older API reference page reports that the 0 form did not work for them on 11.5.4 and 11.6.0.
- **A skip past the end, a negative skip or count, an empty terminator, and a field number outside the fields** are not covered either.

None of these is exotic in production: a request without the parameter you look for is the normal case on most of a site's traffic.
