## O problema está no core

Uma rede comutada tradicional mantém o core sem loops com o spanning tree, o que significa bloquear links para quebrar os loops, e empilha um protocolo sobre o outro para entregar serviços: trunks 802.1Q para as VLANs, talvez MPLS (Multiprotocol Label Switching) ou VXLAN com BGP para a virtualização, e mais alguma coisa para transportar multicast. Cada camada é mais uma coisa para projetar, provisionar em cada hop (cada switch do caminho) e incluir no troubleshooting. O VOSS (o **Fabric Connect** da Extreme) foi criado para acabar com essa pilha.

## O que é o Fabric Connect

O Fabric Connect é a implementação da Extreme do **Shortest Path Bridging MAC**, ou **SPBM**, padronizado como **IEEE 802.1aq** (com extensões IP na RFC 6329 do IETF). A tecnologia tem uma longa história: vem da antiga Nortel e da Avaya, que implementaram o SPBM cedo e de forma completa. A ideia é reduzir o core a um único protocolo link-state baseado em Ethernet, que oferece todos os serviços de virtualização num modelo integrado, em vez de uma pilha de overlays.

Duas peças fazem isso funcionar:

- um **plano de dados** baseado em **MAC-in-MAC**: os frames (quadros) do cliente são encapsulados num header de backbone MAC e comutados pelo core com base nos endereços MAC de backbone (B-MACs), de modo que o core nunca examina o frame do cliente; e
- um **plano de controle** baseado em **IS-IS**: os nós formam adjacências, descobrem a topologia, calculam os caminhos mais curtos até todos os outros nós e anunciam de quais serviços cada um participa, tudo num único protocolo.

## Sem spanning tree no core

O SPBM não roda spanning tree na fabric. O transporte usa duas **Backbone VLANs** (B-VLANs, normalmente a 4051 e a 4052). Uma B-VLAN não é uma VLAN comum: ela nunca faz flooding de tráfego desconhecido (unknown), broadcast ou multicast. Ela encaminha estritamente pelas tabelas de backbone MAC que o IS-IS monta, seguindo o caminho mais curto que o IS-IS calculou. Como o encaminhamento é calculado, e não aprendido por flooding, todos os links podem carregar tráfego, e a convergência é rápida.

## Configure a borda e deixe o core em paz

Os switches na fronteira da fabric são os **Backbone Edge Bridges (BEBs)**; os switches de trânsito, no meio, são os **Backbone Core Bridges (BCBs)**. Toda a configuração de serviço acontece nos BEBs, onde a aplicação encontra a rede: é ali que você associa uma VLAN ou uma instância de roteamento a um serviço, e o IS-IS propaga essa associação por flooding, para que todos os BEBs envolvidos participem. Os BCBs no meio do caminho são provisionados uma única vez, para a própria fabric, e depois ninguém mexe mais neles; eles carregam qualquer serviço sem configuração por serviço. É a promessa do SPBM que muita gente resume como "construir a rede uma vez e não mexer mais nela".
