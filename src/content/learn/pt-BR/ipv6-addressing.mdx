## Por que o IPv6 existe

O IPv4 tem cerca de 4,3 bilhões de endereços (2^32). Nos anos 1980, isso parecia não ter fim; hoje, o estoque livre dos registros de endereços acabou faz tempo. O IPv6, cujo endereçamento é definido na RFC 4291, aumenta o endereço de 32 para **128 bits**, ou seja, 2^128 endereços, um número tão grande que a falta de endereços deixa de ditar o projeto da rede. Na prática, as sub-redes ficam enormes, e truques para economizar endereços, como o NAT (network address translation, a tradução de endereços de rede), deixam de ser necessários para a conectividade básica.

## A estrutura de 128 bits

Um endereço IPv6 tem 128 bits e é escrito como **oito grupos de quatro dígitos hexadecimais**, separados por dois-pontos. Cada grupo representa 16 bits:

```
2001:0db8:0000:0000:0008:0800:200c:417a
```

Essa é a forma **expandida**, com tudo escrito por extenso. Como ela é longa e cheia de zeros, a escrita tem regras de compressão.

## Como escrever um endereço: as regras de compressão

São duas regras para encurtar o texto, e a RFC 5952 torna o resultado canônico (cada endereço passa a ter uma única forma preferida de escrita):

- **Tire os zeros à esquerda** de cada grupo: `0db8` vira `db8`, e `0000` vira `0`.
- **Troque uma sequência de grupos consecutivos só de zeros por `::`**. Esses dois-pontos duplos podem aparecer **no máximo uma vez** e representam um ou mais grupos de 16 bits zerados. Se houver várias sequências com o mesmo tamanho, comprime-se a primeira.

Com as duas regras aplicadas ao endereço acima, chegamos à forma canônica:

```
2001:db8::8:800:200c:417a
```

A RFC 5952 acrescenta algumas regras de acabamento para que todas as ferramentas escrevam o endereço do mesmo jeito: os dígitos hexadecimais ficam em minúsculas, e o `::` não é usado para "comprimir" um único grupo de zeros (não economizaria nada que valesse a pena). A ferramenta IPv6 mostra lado a lado a forma canônica comprimida e a forma expandida completa, para você ver exatamente o que o `::` está substituindo.

Um caso especial: os últimos 32 bits de um endereço podem trazer um **IPv4 embutido**, escrito na notação decimal com pontos. O caso mais comum é o endereço **IPv4 mapeado**, para o qual a RFC 5952 recomenda a notação mista `::ffff:192.0.2.128` em vez de hexadecimal puro.

## Prefixos e o cálculo de prefixos

Como no CIDR do IPv4, um prefixo IPv6 é escrito como `endereço/comprimento`, em que o comprimento é a quantidade de bits de rede, contados a partir do início do endereço:

```
2001:db8::/64
```

Um `/64` quer dizer que os primeiros 64 bits são a rede e os 64 restantes são o identificador de interface (interface ID). O `/64` é o tamanho padrão de uma LAN, e uma única rede desse tamanho já comporta 2^64 endereços, cerca de 18 quintilhões. Para qualquer prefixo que você informar, a ferramenta calcula o endereço de rede (o primeiro), o último endereço e a quantidade de endereços; ela zera os bits de host para achar a rede, mesmo que você tenha digitado um endereço com bits de host diferentes de zero.

## Tipos de endereço e escopos

Os primeiros bits de um endereço definem a categoria dele. As mais importantes, segundo a RFC 4291 e o registro da IANA:

- **Global unicast (2000::/3)** é o espaço público roteável, o equivalente IPv6 de um endereço IPv4 público.
- **Unique local, ou ULA (fc00::/7)**, é o espaço de uso privado (RFC 4193), o equivalente da RFC 1918 no IPv4. Esse espaço não é roteado na internet pública.
- **Link-local unicast (fe80::/10)** só vale dentro de um único link e é configurado automaticamente em toda interface IPv6. Os roteadores nunca encaminham esse tráfego; o escopo dele é o link local.
- **Multicast (ff00::/8)** se destina a um grupo, e não a um único host. Um campo de escopo dentro do próprio endereço diz até onde ele chega: interface-local, link-local, admin-local, site-local, organization-local ou global. Por exemplo, `ff02::1` é o grupo all-nodes (todos os nós) de escopo link-local.
- **Loopback (::1/128)** é o equivalente IPv6 do 127.0.0.1, e o **endereço não especificado (::/128)** significa "nenhum endereço": ele fica no lugar do endereço enquanto a configuração não termina.
- **Documentação (2001:db8::/32)** é um bloco reservado pela RFC 3849 para exemplos e textos técnicos; é por isso que quase todo exemplo de IPv6 que você encontra, inclusive o exemplo clássico da própria RFC 4291, usa esse bloco.

A ferramenta IPv6 informa o tipo do endereço e o prefixo exato em que ele se encaixou, além do escopo, no caso de endereços multicast e link-local.

## O identificador de interface e o EUI-64

Num `/64` típico, os 64 bits finais formam o **identificador de interface**. Uma das formas tradicionais de montá-lo era o **EUI-64 modificado** (RFC 4291, Apêndice A): pegue o endereço MAC de 48 bits, insira os bytes `ff:fe` no meio e inverta o sétimo bit (o bit universal/local). Assim, o interface ID podia ser calculado a partir do endereço de hardware. Quando a ferramenta encontra o `ff:fe` no meio do interface ID, que denuncia esse método, ela faz o caminho inverso e mostra o MAC original. Os sistemas modernos costumam preferir interface IDs aleatórios ou de privacidade, justamente porque derivar o ID do MAC expõe o endereço de hardware.

## DNS reverso: ip6.arpa

No IPv6, as consultas reversas (de endereço para nome) ficam sob o domínio **ip6.arpa**. O endereço é expandido para os seus 32 nibbles, os dígitos hexadecimais; a ordem desses nibbles é invertida, e cada um vira um label (rótulo) do nome. Assim, `2001:db8::1` vira um nome terminado em `...8.b.d.0.1.0.0.2.ip6.arpa`. A ferramenta gera esse nome para qualquer endereço, e ele é exatamente o valor que você colocaria num registro `PTR`.

## O que a ferramenta faz e o que ela não faz

A ferramenta IPv6 é uma calculadora determinística, que roda localmente. Ela interpreta o endereço, coloca na forma canônica, classifica e calcula, tudo no seu navegador, sem fazer nenhuma consulta à rede real. Ela diz o que um endereço **é**, do ponto de vista da estrutura. Ela não diz se o endereço está alcançável, se foi alocado ou se está em uso: essas são outras perguntas, e para respondê-las é preciso consultar a rede ou um registro de endereços.
