## What it does

This tool is a linter for F5 Distributed Cloud (XC) configuration objects. Paste an origin_pool, http_loadbalancer, or app_firewall object - from the Console's JSON view or the API - and it flags settings that are risky, surprising, or likely mistakes, each with a severity and a short explanation grounded in F5's documentation. It runs entirely in your browser, and it introduces no new schema: every rule reuses the object structures verified for the other tools in this family.

## What it checks

For an origin pool, the linter flags TLS to the origin with server verification skipped (the connection is encrypted but the origin's certificate is not validated), SNI disabled, cleartext to the origin, an absent health check, and a single origin server with no redundancy. For an HTTP load balancer, it flags no WAF attached, a plain-HTTP listener with no HTTPS, HTTPS configured without an HTTP-to-HTTPS redirect, a route that disables the WAF, a catch-all route placed before other routes (which can never match under first-match evaluation), and a wildcard domain mixed with its apex. For a WAF, it flags monitoring mode (detects but does not block) and disabled threat campaigns.

## Severity and grounding

Each finding carries a severity - high, warn, or info - and the list is sorted with the most serious first. High is reserved for a setting that materially weakens security, like skipping origin verification. Warn covers settings that are usually wrong, like no WAF or a shadowed route. Info covers things worth knowing but often intentional, like a single origin. Every rule cites the F5 source it is based on, so a flag is a starting point for a decision rather than a verdict - some of these settings are the right choice in context, and the linter says why each one matters so you can decide.

## What it is not

The linter reads one object at a time and reasons only about what is inside it. It cannot see whether a WAF referenced by name is itself in monitoring mode, or whether an origin pool referenced by a route carries a weight - those live in other objects. It is a fast first pass over a single object's own settings, not a full configuration audit.

## Share results

Under the findings, **Share results** builds a link to this page, only when you press it, that carries a copy of the object after the `#`, never the object as pasted. An origin pool, load balancer or WAF object can hold secrets the linter never reads. F5 Distributed Cloud's schema marks them: SecretType, "used in an object to indicate a sensitive/confidential field", holds the secret either in clear (`clear_secret_info.url`: "For string:/// scheme, Secret needs to be encoded Base64 format") or encrypted by Blindfold (`blindfold_secret_info.location`) ([XC API reference](https://docs.cloud.f5.com/docs-v2/api/views-http-loadbalancer), read 2026-11-01): a certificate's private key, a header's or cookie's `secret_value`, an mTLS client key. The plain `value` of a header or cookie a load balancer adds ("Exclusive with [secret_value]") is a common place for an origin's shared secret too. The linter reads which settings are present and a few names and domains, never those values. So the copy replaces every SecretType secret and every added header or cookie value with `[redacted]`, and keeps every other byte as pasted. Before the link is offered, the page reads the copy again and must lint the same, or there is no link; then the copy is searched for a credential that is still there (a private key outside SecretType, an `Authorization` header matcher's value, a JWT, a password in a URL, read as in the site's other tools): one means no link, and the popover names its line; a value whose name only looks like a secret is named in the popover instead.

Its popover says first what the link carries, then offers Copy link and, where the browser has one, its share sheet; the page's address is not changed. It also says how many values were replaced, and that the object names its pools, hosts and domains, and may name its tenant and namespace. When the copy replaced only header or cookie values (none of them an `Authorization` value or one whose name looks secret, and nothing else in the object a credential), a switch under its first line, **Include the replaced header and cookie values in the link**, lets you send them after all: it is off every time the popover opens; ticked, the link carries the object as pasted, and the popover warns that header and cookie values can hold tokens or an origin's shared secret. The switch is never offered beside a SecretType secret, nor when a credential has stopped the link.

[RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (section 3.5, read 2026-11-01) has the fragment "separated from the rest of the URI prior to a dereference", so what follows the `#` is not sent to the server when the link is opened; it stays in the address bar and the history of whoever opens it, and anyone who has the link can read it.

- **How long.** At most 16,384 characters in all, the bound the site uses for every value after the `#`; a longer share gets no link, and the popover says how long it is.
- **Opening a link.** The copy (or, with the switch, the object) fills the box as a paste would, and the page lints it. The values then leave the page's address at once, without a request, so a reload or the page's own Share button carries nothing.
