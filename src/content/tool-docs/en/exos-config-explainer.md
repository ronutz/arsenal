## What it does

Paste an ExtremeXOS (EXOS, now branded Switch Engine) configuration and this reads it back without touching a switch: a plain-English explanation of each command, an aggregated VLAN summary, and the commands grouped by category. EXOS is unlike Cisco IOS or FortiOS in one structural way that makes an explainer genuinely useful: it has no interface sub-modes. Every line is a self-contained imperative command, so a config reads as a flat list rather than nested blocks. This tool runs entirely in your browser and is grounded in the ExtremeXOS Command Reference.

## The command model

Every EXOS command begins with one of six verbs acting on a named object: `create` (make a new VLAN, account, or STP domain), `configure` (set a property on something that already exists, the workhorse verb), `enable` and `disable` (turn a feature or object on and off), `delete` (remove an object), and `unconfigure` (reset part of the config to default). Because there is no mode nesting, you read each line on its own. The tool labels each command with its verb and category so the structure is visible at a glance.

## VLANs and ports

The most common EXOS commands build VLANs and assign ports, and the tool aggregates them into a per-VLAN summary. It follows `create vlan <name> tag <id>`, `configure vlan <name> add ports <portlist> tagged|untagged`, and `configure vlan <name> ipaddress <ip>` across the whole config, then shows each VLAN with its tag, its tagged and untagged ports, and any IP address. Two rules from the documentation are surfaced where relevant: tagged ports carry the 802.1Q tag and can belong to many VLANs (a trunk), while an untagged port can belong to only one VLAN and must first be removed from the Default VLAN. Ports are written slot:port on stacked and modular switches (for example 1:1, 2:24) and as plain numbers on a stand-alone switch.

## Layer 3, link aggregation, and the rest

Assigning an IP address to a VLAN makes it a routed interface, but the switch still needs `enable ipforwarding` to route between interfaces, so the tool warns when a VLAN has an IP but no ipforwarding command was seen. Link aggregation has an EXOS-specific name and shape: a LAG is a "sharing" group created with `enable sharing <master-port> grouping <portlist>` and referenced by its master port, which the tool calls out. Static routes (`configure iproute add default`), spanning tree (`create stpd`, `configure stpd add vlan`), local accounts (`create account <role> <name>`), and management services (SNMP, SNTP, DNS, logging, LLDP) are each recognised, explained, and grouped under their category.

## Scope and grounding

This parses and explains; it never connects to a switch, runs a command, or fetches anything, and the same input always produces the same output. It models the command grammar and recognises the common commands; it is not a full ExtremeXOS parser, and an unusual or newer command it does not recognise is shown with a generic explanation rather than a wrong one. Every fact comes from the ExtremeXOS Command Reference and the Switch Engine user guide. Nothing you paste leaves the page.

## Share results

Under the findings, **Share results** builds a link to this page, only when you press it, that carries after the `#` a copy of the configuration in which every secret value is replaced by `[redacted]`, never the configuration as pasted. Its popover says first what the link carries, how many values were replaced, and a caution (the copy still names addresses, VLANs, ports and hosts), then offers Copy link and, where the browser has one, its share sheet; the page's address is not changed.

A saved EXOS configuration carries credentials in plain sight. The values replaced are the ones Extreme's Switch Engine v33.7.1 Command References define (read 2026-11-01, the newest edition published): the password of [create account](https://documentation.extremenetworks.com/Switch%20Engine%20v33.7.1%20Command%20References/content/documents/Switch_Operating_Systems/Switch_Engine/Command_References/create_account.shtml), also in its `encrypted` form, which the switch "will de-crypt" into the plain password when it is pasted into another switch, and of [configure account ... encrypted](https://documentation.extremenetworks.com/Switch%20Engine%20v33.7.1%20Command%20References/content/documents/Switch_Operating_Systems/Switch_Engine/Command_References/configure_account_encrypted.shtml); SNMP community strings, which "provide a simple method of authentication between a switch and a remote network manager" ([configure snmp add community](https://documentation.extremenetworks.com/Switch%20Engine%20v33.7.1%20Command%20References/content/documents/Switch_Operating_Systems/Switch_Engine/Command_References/configure_snmp_add_community.shtml), and the index and name of [configure snmpv3 add community](https://documentation.extremenetworks.com/Switch%20Engine%20v33.7.1%20Command%20References/content/documents/Switch_Operating_Systems/Switch_Engine/Command_References/configure_snmpv3_add_community.shtml)); SNMPv3 authentication and privacy passwords ([configure snmpv3 add user](https://documentation.extremenetworks.com/Switch%20Engine%20v33.7.1%20Command%20References/content/documents/Switch_Operating_Systems/Switch_Engine/Command_References/configure_snmpv3_add_user.shtml)); RADIUS and TACACS+ shared secrets ([configure radius shared-secret](https://documentation.extremenetworks.com/Switch%20Engine%20v33.7.1%20Command%20References/content/documents/Switch_Operating_Systems/Switch_Engine/Command_References/configure_radius_shared_secret.shtml), [configure tacacs shared-secret](https://documentation.extremenetworks.com/Switch%20Engine%20v33.7.1%20Command%20References/content/documents/Switch_Operating_Systems/Switch_Engine/Command_References/configure_tacacs_shared_secret.shtml)); BGP and MSDP TCP MD5 passwords ([configure bgp neighbor password](https://documentation.extremenetworks.com/Switch%20Engine%20v33.7.1%20Command%20References/content/documents/Switch_Operating_Systems/Switch_Engine/Command_References/configure_bgp_neighbor_password.shtml)); OSPF simple passwords and MD5 keys ([configure ospf authentication](https://documentation.extremenetworks.com/Switch%20Engine%20v33.7.1%20Command%20References/content/documents/Switch_Operating_Systems/Switch_Engine/Command_References/configure_ospf_authentication.shtml)), OSPFv3 IPsec keys and IS-IS passwords; the MLAG checkpoint key, NTP keys, keychain key strings, MACsec CAKs ("a long-lived secret key"), netlogin local users' passwords and the LDAP bind password; and a pregenerated SSH2 host key pasted as colon-separated hex ([configure ssh2 key](https://documentation.extremenetworks.com/Switch%20Engine%20v33.7.1%20Command%20References/content/documents/Switch_Operating_Systems/Switch_Engine/Command_References/configure_ssh2_key.shtml)). `none` stays. A commented-out command is treated the same; prose comments are left alone.

The page shows each line as written and explains what it does, never anything that depends on a secret's value, so the copy reads as the same lines, categories, VLANs and notes, with `[redacted]` where each value was. After the copy, the site's secrets check runs on it: a secret no command names (a PEM private key in a banner, a JWT, a password in a URL) means no link, and the popover names its line.

**The switch to include the values.** When the copy replaced something, the popover offers an unticked box to include the replaced values: a lab or class configuration with the default `public` and `private` communities is a reasonable thing to send on purpose. Ticked, the link carries the configuration as pasted, and the popover says anyone with it can read and use them. The box is off every time the popover opens, it is never offered in place of a link the check refused, and never when the copy replaced a private key.

[RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (section 3.5, read 2026-11-01) has the fragment "separated from the rest of the URI prior to a dereference", so the configuration is not sent to the server when the link is opened; it stays in the address bar and the history of whoever opens it, and anyone who has the link can read it.

- **How long.** At most 16,384 characters in all, the bound the site uses for every value after the `#`; a longer share gets no link, and the popover says how long it is.
- **Opening a link.** The text fills the box as a paste would and the page explains it; nothing touches a switch. The values then leave the page's address at once, without a request, so a reload or the page's own Share button carries nothing.
