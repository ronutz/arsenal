## Cosa fa

Incolla un file PAC (Proxy Auto-Config) e lo strumento te lo rilegge senza mai eseguirlo: le direttive proxy che può restituire, le funzioni helper PAC che usa, una serie di controlli strutturali e di correttezza e se sembra un file di steering per il Cloud Explicit Proxy di Netskope. Un file PAC è la piccola funzione JavaScript, `FindProxyForURL(url, host)`, che un browser o un client di inoltro chiama per ogni richiesta per decidere se andare direttamente alla destinazione o passare da un proxy. Lo strumento spiega questa logica decisionale. Viene eseguito interamente nel tuo browser e si basa sul riferimento PAC di MDN e sulla documentazione Explicit Proxy di Netskope.

## Non esegue mai il file

È questa la proprietà di sicurezza importante. Lo strumento non valuta il JavaScript del PAC. Legge il testo a livello lessicale: scorre il sorgente carattere per carattere per verificare il bilanciamento di parentesi graffe e tonde (ignorando tutto ciò che sta dentro stringhe e commenti), raccoglie i letterali stringa per trovare le direttive proxy e conta i nomi delle funzioni helper chiamate. Non chiama mai `eval`, non esegue mai `FindProxyForURL`, non apre mai un socket e non scarica mai nulla.

## Le direttive proxy

Ogni stringa di ritorno di un file PAC è composta da una o più direttive separate da punto e virgola, provate da sinistra a destra come failover. Lo strumento estrae ogni stringa di ritorno e ne spiega le parti: `DIRECT` (connessione diretta alla destinazione, senza proxy), `PROXY host:port` (usa quel proxy HTTP), `SOCKS host:port` (usa quel server SOCKS) e le parole chiave più recenti `HTTP`, `HTTPS`, `SOCKS4` e `SOCKS5` per un tipo di proxy specifico. Una stringa come `PROXY p1:8080; PROXY p2:8080; DIRECT` viene segnalata come catena di failover, e una parte che non è una delle parole chiave valide (un comune errore di battitura) viene evidenziata.

## Le funzioni helper

I file PAC decidono usando un insieme fisso di funzioni helper: lo strumento spiega ognuna di quelle che trova e, soprattutto, segnala le tre che forzano una risoluzione DNS: `isInNet`, `isResolvable` e `dnsResolve`. Queste consultano il server DNS e possono bloccarsi, quindi MDN consiglia di mettere prima i controlli sulle stringhe, meno costosi, come `isPlainHostName` e `dnsDomainIs`, e di arrivare alle funzioni helper che consultano il DNS solo quando nient’altro ha deciso. Lo strumento segnala anche i punti delicati indicati dalla documentazione: `shExpMatch` usa i caratteri jolly glob della shell (`*` e `?`), non le espressioni regolari; `myIpAddress` può essere inaffidabile sulle macchine multi-homed e può ripiegare su un indirizzo di loopback; e i browser moderni basati su Chromium rimuovono il percorso e la query dagli URL `https://` prima di chiamare il PAC, quindi un confronto sul percorso di un URL HTTPS potrebbe non funzionare.

## Riconoscimento di Netskope

Quando il file indirizza il traffico verso un host explicit proxy `goskope.com` (di solito `eproxy-<tenant>.goskope.com` sulla porta 8081), lo strumento lo riconosce come file di steering per il Cloud Explicit Proxy di Netskope e ne spiega lo schema: i nomi host semplici e gli host dell’identity provider vengono restituiti `DIRECT`, così aggirano il proxy; Netskope usa i cookie surrogate per l’identità dell’utente; il segnaposto del tenant va sostituito con il tuo tenant reale; e la CA radice di Netskope deve essere attendibile sul client perché l’ispezione TLS funzioni.

## Ambito e fondamenti

Lo strumento analizza e spiega; non valuta mai il file, non apre socket e non scarica nulla, e lo stesso input produce sempre lo stesso output. È un lettore strutturale e lessicale, non un parser JavaScript completo né un ambiente di test per PAC: non ti dirà a quale proxy porta un URL specifico (servirebbe eseguire la funzione). Ogni informazione viene dal riferimento Proxy Auto-Configuration di MDN, dall’articolo di Wikipedia sul proxy auto-config per le estensioni IPv6 di Microsoft alle funzioni helper e dalla documentazione Cloud Explicit Proxy di Netskope. Nulla di ciò che incolli lascia la pagina.

## Condivisione dei risultati

All’inizio della lettura, **Condividi i risultati** crea un link a questa pagina, solo quando lo premi, che contiene dopo il `#` il file così come l’hai incollato, una volta che la pagina ha letto un file (il riferimento mostrato quando la casella è vuota non è un risultato). Il suo riquadro a comparsa indica prima cosa contiene il link, poi offre Copia link e, se il browser ne ha uno, il menu di condivisione; l’indirizzo della pagina non cambia. Un file PAC nomina host interni, e uno di Netskope nomina il tuo tenant: secondo la pagina [Cloud Explicit Proxy](https://docs.netskope.com/en/explicit-proxy/) di Netskope (consultata il 01/11/2026) il file restituisce `PROXY eproxy-<Tenant Name>:8081`. Il riquadro a comparsa ti chiede di controllarli. La pagina legge ogni direttiva e ogni chiamata a una funzione helper, quindi non viene tolto nulla. Prima che venga offerto un link, nel file viene cercata una credenziale definita da uno standard: una chiave privata PEM, una riga `Authorization` o `Proxy-Authorization` con qualsiasi schema ([RFC 9110](https://www.rfc-editor.org/rfc/rfc9110), sezioni 11.6.2 e 11.7.2: il valore è costituito da credenziali, «consists of credentials»), una riga `Cookie` o `Set-Cookie` con un valore ([RFC 6265](https://www.rfc-editor.org/rfc/rfc6265), sezione 8.4: i server memorizzano comunemente in un cookie un nonce, o identificatore di sessione, «commonly store a nonce (or “session identifier”) in a cookie»), un JWT ([RFC 7519](https://www.rfc-editor.org/rfc/rfc7519), sezione 1), una password in un URL ([RFC 3986](https://www.rfc-editor.org/rfc/rfc3986), sezione 3.2.1), un ID della chiave di accesso AWS o un valore `ENC` di FortiOS; tutte consultate il 01/11/2026. Una sola di queste significa niente link: il riquadro a comparsa ne indica la riga, e tu la sostituisci con un segnaposto e premi di nuovo. Un valore il cui nome sembra soltanto un segreto (un membro JSON `token`, un `token=` in una query) non blocca il link; il riquadro a comparsa indica il primo, così puoi controllarlo.

La [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (sezione 3.5, consultata il 01/11/2026) stabilisce che il frammento viene separato dal resto dell’URI prima della dereferenziazione («separated from the rest of the URI prior to a dereference»), quindi ciò che segue il `#` non viene inviato al server quando si apre il link; resta nella barra degli indirizzi e nella cronologia di chi lo apre, e chiunque abbia il link può leggerlo.

- **Lunghezza massima.** Al massimo 16.384 caratteri in tutto, il limite che il sito applica a ogni valore dopo il `#`; una condivisione più lunga non ottiene il link e il riquadro a comparsa ne indica la lunghezza.
- **Apertura di un link.** Il file compila la casella come farebbe un incolla e la pagina lo legge (senza mai eseguirlo). I valori lasciano poi subito l’indirizzo della pagina, senza alcuna richiesta, quindi un ricaricamento o il pulsante Condividi della pagina stessa non contengono nulla.
