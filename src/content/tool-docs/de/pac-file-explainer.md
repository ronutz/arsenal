## Was das Tool tut

Fügen Sie eine PAC-Datei (Proxy Auto-Config) ein, und das Tool gibt wieder, was darin steht, ohne sie je auszuführen: die Proxy-Direktiven, die sie zurückgeben kann, die PAC-Hilfsfunktionen, die sie verwendet, eine Reihe von Prüfungen auf Struktur und Korrektheit und ob sie wie eine Steering-Datei für den Cloud Explicit Proxy von Netskope aussieht. Eine PAC-Datei ist die kleine JavaScript-Funktion `FindProxyForURL(url, host)`, die ein Browser oder ein weiterleitender Client bei jeder Anfrage aufruft, um zu entscheiden, ob die Verbindung direkt oder über einen Proxy läuft. Das Tool erklärt diese Entscheidungslogik. Es läuft vollständig in Ihrem Browser und stützt sich auf die PAC-Referenz von MDN und die Dokumentation von Netskope zum Explicit Proxy.

## Die Datei wird nie ausgeführt

Das ist die wichtige Sicherheitseigenschaft. Das Tool führt das JavaScript der PAC-Datei nicht aus. Es liest den Text lexikalisch: Es geht den Quelltext Zeichen für Zeichen durch, um geschweifte und runde Klammern abzugleichen (alles innerhalb von Zeichenfolgen und Kommentaren wird ignoriert), sammelt die Zeichenfolgenliterale, um Proxy-Direktiven zu finden, und zählt die Namen der aufgerufenen Hilfsfunktionen. Es ruft nie `eval` auf, führt nie `FindProxyForURL` aus, öffnet nie einen Socket und ruft nie etwas ab.

## Die Proxy-Direktiven

Jede Rückgabezeichenfolge einer PAC-Datei besteht aus einer oder mehreren Direktiven, getrennt durch Semikolons und als Failover von links nach rechts versucht. Das Tool zieht jede Rückgabezeichenfolge heraus und erklärt ihre Teile: `DIRECT` (direkt zum Ziel verbinden, kein Proxy), `PROXY host:port` (diesen HTTP-Proxy verwenden), `SOCKS host:port` (diesen SOCKS-Server verwenden) und die neueren Schlüsselwörter `HTTP`, `HTTPS`, `SOCKS4` und `SOCKS5` für einen bestimmten Proxy-Typ. Eine Zeichenfolge wie `PROXY p1:8080; PROXY p2:8080; DIRECT` wird als Failover-Kette gekennzeichnet, und ein Teil, der keines der gültigen Schlüsselwörter ist (ein häufiger Tippfehler), wird benannt.

## Die Hilfsfunktionen

PAC-Dateien entscheiden mit einem festen Satz von Hilfsfunktionen. Das Tool erklärt jede, die es findet, und kennzeichnet vor allem die drei, die eine DNS-Abfrage erzwingen: `isInNet`, `isResolvable` und `dnsResolve`. Sie fragen den DNS-Server und können blockieren; MDN empfiehlt daher, günstigere Zeichenfolgenprüfungen wie `isPlainHostName` und `dnsDomainIs` an den Anfang zu stellen und die DNS abfragenden Hilfsfunktionen erst zu erreichen, wenn sonst nichts entschieden hat. Das Tool weist auch auf die Fallstricke hin, die die Dokumentation nennt: `shExpMatch` verwendet Shell-Glob-Platzhalter (`*` und `?`), keine regulären Ausdrücke; `myIpAddress` kann auf Multihomed-Rechnern unzuverlässig sein und auf eine Loopback-Adresse zurückfallen; und moderne Chromium-basierte Browser entfernen bei `https://`-URLs Pfad und Query-String, bevor sie die PAC-Datei aufrufen, sodass ein Vergleich auf den Pfad einer HTTPS-URL womöglich nicht funktioniert.

## Erkennung von Netskope

Lenkt die Datei Datenverkehr auf einen Explicit-Proxy-Host unter `goskope.com` (typischerweise `eproxy-<tenant>.goskope.com` auf Port 8081), erkennt das Tool sie als Steering-Datei für den Cloud Explicit Proxy von Netskope und erklärt das Muster: Einfache Hostnamen und die Hosts des Identity Providers werden mit `DIRECT` zurückgegeben, sodass sie am Proxy vorbeigehen; Netskope verwendet Cookie-Surrogate für die Benutzeridentität; der Platzhalter für den Tenant muss durch Ihren echten Tenant ersetzt werden; und die Root-CA von Netskope muss auf dem Client vertrauenswürdig sein, damit die TLS-Inspektion funktioniert.

## Umfang und Grundlagen

Das Tool parst und erklärt; es führt die Datei nie aus, öffnet keinen Socket und ruft nichts ab, und dieselbe Eingabe ergibt immer dieselbe Ausgabe. Es liest Struktur und Lexik, ist aber weder ein vollständiger JavaScript-Parser noch eine Testumgebung für PAC-Dateien: Es sagt Ihnen nicht, zu welchem Proxy eine bestimmte URL führt (dafür müsste die Funktion ausgeführt werden). Jede Aussage stammt aus der Referenz von MDN zu Proxy Auto-Configuration, dem Wikipedia-Artikel zu Proxy Auto-Config für die IPv6-Erweiterungen von Microsoft und der Dokumentation von Netskope zum Cloud Explicit Proxy. Nichts, was Sie einfügen, verlässt die Seite.

## Ergebnisse teilen

Ganz oben in der Auswertung erzeugt **Ergebnisse teilen** einen Link auf diese Seite, und zwar nur, wenn Sie die Schaltfläche wählen und sobald die Seite eine Datei gelesen hat (die Referenz, die bei leerem Feld erscheint, ist kein Ergebnis). Der Link enthält nach dem `#` die Datei so, wie eingefügt. Das Popover nennt zuerst, was der Link enthält, und bietet dann „Link kopieren“ und, sofern der Browser eines bietet, das Teilen-Menü an; die Adresse der Seite bleibt unverändert. Eine PAC-Datei nennt interne Hosts und, bei Netskope, Ihren Tenant: Laut der Seite [Cloud Explicit Proxy](https://docs.netskope.com/en/explicit-proxy/) von Netskope (abgerufen am 01.11.2026) gibt die Datei `PROXY eproxy-<Tenant Name>:8081` zurück. Das Popover bittet Sie, diese Angaben zu prüfen. Die Seite liest jede Direktive und jeden Aufruf einer Hilfsfunktion, daher wird nichts herausgeschnitten. Bevor ein Link angeboten wird, wird die Datei nach Zugangsdaten durchsucht, die ein Standard definiert: ein privater Schlüssel im PEM-Format, eine Zeile `Authorization` oder `Proxy-Authorization` mit beliebigem Schema ([RFC 9110](https://www.rfc-editor.org/rfc/rfc9110), Abschnitte 11.6.2 und 11.7.2: Der Wert „consists of credentials“), eine Zeile `Cookie` oder `Set-Cookie` mit einem Wert ([RFC 6265](https://www.rfc-editor.org/rfc/rfc6265), Abschnitt 8.4: Server „commonly store a nonce (or "session identifier") in a cookie“), ein JWT ([RFC 7519](https://www.rfc-editor.org/rfc/rfc7519), Abschnitt 1), ein Passwort in einer URL ([RFC 3986](https://www.rfc-editor.org/rfc/rfc3986), Abschnitt 3.2.1), eine AWS-Zugriffsschlüssel-ID oder ein `ENC`-Wert von FortiOS; alle abgerufen am 01.11.2026. Findet sich eines davon, gibt es keinen Link: Das Popover nennt die Zeile, und Sie setzen einen Platzhalter an seine Stelle und wählen die Schaltfläche erneut. Ein Wert, dessen Name nur nach einem Secret aussieht (ein JSON-Member `token`, ein `token=` in einer Query), blockiert den Link nicht; das Popover nennt den ersten solchen Wert, damit Sie ihn prüfen können.

Laut [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (Abschnitt 3.5, abgerufen am 01.11.2026) ist das Fragment „separated from the rest of the URI prior to a dereference“, also vor der Dereferenzierung vom Rest der URI getrennt; daher wird, was nach dem `#` steht, beim Öffnen des Links nicht an den Server gesendet. Es bleibt in der Adressleiste und im Verlauf dessen, der den Link öffnet, und wer den Link hat, kann es lesen.

- **Länge.** Insgesamt höchstens 16.384 Zeichen, die Grenze, die die Website für jeden Wert nach dem `#` setzt; ist der geteilte Inhalt länger, gibt es keinen Link, und das Popover nennt seine Länge.
- **Öffnen eines Links.** Die Datei füllt das Feld wie beim Einfügen, und die Seite liest sie (führt sie aber nie aus). Danach verschwinden die Werte sofort aus der Adresse der Seite, ohne dass eine Anfrage gesendet wird; ein Neuladen oder die Schaltfläche „Teilen“ der Seite überträgt daher nichts.
