# Referenz der APM-Sitzungsvariablen

Alles, was eine Zugriffsrichtlinie von BIG-IP Zero Trust Access (früher BIG-IP APM, Access Policy Manager) erfährt, speichert sie in Sitzungsvariablen. Das sind hierarchische Namen, deren Aufbau die Anatomie-Abbildung im Leitfaden zum Visual Policy Editor selbst darlegt: der String session, ein Typ, der Name des Agents oder der String last, agentenspezifische Teile, ein Knotenname attr oder result, ein Attributname. Das Kapitel Session Variables ist die maßgebliche Tabelle dieser Namen, und das Tool bringt eine eigene Kopie davon mit: einen umfangreichen, kuratierten Kern, der die Ergebnisse der Richtlinie, die Gruppe zu Sitzungsverwaltung und Client, die Familien für AD, LDAP (Lightweight Directory Access Protocol) und RADIUS (Remote Authentication Dial-In User Service), die vollständige Familie session.ssl.cert, die Endpoint-Prüfungen, OTP und die Ressourcenzuweisung umfasst, erweitert um die Zeilen zur Logon- und SSO-Mechanik (Single Sign-on), die der SSO Configuration Guide definiert: session.logon.last.* und session.sso.token.last.*, das Paar, das jede SSO-Methode liest.

Die Suche erkennt Muster, weil das Kapitel Muster schreibt. Zeilen wie session.ad.$name.attr.$attr_name sind Vorlagen, bei denen jedes abgerufene Attribut in eine eigene Sitzungsvariable umgewandelt wird; fügen Sie also session.ad.last.attr.memberOf ein, wird es zu seiner Zeile aufgelöst, mit den angezeigten Bindungen $name = last, $attr_name = memberOf und mit der Aktion, die es befüllt, in diesem Fall ein AD Query. Suchen nach Familien und ein Modus mit dem vollständigen Katalog runden die Referenzseite ab.

Fügen Sie stattdessen einen Ausdruck ein, wird jede Referenz darin extrahiert und erklärt, in allen drei Syntaxformen, die die Plattform selbst verwendet: die Inline-Expansion %{session.x}, die die OTP-Beispielnachricht des Kapitels selbst zeigt; mcget in Branch-Regeln mit expr, deren kanonische Form die Referenz für Per-Request-Richtlinien als expr { [mcget {session.ad.last.attr.primaryGroupID}] == 100 } liefert; und access::session data get und set. Die Prüfung auf sichere Variablen läuft bei allen dreien mit, gestützt auf den Wortlaut des Lab-Materials von F5 selbst: Der Wert einer sicheren Variablen wird verschlüsselt in der Session-DB gespeichert, erscheint nicht im Sitzungsbericht, wird vom Logging-Agent nicht protokolliert und erfordert die Option -secure sowohl für mcget als auch für access::session data get/set. Das Beispiel, das ein Klick lädt, ist die klassische Falle, die diese Regel mit sich bringt, ein bloßes mcget auf session.logon.last.password, und das Tool nennt genau, was zurückkommt: ein leerer Wert, stillschweigend, kein Fehler.

Die ehrlichen Grenzen stehen auf den Karten. Es handelt sich um einen Stand des Kapitels aus 13.1, der letzten Generation, die als Handbuchkapitel ausgeliefert wurde; Namen und Familien sind über die Versionen hinweg stabil, und der Rat lautet weiterhin, pro Version zu prüfen. Variablen außerhalb dieses Stands werden als solche gemeldet, zusammen mit den beiden Möglichkeiten zum Debuggen: dem Bericht Current Sessions, der laut den Lab-Notizen nur Variablen aktiver Sitzungen zeigt, daher der Trick mit der Pause per Message Box, und dem Befehl sessiondump mit seinen Ansichten sid und allkeys.

Alles läuft lokal; nichts, was Sie einfügen, verlässt die Seite.

## Ergebnisse teilen

Oberhalb der Auswertung erzeugt **Ergebnisse teilen** einen Link auf diese Seite, und zwar nur, wenn Sie die Schaltfläche wählen. Der Link enthält nach dem `#` das Feld so, wie eingegeben, und sonst nichts: Variablennamen und Ausdrücke, nie ihre Werte, die diese Seite nie zu sehen bekommt. Das Popover nennt zuerst, was der Link enthält, und bietet dann „Link kopieren“ und, sofern der Browser eines bietet, das Teilen-Menü an; die Adresse der Seite bleibt unverändert.

Laut [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (Abschnitt 3.5, abgerufen am 27.10.2026) ist das Fragment „separated from the rest of the URI prior to a dereference“, also vor der Dereferenzierung vom Rest der URI getrennt; daher wird der Text beim Öffnen des Links nicht an den Server gesendet. Er bleibt in der Adressleiste und im Verlauf dessen, der den Link öffnet, und wer den Link hat, kann ihn lesen.

- **Länge.** Insgesamt höchstens 16.384 Zeichen, die Grenze, die die Website für jeden Wert nach dem `#` setzt; ist der geteilte Inhalt länger, gibt es keinen Link, und das Popover nennt seine Länge.
- **Öffnen eines Links.** Der Text füllt das Feld wie beim Einfügen, und die Seite liest ihn; es wird nichts gesendet. Danach verschwindet der Wert sofort aus der Adresse der Seite, ohne dass eine Anfrage gesendet wird; ein Neuladen oder die Schaltfläche „Teilen“ der Seite überträgt daher nichts.
