## Was das Tool tut

Fügen Sie ein, was ein Host für seine Routingtabelle ausgegeben hat, und das Tool liest es für Sie. Es erkennt vier Ausgabeformate: Linux iproute2 (`ip route`, `ip route show table all`, `ip -6 route`, `ip -d route`), Linux net-tools (`netstat -rn` und `route -n`, die „Kernel IP routing table“), `netstat -rn` von BSD und macOS („Routing tables“, „Internet:“, „Internet6:“) sowie `route print` von Windows mit seinen Tabellen für IPv4 und IPv6, Active und Persistent. Jede Route wird zu einer Zeile derselben Tabelle (Zielpräfix, Next Hop, Schnittstelle, Metrik, Typ, Tabelle), und jede Zeile lässt sich zu einer Auswertung Feld für Feld in verständlicher Sprache aufklappen. Danach listet das Tool die Standardrouten jeder Tabelle auf und sagt, welche gewinnt, und ein zweites Feld beantwortet nach den Regeln eines Routers die Frage „Welche Route nimmt dieses Ziel?“. Nichts verlässt den Browser, und keine Route wird geändert oder abgefragt.

## Was jedes Feld bedeutet

Die Auswertungen stammen aus den Manpages der Befehle, abgerufen am 19.10.2026.

- **iproute2.** Das Ziel steht am Anfang; `default` ist „equivalent to IP 0/0 or to IPv6 ::/0“, und eine bloße Adresse ist eine Host-Route, denn „If the length of the prefix is missing, ip assumes a full-length host route“ ([ip-route(8)](https://man7.org/linux/man-pages/man8/ip-route.8.html)). Dann folgen `via` (der Next-Hop-Router), `dev` (das Ausgabegerät), `proto` (kernel, boot, static, ra und redirect haben feste Bedeutungen; jedes andere Tag interpretiert der Kernel nicht, [rtnetlink(7)](https://man7.org/linux/man-pages/man7/rtnetlink.7.html)), `scope` (host, link, global), `src` (die bevorzugte Quelladresse), `metric` („routes with lower values are preferred“), `table`, das Next-Hop-Flag `onlink` und Optionen wie `pref`, `mtu` und `nhid`. Ein vorangestelltes Typwort sagt, was die Route tut: unicast leitet weiter, local und broadcast gehören zur eigenen Tabelle des Hosts, und blackhole, unreachable, prohibit und throw leiten nicht weiter. Eingerückte `nexthop`-Zeilen werden der Route darüber als ihre Multipath-Hops zugeordnet, mit ihrem `weight`.
- **net-tools.** Destination und Genmask ergeben zusammen das Präfix („'0.0.0.0' for the default route“), Gateway ist „The gateway address or '*' if none set“, und die Buchstaben unter Flags sind die, die [route(8)](https://man7.org/linux/man-pages/man8/route.8.html) unter OUTPUT aufführt: U up, H host, G use gateway, R, D, M, A, C und ! für reject. `route -n` gibt Metric, Ref und Use aus; `netstat -rn` gibt stattdessen MSS, Window und irtt aus.
- **BSD und macOS.** Die Buchstaben unter Flags werden nach [FreeBSD netstat(1)](https://man.freebsd.org/cgi/man.cgi?query=netstat&sektion=1) (U, G, H, S, B, b, D, L, M, R, X, 1, 2, 3) und nach netstat.1 von Apple dekodiert, das C, c, I, i, m, r, W, Y und g ergänzt; ein Buchstabe, den nur macOS aufführt, wird als solcher gekennzeichnet. Ein Gateway `link#N` ist eine direkte Route, und ein Gateway wie `0:e0:b5:36:cf:4f` ist eine Link-Layer-Adresse. Diese Ausgaben enthalten keine Metrik.
- **Windows.** Active Routes sind die genutzten Routen; Persistent Routes sind gespeicherte Konfiguration ([Microsoft Learn, KB 2966111](https://learn.microsoft.com/en-us/troubleshoot/windows-client/networking/incorrect-default-gateways-in-persistent-routes)). In der IPv4-Tabelle ergibt Netmask die Präfixlänge, Gateway ist eine Next-Hop-Adresse oder `On-link`, Interface ist die Adresse des lokalen Adapters, und unter Routen zum selben Ziel gilt: „the route with the lowest metric is selected“ ([Microsoft Learn, The IP routing table](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-server-2003/cc779122(v=ws.10))). In der IPv6-Tabelle ist If eine Schnittstellennummer aus der Interface List; ein Gateway, das in die nächste Zeile umbricht, wird seiner Zeile zugeordnet.

Alles, was das Tool nicht versteht, wird angezeigt, nie verworfen: Ein Token, das es nicht lesen kann, bleibt bei seiner Route unter „Nicht verstanden“, und eine Zeile, die weder eine Route noch bekannte Struktur ist (Spaltenköpfe, Trennlinien, Abschnittstitel, ein mitkopierter Prompt `$ ip route`), wird mit ihrer Zeilennummer aufgeführt.

## Standardrouten und die Routensuche

Eine Standardroute ist eine Route mit Präfixlänge null. Enthält eine Tabelle mehrere, haben sie dieselbe Länge, also entscheidet die Metrik, und die niedrigste gewinnt; das Tool nennt die gewinnende Route oder sagt, warum es keine nennen kann (gleiche Metriken oder eine Ausgabe ohne vergleichbare Metrik, etwa netstat von BSD oder Persistent Routes von Windows mit `Default`).

Die Routensuche wendet die Auswahlregeln aus [RFC 1812, Abschnitt 5.2.4.3](https://www.rfc-editor.org/rfc/rfc1812.txt) an: Der Basic Match behält die Routen, deren Präfix das Ziel enthält, der Longest Match behält die längste davon, und bei gleicher Länge gewinnt die niedrigste Metrik. Das Tool zeigt die Kandidaten, die verbleibenden Routen und die Regel, die entschieden hat. Bei iproute2 liest es die Tabellen in der Reihenfolge der drei Standard-Policy-Regeln, local, dann main, dann default ([ip-rule(8)](https://man7.org/linux/man-pages/man8/ip-rule.8.html)); jede andere Tabelle, etwa eine `table 100`, wird als nicht abgefragt aufgeführt, da nur eine eigene Policy-Regel sie erreichen würde. Eine gewinnende `throw`-Route schickt die Suche weiter zur nächsten Tabelle, wie ip-route(8) es beschreibt. Unter Windows werden nur die Active Routes abgefragt. Routen, deren Ziel keine Adresse mit Länge ist (ein ohne `-n` ausgegebener Name, eine Abkürzung, ein geschwärzter Wert), werden als ausgelassen aufgeführt.

## Was das Tool nicht wissen kann

- `ip route show table 100` gibt auf seinen Zeilen kein Wort `table` aus; eine eingefügte Auflistung einer einzelnen Tabelle wird daher als Tabelle main gelesen, die Standardtabelle der Auflistung.
- iproute2 gibt keine Metrik aus, wenn sie null ist: In der Aufzeichnung hinter den Beispielen zeigte `route -n` Metric 0 für eine Route, die `ip route` ohne Metrik ausgab, und das Tool vergleicht eine solche Route mit Metrik 0.
- Die „Kernel IPv6 routing table“ von Linux net-tools bleibt als nicht verstanden stehen, weil route(8) nur die IPv4-Spalten dokumentiert; fügen Sie stattdessen `ip -6 route` ein.
- Andere Policy-Regeln als die drei Standardregeln stehen nicht in der Ausgabe einer Routingtabelle, daher kann das Tool ihnen nicht folgen.

## Beispiele

Die Schaltfläche „Beispiel“ lädt ein echtes `ip route show`, aufgezeichnet am 19.10.2026 auf einem Host mit 192.0.2.2, und fragt nach 192.0.2.77: Die Standardroute 0.0.0.0/0 und das direkt verbundene 192.0.2.0/24 enthalten die Adresse beide, und das /24 gewinnt per Longest Match, also wird das Paket on-link über eth0 zugestellt. Die Referenzvektoren (Golden Vectors) ergänzen von demselben Host `ip route show table all` (wo 192.0.2.200 in einem /25 der Tabelle 100 liegt, aber keine Regel Tabelle 100 erreicht und das /24 von main es zustellt), sein `ip -d route show table 100` (zwei Standardrouten mit den Metriken 100 und 200 sowie Routen vom Typ blackhole, unreachable, prohibit und throw), sein `netstat -rn` und `route -n`, das Multipath-Beispiel von FRRouting mit sechzehn Pfaden, ein `route print` von Windows 10 (ff02::1 passt zu zwei ff00::/8-Routen, und Metrik 331 schlägt 5256), das Beispiel von Microsoft für persistente Routen sowie die Tabellen von `netstat -nr` und `netstat -r` aus dem FreeBSD Handbook.

## Ergebnisse teilen

Am Anfang der Auswertung erzeugt **Ergebnisse teilen** einen Link auf diese Seite, und zwar nur, wenn Sie die Schaltfläche wählen. Der Link enthält die Tabelle so, wie eingefügt (`#input=...`), und, wenn Sie eines eingegeben haben, das Ziel (`&destination=192.0.2.77`); welche Auswertung Feld für Feld gerade aufgeklappt ist, ist nicht enthalten. Bevor Sie etwas kopieren, fügt das Popover einen Warnhinweis hinzu: Eine Routingtabelle nennt interne Adressen, Gateways und Schnittstellen; lesen Sie sie daher, bevor Sie den Link senden. Alles, was der Link enthält, steht nach dem `#`, und dieser Teil ist laut [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (Abschnitt 3.5, abgerufen am 27.10.2026) „separated from the rest of the URI prior to a dereference“, also vor der Dereferenzierung vom Rest der URI getrennt: Ein Browser sendet ihn beim Öffnen des Links nicht an den Server, aber er bleibt in der Adressleiste und im Verlauf dessen, der den Link öffnet, und wer den Link hat, kann ihn lesen.

- **Länge.** Ein Link enthält höchstens 16.384 Zeichen, die Grenze, die die Website für jeden Wert nach dem `#` setzt; ist der Inhalt länger, gibt es keinen Link, und das Popover nennt die Länge, die er hätte.
- **Öffnen eines Links.** Die Tabelle füllt das Feld wie beim Einfügen, das Ziel füllt sein Feld (und wird geleert, wenn der Link keines enthält), und die Seite parst und sucht erneut. Ein fehlerhaftes Ziel lehnt die Seite mit ihrer eigenen Meldung ab, wie bei der Eingabe. Ob angenommen oder nicht, die Werte verschwinden danach sofort aus der Adresse der Seite, ohne dass eine Anfrage gesendet wird; ein Neuladen, ein Lesezeichen oder die Schaltfläche „Teilen“ der Seite überträgt daher nichts, was Sie nicht selbst teilen wollten.

## API

Dieselbe Engine beantwortet die Operation `/api/v1/routing-table-explainer` der HTTP-API der Website, Feld für Feld beschrieben im OpenAPI-Vertrag auf der [API-Seite](/api), mit Beispielen aus den Referenzvektoren. Der Vertrag gibt auch an, ob diese Website die API bereitstellt.

- **Anfrage.** Entweder die Ausgabe als Text, die nur geparst wird, oder ein JSON-Objekt `{"text": "<the printout>", "lookup": "<an IPv4 or IPv6 address>"}`, das geparst und dann für die Routensuche verwendet wird.
- **Antwort.** `parse` enthält `format` (`iproute2`, `netstat-linux`, `netstat-bsd`, `windows` oder `unknown`), `routes` (jede mit `index`, `line`, `raw`, `section`, `family`, `destination`, `prefix`, `prefixLength`, `isDefault`, `type`, `gateway`, `onLink`, `interface`, `metric`, `metricText`, `protocol`, `scope`, `src`, `flags`, `nhFlags`, `nexthops`, `attributes`, `unparsed` und `notes`), `interfaces` (die Interface List von Windows), `defaults` (pro Tabelle: `section`, `consulted`, `candidates`, `winner` und `reason`), `unparsedLines`, `structureLines`, `lineCount` und `warnings`. `lookup` ist null oder enthält `destination`, `family`, `stages` (jede mit `section`, `candidates`, `longest`, `survivors`, `winner`, `outcome` und `decidedBy`), `skipped`, `unusable`, `winner`, `action` und `decidedBy`. Für die Beispielaufzeichnung mit der Routensuche nach 192.0.2.77 ist die Antwort die Route mit `index` 1 (192.0.2.0/24, auf der Seite als #2 angezeigt), Aktion `on-link`, entschieden durch `longest-prefix`.
- **Fehler.** HTTP 400, `invalid_input`, mit der Meldung der Engine: eine Routensuche nach etwas, das keine einzelne IPv4- oder IPv6-Adresse ist, oder eine Anfrage, die mit `{` beginnt, aber nicht das obige JSON-Objekt ist. Text, der keine Routingtabelle ist, wird nicht abgelehnt: `format` ist `unknown`, und die Zeilen werden als nicht verstanden aufgeführt.
