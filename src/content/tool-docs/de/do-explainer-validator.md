# DO-Deklarationen erklärt und geprüft

Declarative Onboarding ist die Schwester-Extension von AS3, und die Aufteilung zwischen beiden ist der klarste Weg, sich beide zu merken: AS3 konfiguriert die Anwendungsdienste auf Layer 4–7 eines BIG-IP, das bereits im Netzwerk ist, und DO übernimmt das Onboarding auf Layer 1–3, das es dorthin bringt. Lizenzierung, Provisionierung der Module, DNS und NTP, VLANs, Self IPs und Routen, Benutzerkonten und das Clustering, das Geräte zu einem Hochverfügbarkeitspaar verbindet, sind allesamt Aufgabe von DO. Das Tool gibt jede Deklaration so wieder, wie die Dokumentation sie beschreibt.

Fügen Sie das JSON ein, das Sie per POST an `/mgmt/shared/declarative-onboarding` senden, und das Tool sagt Ihnen zuerst, welche Art von Dokument es ist: eine reine `Device`-Deklaration, die Sie direkt an ein BIG-IP senden, oder ein Request-Wrapper mit `class DO` und einem `targetHost`, den Sie an ein BIG-IQ senden, um ein Gerät aus der Ferne einzurichten. Es liest die Optionen der obersten Ebene, `schemaVersion`, `async`, `webhook` und `label`, und geht dann den einen Tenant durch, den eine DO-Deklaration haben darf und der laut Schema `Common` heißen muss.

Der Durchlauf ist nach der Phase gruppiert, in der DO tatsächlich einrichtet, denn die Reihenfolge ist das, was man verinnerlichen sollte: Lizenzierung und Provisionierung geben die Module frei, von denen alles andere abhängt; die Systemidentität mit Hostname, DNS, NTP und Benutzern ist die Grundlage; das Netzwerk baut die Data Plane aus VLANs, Self IPs und Routen; und das Clustering verbindet das eingerichtete Gerät mit seinen Peers. Jede Klasse wird nach der Schema-Referenz von F5 benannt und erklärt, und eine Klasse, die das Tool nicht kennt, wird trotzdem gemeldet statt verworfen.

Drei dokumentierte Fallstricke werden mechanisch durchgesetzt, statt sie einer Fußnote zu überlassen. Der `hostname` darf in `Common` oder in einer Klasse `System` gesetzt werden, aber nicht an beiden Stellen; eine doppelte Angabe wird markiert. Eine `SelfIp` ohne `allowService` wird mit dem entscheidenden Versionshinweis markiert: DO 1.36 hat diesen Standardwert von `default` auf `none` geändert, sodass eine Self IP, die früher Management plus Standarddienste erbte, jetzt nichts mehr zulässt, bis Sie etwas anderes festlegen. Und ein Benutzer `root` ohne sein `oldPassword` wird markiert, weil DO das Root-Passwort ohne das bestehende nicht ändern kann. Das Tool zeigt auch das Verhalten von `async`: `async: true` gibt sofort 202 mit einer Task-ID zurück, und Sie fragen diesen Task per GET ab, bis er abgeschlossen ist.

Das Tool ist eine Strukturerklärung mit Plausibilitätsprüfung, kein vollständiger JSON-Schema-Validator; F5 veröffentlicht das DO-Schema für die Validierung in VS Code, und eine Deklaration, die hier besteht, kann von DO selbst trotzdem abgelehnt werden. Alles läuft lokal, nichts, was Sie einfügen, verlässt die Seite, und es wird nie Kontakt zu einem BIG-IP oder BIG-IQ aufgenommen.

## Ergebnisse teilen

Unter der Bewertung erzeugt **Ergebnisse teilen** einen Link auf diese Seite, und zwar nur, wenn Sie die Schaltfläche wählen. Der Link enthält nach dem `#` eine Kopie der Deklaration, nie den eingefügten Text selbst: Jedes Passwort, jeder Schlüssel, jedes Token und jede Community, die die [Schema-Referenz](https://clouddocs.f5.com/products/extensions/f5-declarative-onboarding/latest/schema-reference.html) von DO (abgerufen am 27.10.2026) definiert, ist durch `[redacted]` ersetzt. Das sind das `password` eines User-Objekts (und `oldPassword` und `newPassword` von root), das `bindPassword` von LDAP (Lightweight Directory Access Protocol), das `secret` von RADIUS (Remote Authentication Dial-In User Service) und TACACS+, `localPassword` und `remotePassword` von DeviceTrust, `regKey`, `addOnKeys`, `bigIpPassword` und `bigIqPassword` der License, `targetPassphrase` und `targetTokens` des Request-Wrappers, die `tokens` eines Eintrags in Credentials, die `community` eines SNMP-Trap-Ziels, der `name` einer SnmpCommunity (der Community-String), die Authentifizierungs- und Privacy-Passwörter von SNMPv3 und der `privateKey` eines DeviceCertificate, sofern als `base64` angegeben. Das Popover nennt zuerst, was der Link enthält und wie viele Werte ersetzt wurden, und bietet dann „Link kopieren“ und, sofern der Browser eines bietet, das Teilen-Menü an; die Adresse der Seite bleibt unverändert.

Diese Seite zeigt diese Werte nie an, und sie bleiben Strings, sodass die empfangende Seite dieselbe Deklaration liest, einschließlich der Prüfung auf das `oldPassword` von root; die Kopie behält jedes andere Byte, auch Abstände und Reihenfolge. Namen, Adressen und Benutzernamen bleiben erhalten. Ein Fall bleibt ebenfalls: eine Community, die nur als eigener Name des SnmpCommunity-Objekts geschrieben ist (DO verwendet den Objektnamen, wenn keine Eigenschaft `name` vorhanden ist), denn der Durchlauf zeigt den Namen jedes Objekts; geben Sie ihr eine Eigenschaft `name` oder benennen Sie das Objekt um, bevor Sie teilen.

Eingefügter Text, der kein gültiges JSON ist, lässt sich nicht sicher zerlegen: Nennt er irgendwo eine dieser Einstellungen, gibt es keinen Link, und das Popover bittet darum, zuerst das JSON zu korrigieren; nennt er keine, bleibt er so, wie eingegeben, und die empfangende Seite zeigt denselben Parse-Fehler.

Laut [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (Abschnitt 3.5, abgerufen am 27.10.2026) ist das Fragment „separated from the rest of the URI prior to a dereference“, also vor der Dereferenzierung vom Rest der URI getrennt; daher wird die Kopie beim Öffnen des Links nicht an den Server gesendet. Sie bleibt in der Adressleiste und im Verlauf dessen, der den Link öffnet, und wer den Link hat, kann sie lesen.

- **Länge.** Insgesamt höchstens 16.384 Zeichen, die Grenze, die die Website für jeden Wert nach dem `#` setzt; ist der geteilte Inhalt länger, gibt es keinen Link, und das Popover nennt seine Länge.
- **Öffnen eines Links.** Die Kopie füllt das Feld wie beim Einfügen, und die Seite erklärt sie; es wird nichts gesendet. Danach verschwindet der Wert sofort aus der Adresse der Seite, ohne dass eine Anfrage gesendet wird; ein Neuladen oder die Schaltfläche „Teilen“ der Seite überträgt daher nichts.
