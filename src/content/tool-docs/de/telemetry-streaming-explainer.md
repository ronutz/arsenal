# Telemetry Streaming (TS) erklärt

Die F5 Automation Toolchain hat drei deklarative Erweiterungen, und am klarsten behält man sie im Kopf über das, was jede mit dem Gerät tut. AS3 konfiguriert die Anwendungsdienste auf Layer 4–7. DO übernimmt das Onboarding auf Layer 1–3. Telemetry Streaming ist die dritte, und sie fällt aus der Reihe: Wo AS3 und DO das BIG-IP konfigurieren, beobachtet TS es. TS sammelt und normalisiert Statistiken und Ereignisse des Geräts und leitet sie an eine Consumer-Anwendung weiter, alles aus einer einzigen JSON-Deklaration, die Sie per POST an `/mgmt/shared/telemetry/declare` senden. Das Tool gibt diese Deklaration so wieder, wie die Dokumentation sie beschreibt.

Fügen Sie das JSON ein: Das Tool bestätigt zuerst, dass die `class` auf oberster Ebene `Telemetry` ist, und liest dann das optionale Objekt `Controls` (seinen `logLevel`, ob `debug` eingeschaltet ist und ob der `memoryMonitor` (Beta) gesetzt ist). Danach geht es jedes benannte Klassenobjekt durch, gruppiert diese aber nicht nach der Reihenfolge des Onboardings wie das Tool „DO-Deklarationen erklärt und geprüft“, sondern nach ihrer Rolle in der Telemetrie-Pipeline, denn diese Pipeline ist das, was man verinnerlichen sollte.

Es gibt drei Rollen. Datenquellen erzeugen Telemetrie: Ein `Telemetry_System` mit einem `systemPoller` erfasst und normalisiert in einem Intervall Statistiken zu Gerät, virtuellen Servern, Pools und Pool-Membern; ein eigenständiger `Telemetry_System_Poller` tut dasselbe als referenziertes Objekt, etwa um Statistiken von einem weiteren BIG-IP abzurufen; und ein `Telemetry_Listener` nimmt die Logs und Ereignisse auf, die das BIG-IP veröffentlicht, über TCP und UDP, standardmäßig auf Port 6514. Consumer leiten Telemetrie nach außen weiter: Ein `Telemetry_Consumer` ist ein Push-Consumer, dessen `type` das Ziel auswählt, und der Katalog ist lang: Splunk, Azure Log Analytics, AWS CloudWatch und S3, Graphite, Kafka, ElasticSearch, DataDog, Generic HTTP, OpenTelemetry und weitere; ein `Telemetry_Pull_Consumer` stellt Telemetrie dagegen bereit, damit ein externes System wie Prometheus sie abruft. Die unterstützenden Klassen gruppieren und erweitern den Rest: Ein `Telemetry_Namespace` isoliert eine Gruppe von Pollern, Listenern und Consumern, sodass sie nur einander sehen, und `Telemetry_Endpoints` definiert eigene Endpunkte, die ein Poller über die Standardausgabe hinaus abfragen kann.

Die nützlichste einzelne Prüfung des Tools ist die Vollständigkeit der Pipeline. Eine TS-Deklaration kann strukturell gültig sein und trotzdem nichts bewirken, und das geschieht auf zwei Arten: eine Deklaration mit Consumern, aber ohne Datenquelle (es wird nichts erfasst, was weitergeleitet werden könnte), und eine Deklaration mit Quellen, aber ohne Consumer (die Telemetrie kann nirgendwohin). Das Tool markiert beides. Es markiert auch den konkreten Fallstrick, den der Leitfaden zur Fehlersuche nennt, ein `Telemetry_System` ohne `systemPoller`, das stillschweigend keine Metriken erfasst, sowie einen `Telemetry_Consumer` ohne `type`. Entscheidend ist, dass es Quellen und Consumer innerhalb eines `Telemetry_Namespace` mitzählt, sodass eine korrekt in Namespaces gegliederte Deklaration nicht fälschlich so gemeldet wird, als fehle ihr eine der beiden Hälften.

Eines sei offen gesagt: F5 hat Telemetry Streaming in den Wartungsmodus versetzt. Es wird weiterhin mit kritischen Fehlerbehebungen und Sicherheitsupdates unterstützt, und eine Abkündigung ist nicht geplant, aber es ist nicht mehr der aktiv wachsende Weg, der es einmal war. Das Tool ist eine Strukturerklärung mit Plausibilitätsprüfung, kein vollständiger JSON-Schema-Validator; eine Deklaration, die hier sauber gelesen wird, kann von TS trotzdem abgelehnt werden. Alles läuft lokal, nichts, was Sie einfügen, verlässt die Seite, und es wird nie Kontakt zu einem BIG-IP aufgenommen.

## Ergebnisse teilen

Unter der Bewertung erzeugt **Ergebnisse teilen** einen Link auf diese Seite, und zwar nur, wenn Sie die Schaltfläche wählen. Der Link enthält nach dem `#` eine Kopie der Deklaration, nie den eingefügten Text selbst: Jeder Wert, den Telemetry Streaming als Secret führt, ist durch `[redacted]` ersetzt. Die [Schema-Referenz](https://clouddocs.f5.com/products/extensions/f5-telemetry-streaming/latest/schema-reference.html) von TS und sein [Leitfaden zur Einrichtung von Consumern](https://clouddocs.f5.com/products/extensions/f5-telemetry-streaming/latest/setting-up-consumer.html) (beide abgerufen am 27.10.2026) legen Secrets in Secret-Objekten ab, deren `cipherText` den Wert enthält (einen API-Schlüssel, einen Shared Key, das PEM eines privaten Schlüssels); DataDog nimmt seinen `apiKey` als einfachen String entgegen, und der Consumer Generic HTTP sendet `headers`, deren Werte Token sein können. Daher ersetzt die Kopie jeden `cipherText` (ein Zertifikat, das auf dieselbe Weise abgelegt ist, wird mit ersetzt), jede `passphrase`, jeden `apiKey` und jeden `privateKey` als einfachen String und jeden `value` eines Headers. Das Popover nennt zuerst, was der Link enthält und wie viele Werte ersetzt wurden, und bietet dann „Link kopieren“ und, sofern der Browser eines bietet, das Teilen-Menü an; die Adresse der Seite bleibt unverändert.

Diese Seite zeigt diese Werte nie an, sodass die empfangende Seite dieselbe Deklaration liest; die Kopie behält jedes andere Byte, auch Abstände und Reihenfolge. Hosts, Ports, Pfade, Benutzernamen, `privateKeyId`, Header-Namen und Objektnamen bleiben erhalten.

Eingefügter Text, der kein gültiges JSON ist, lässt sich nicht sicher zerlegen: Nennt er irgendwo eine dieser Einstellungen, gibt es keinen Link, und das Popover bittet darum, zuerst das JSON zu korrigieren; nennt er keine, bleibt er so, wie eingegeben, und die empfangende Seite zeigt denselben Parse-Fehler.

Laut [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (Abschnitt 3.5, abgerufen am 27.10.2026) ist das Fragment „separated from the rest of the URI prior to a dereference“, also vor der Dereferenzierung vom Rest der URI getrennt; daher wird die Kopie beim Öffnen des Links nicht an den Server gesendet. Sie bleibt in der Adressleiste und im Verlauf dessen, der den Link öffnet, und wer den Link hat, kann sie lesen.

- **Länge.** Insgesamt höchstens 16.384 Zeichen, die Grenze, die die Website für jeden Wert nach dem `#` setzt; ist der geteilte Inhalt länger, gibt es keinen Link, und das Popover nennt seine Länge.
- **Öffnen eines Links.** Die Kopie füllt das Feld wie beim Einfügen, und die Seite erklärt sie; es wird nichts gesendet. Danach verschwindet der Wert sofort aus der Adresse der Seite, ohne dass eine Anfrage gesendet wird; ein Neuladen oder die Schaltfläche „Teilen“ der Seite überträgt daher nichts.
