## Was das Tool tut

Fügen Sie ein JSON Web Token ein, um zu lesen, was darin steht, und um bei einem mit HMAC signierten Token zu prüfen, ob die Signatur gültig ist. Das Tool zerlegt das Token in seine drei Teile, dekodiert Header und Claims, übersetzt die zeitbezogenen Claims in verständliche Datumsangaben und prüft, wenn Sie das Secret angeben, eine Signatur mit HS256, HS384 oder HS512. Alles läuft in Ihrem Browser; ein eingefügtes Secret verlässt ihn nie.

## Die Form eines JWT

Ein JWT in seiner üblichen kompakten Form besteht aus drei Base64url-Segmenten, verbunden durch Punkte: `header.payload.signature`. Der **Header** nennt den Signaturalgorithmus (`alg`) und oft eine Schlüssel-ID (`kid`); der **Payload** enthält die Claims, ein JSON-Objekt mit Aussagen über das Subject; und die **Signatur** wird über die ersten beiden Segmente berechnet, sodass sich jede Manipulation daran erkennen lässt. Zu den registrierten Claims gehören Aussteller (`iss`), Subject (`sub`), Audience (`aud`) sowie die Zeitfelder `iat`, `nbf` und `exp`; diese sind Sekunden seit der Unix-Epoche, und das Tool stellt sie als lesbare Datumsangaben dar.

## Dekodieren ist nicht Prüfen

Das ist das Wichtigste, was man über ein JWT verstehen muss: Header und Payload sind nur Base64url-kodiert, nicht verschlüsselt. Wer das Token hat, kann sie lesen; ein JWT ist also kein Ort für Secrets. Das Dekodieren sagt Ihnen, was ein Token behauptet, nicht, ob diese Behauptungen stimmen. Erst die Prüfung der Signatur mit dem richtigen Schlüssel belegt, dass das Token von dem ausgestellt wurde, der es angibt, und nicht verändert wurde.

## Signaturprüfung und Algorithmus

HS256, HS384 und HS512 signieren mit einem HMAC über ein Shared Secret, dieselbe Konstruktion, die der HMAC-Generator verwendet; diese Prüfung und jenes Tool stimmen also überein. Weil dasselbe Secret signiert und prüft, kann jeder, der ein mit HS signiertes Token prüfen kann, auch eines ausstellen; das ist die Abwägung der symmetrischen Verfahren, und deshalb verwenden Dienste, die andere prüfen lassen müssen, ohne dass diese fälschen können, stattdessen einen asymmetrischen Algorithmus wie RS256 oder ES256. Eine bekannte Familie von Angriffen missbraucht das Feld `alg`: Entweder wird es auf `none` gesetzt, oder ein Server, der einen öffentlichen RSA-Schlüssel hat, wird dazu gebracht, diesen als HMAC-Secret zu behandeln. Die Best-Current-Practice-Empfehlungen in RFC 8725 sollen diese Lücken schließen; kurz gesagt: Prüfen Sie immer, ob der Algorithmus der erwartete ist.

## Verwendung

Fügen Sie ein Token ein, um Header und Claims zu dekodieren und seine Zeitangaben in verständlicher Sprache zu lesen. Um ein mit HMAC signiertes Token zu prüfen, fügen Sie das Shared Secret ein, und das Tool bestätigt, ob die Signatur passt. Ob ein Token gerade abgelaufen ist, wird anhand Ihrer aktuellen Uhr angezeigt, zusätzlich zu den zeitbezogenen Claims, die der Decoder liest.

## Ergebnisse teilen

Unter den Statusanzeigen des Tokens erzeugt **Ergebnisse teilen** einen Link auf diese Seite, und zwar nur, wenn Sie die Schaltfläche wählen. Der Link enthält nach dem `#` Header und Claims des Tokens: die ersten beiden Segmente genau so, wie eingefügt, gefolgt von einem leeren Signatursegment (`header.payload.`), und einen Vermerk, dass das eingefügte Token eine Signatur hatte. Er enthält nie die Signatur, nie das Token so, wie eingefügt, und nie das Secret aus dem Prüffeld. Das Popover nennt zuerst, was der Link enthält, dann einen eigenen Warnhinweis: Die Claims können eine Person und die Dienste nennen, die dem Token vertrauen, lesen Sie sie also, bevor Sie den Link senden. Dann bietet es „Link kopieren“ und, sofern der Browser eines bietet, das Teilen-Menü an; die Adresse der Seite bleibt unverändert.

Warum nicht das Token selbst: Ein JWT dient, solange es gültig ist, als Bearer-Zugangsdaten. [RFC 6750](https://www.rfc-editor.org/rfc/rfc6750) (Abschnitt 1.2, abgerufen am 01.11.2026) definiert ein Bearer Token als eines, das „any party in possession of the token (a "bearer") can use“, also jeder verwenden kann, der es besitzt, und laut [RFC 7519](https://www.rfc-editor.org/rfc/rfc7519) (Abschnitt 1, abgerufen am 01.11.2026) stehen die Claims eines JWT im Payload eines JWS. Ohne Signatur ist die Kopie kein Token, das ein Prüfer akzeptiert: Laut [RFC 7515](https://www.rfc-editor.org/rfc/rfc7515) (Abschnitt 5.2, abgerufen am 01.11.2026) gilt, wenn keine Signatur gültig ist: „the JWS MUST be considered invalid“. Weil die Signatur fehlt, gibt der Link außerdem niemandem, was er bräuchte, um Rateversuche für ein schwaches HMAC-Secret offline zu testen. Enthält der Eintrag `jwk` eines Headers privates Schlüsselmaterial (`d`, `p`, `q`, `dp`, `dq`, `qi`, `oth` oder `k`; laut RFC 7515, Abschnitt 4.1.3 enthält `jwk` den öffentlichen Schlüssel), gibt es keinen Link, und das Popover nennt die Einträge.

Laut [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (Abschnitt 3.5, abgerufen am 01.11.2026) ist das Fragment „separated from the rest of the URI prior to a dereference“, also vor der Dereferenzierung vom Rest der URI getrennt; daher werden die Werte beim Öffnen des Links nicht an den Server gesendet. Sie bleiben in der Adressleiste und im Verlauf dessen, der den Link öffnet, und wer den Link hat, kann sie lesen.

- **Länge.** Insgesamt höchstens 16.384 Zeichen, die Grenze, die die Website für jeden Wert nach dem `#` setzt; ist der geteilte Inhalt länger, gibt es keinen Link, und das Popover nennt seine Länge.
- **Öffnen eines Links.** Die Kopie füllt das Feld, und die Seite dekodiert sie wie beim Einfügen: derselbe Header, dieselben Claims und Zeiten, wobei der Ablauf an der Uhr der lesenden Person gemessen wird. War das Token des Absenders signiert, meldet der Signaturbereich anstelle der Signatur und des Prüffelds, dass die Signatur im Link weggelassen wurde. Angenommen wird nur ein Wert in der Form der Kopie, den die Seite dekodiert; ein ganzes Token oder alles andere wird ignoriert. In beiden Fällen verschwinden die Werte sofort aus der Adresse der Seite, ohne dass eine Anfrage gesendet wird; ein Neuladen oder die Schaltfläche „Teilen“ der Seite überträgt daher nichts.
