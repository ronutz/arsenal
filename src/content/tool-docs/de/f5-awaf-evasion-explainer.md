## Was das Tool tut

F5 AWAF (Advanced WAF, früher BIG-IP ASM, Application Security Manager) erkennt eine ganze Klasse von Angriffen, die sich hinter Kodierung verstecken: Ein Payload wird maskiert oder kodiert, sodass eine Angriffssignatur nie die echten Zeichen sieht, und der Webserver dekodiert ihn erst wieder zum Angriff, nachdem die Firewall hingesehen hat. F5 fasst die Abwehr unter einer Violation zusammen, „Evasion technique detected“ (`VIOL_EVASION`), aufgeteilt in acht Sub-Violations. Das Tool ist die Dekodierseite dieser Violation: Geben Sie den Namen einer Sub-Violation ein (oder das Wort `evasions`), um alle acht erklärt zu bekommen, oder fügen Sie den `evasions`-Block einer deklarativen Richtlinie ein, um jede als aktiviert oder deaktiviert auszuwerten. Es stützt sich auf den Wortlaut von K7929 und des aktuellen Kapitels zu den Violations von BIG-IP ASM, beide von F5, und läuft vollständig in Ihrem Browser.

## Zwei Modi, eine Eingabe

Geben Sie `evasions` ein, und das Tool listet die acht Sub-Violations von F5 auf, jede mit ihrem Standardzustand (alle acht sind ab Werk aktiviert), einer Beschreibung in verständlicher Sprache, was sie normalisiert oder erkennt, und dem Kodierungstrick, den ein Angreifer verwendet und den sie abfangen soll. Geben Sie einen einzelnen Namen ein, etwa `Multiple decoding` oder `Bad unescape`, und Sie erhalten nur diese Karte. Die Suche ist tolerant bei Leerzeichen, Groß- und Kleinschreibung und Prozentzeichen, sodass sowohl `multiple decoding` als auch `Multiple decoding` aufgelöst werden.

Fügen Sie stattdessen JSON ein, ein bloßes `evasions`-Array, das Objekt `blocking-settings` oder einen ganzen Wrapper `{ "policy": { ... } }`, wechselt das Tool in den Auswertungsmodus: Es meldet jede der acht Sub-Violations als aktiviert, deaktiviert oder nicht gesetzt, wobei „nicht gesetzt“ bedeutet, dass die Richtlinie die Vorgabe ihres Templates erbt, statt die Prüfung auszuschalten. Eine deaktivierte Sub-Violation wird als Warnung hervorgehoben, denn wer eine ausschaltet, überspringt diese Normalisierung, und die Umgehung, die sie abgefangen hat, kann die Anwendung unaufgelöst erreichen.

## Die acht Sub-Violations

Das Tool deckt genau die acht von F5 ab, in der Reihenfolge, in der das Handbuch sie aufführt: `%u decoding` (`%u`-Unicode-Escapes von Microsoft), `Apache whitespace` (die ASCII-Steuerbytes 9, 11, 12, 13), `Bad unescape` (ungültiges Hex wie `%RR`), `Bare byte decoding` (rohe Bytes über 127), `Directory traversals` (Muster wie `../`), `IIS backslashes` (Umwandlung von `\` in `/`), `IIS Unicode codepoints` (IIS-spezifische `%u`-Zuordnungen aus Windows-1252) und `Multiple decoding` (wiederholtes Dekodieren verschachtelter Kodierungen). Jeder Name, jeder Standardwert und jede Beschreibung stammt direkt aus der Dokumentation von F5.

## Multiple decoding und die Anzahl der Durchgänge

Multiple decoding ist die einzige Sub-Violation mit einem Einstellwert. Im deklarativen Schema hat sie `maxDecodingPasses`, den das Schema auf 2 bis 5 begrenzt, mit einem dokumentierten Standardwert von 3. Das Tool zeigt die Anzahl der Durchgänge an, wenn eine Richtlinie sie setzt, markiert einen über den Standardwert erhöhten Wert als Hinweis und einen Wert außerhalb des Bereichs 2 bis 5 als Warnung, weil das System ihn ablehnen oder begrenzen würde. Ist die Anzahl nicht gesetzt, nennt das Tool den geltenden Standardwert, statt zu raten.

## Die Brücke zu den Kodierungs-Tools

Mehrere dieser Sub-Violations sind genau die Dekodierschritte, die die Toolbox bereits ausführt. Die `%u`-Escapes, rohe Bytes und die `%XX`-Prozentkodierung, die Bad unescape überwacht, gehören in das Gebiet des [Codecs für Base64, Base32, Hex und Prozentkodierung](/tools/base64), und Multiple decoding ist schlicht Prozentdekodierung, die mehr als einmal läuft. Jede Referenzkarte nennt das passende Tool, sodass Sie einen kodierten String nehmen und das Dekodieren von Hand verfolgen können; so entsteht am schnellsten ein Gespür dafür, was die WAF wegnormalisiert.

## Eine Regel aus dem Schema

Das Tool liest auch das Learn-Flag der übergeordneten Violation, wenn ein vollständiges Array `blocking-settings.violations` vorhanden ist. Laut Schema werden diese Sub-Violations nur *gelernt*, wenn das Lernen für `VIOL_EVASION` aktiviert ist; ist es dort ausgeschaltet, wird eine auslösende Anfrage zwar weiterhin erkannt und kann einen Alarm auslösen oder blockiert werden, aber es entsteht kein Lernvorschlag. Das Tool zeigt diesen Zustand an, damit Sie eine Richtlinie, die ihre Umgehungen nie lernen wird, nicht überrascht.

## Grundlagen und Genauigkeit

Jeder Name, jeder Standardwert und jede Beschreibung einer Sub-Violation stützt sich auf K7929 von F5 und das aktuelle Kapitel „Working with Violations“ von BIG-IP ASM 17.5 (die Tabelle Evasion Techniques Sub-Violations); die Feldnamen, das boolesche `enabled`, `maxDecodingPasses` und die Grenze von 2 bis 5 stammen aus dem Declarative WAF Policy Schema von F5. Es ist ein reines Tool zum Dekodieren: Es liest, was Sie einfügen, ruft nie etwas ab, validiert nie gegen ein laufendes BIG-IP und wertet nie Datenverkehr aus. Nichts, was Sie einfügen, wird hochgeladen oder verlässt die Seite; für eine Entscheidung in der Produktion prüfen Sie jede Auswertung gegen die Dokumentation Ihrer BIG-IP-Version.

## Ergebnisse teilen

Am Anfang der Antwort erzeugt **Ergebnisse teilen** einen Link auf diese Seite, und zwar nur, wenn Sie die Schaltfläche wählen. Der Link enthält nach dem `#` das Feld so, wie eingegeben, sobald die Seite eine Antwort darauf hat. Ein Schlüsselwort wie `evasions` oder der Name einer Sub-Violation öffnet die zugehörigen Karten und nennt nichts von Ihnen, daher hat das Popover keinen Warnhinweis. Ein eingefügter evasions-Block oder eine ganze Richtlinie kann interne Hosts und Adressen nennen, daher bittet das Popover Sie, den Text zuerst zu lesen, und der Text durchläuft dieselbe Prüfung wie bei „Deklarative AWAF-Richtlinien erklärt“. Bevor ein Link angeboten wird, wird der Text nach Zugangsdaten durchsucht, die ein Standard definiert: ein privater Schlüssel im PEM-Format, eine Zeile `Authorization` oder `Proxy-Authorization` mit beliebigem Schema ([RFC 9110](https://www.rfc-editor.org/rfc/rfc9110), Abschnitte 11.6.2 und 11.7.2: Der Wert „consists of credentials“), eine Zeile `Cookie` oder `Set-Cookie` mit einem Wert ([RFC 6265](https://www.rfc-editor.org/rfc/rfc6265), Abschnitte 4.1.1, 4.2.1 und 8.4, wonach ein Cookie häufig eine Sitzungskennung enthält), ein JWT ([RFC 7519](https://www.rfc-editor.org/rfc/rfc7519), Abschnitt 1), ein Passwort in einer URL ([RFC 3986](https://www.rfc-editor.org/rfc/rfc3986), Abschnitt 3.2.1), eine AWS-Zugriffsschlüssel-ID oder ein `ENC`-Wert von FortiOS; alle abgerufen am 01.11.2026. Findet sich eines davon, gibt es keinen Link: Das Popover nennt seine Zeile, und Sie setzen einen Platzhalter an seine Stelle und wählen die Schaltfläche erneut. Ein Wert, dessen Name nur nach einem Secret aussieht (ein JSON-Eintrag `token`, ein `password=` in der Query einer URL), blockiert den Link nicht; das Popover nennt den ersten solchen Wert, damit Sie ihn prüfen können. Ein Name, den die Seite nicht kennt, oder JSON, das sie nicht parsen kann, hat keine Antwort, daher bleibt die Schaltfläche deaktiviert. Das Popover nennt zuerst, was der Link enthält, und bietet dann „Link kopieren“ und, sofern der Browser eines bietet, das Teilen-Menü an; die Adresse der Seite bleibt unverändert.

Laut [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (Abschnitt 3.5, abgerufen am 01.11.2026) ist das Fragment „separated from the rest of the URI prior to a dereference“, also vor der Dereferenzierung vom Rest der URI getrennt; daher wird, was nach dem `#` steht, beim Öffnen des Links nicht an den Server gesendet. Es bleibt in der Adressleiste und im Verlauf dessen, der den Link öffnet, und wer den Link hat, kann es lesen.

- **Länge.** Insgesamt höchstens 16.384 Zeichen, die Grenze, die die Website für jeden Wert nach dem `#` setzt; ist der geteilte Inhalt länger, gibt es keinen Link, und das Popover nennt seine Länge.
- **Öffnen eines Links.** Der Text füllt das Feld wie beim Einfügen, und die Seite liest ihn wie gewohnt. Danach verschwinden die Werte sofort aus der Adresse der Seite, ohne dass eine Anfrage gesendet wird; ein Neuladen oder die Schaltfläche „Teilen“ der Seite überträgt daher nichts.
