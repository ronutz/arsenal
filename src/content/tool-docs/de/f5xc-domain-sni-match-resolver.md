## Was das Tool tut

Das Tool beantwortet eine genau umrissene Frage zu F5 Distributed Cloud (XC): Welcher von mehreren HTTP-Load-Balancern mit ihren Domainlisten bedient einen bestimmten Hostnamen? Fügen Sie die Load-Balancer als JSON-Array und einen Test-Hostnamen ein; das Tool nennt den Load-Balancer und den Domaineintrag, die gewinnen, zeigt, warum, und markiert die Konfigurationsgefahren, an denen die Domainzuordnung scheitert. Es läuft vollständig in Ihrem Browser.

## Wie XC einen Load-Balancer auswählt

Wenn eine Anfrage eintrifft, hat XC die Auswahl bereits auf die Load-Balancer eingegrenzt, die sich Ziel-IP und Port teilen (die Advertise Policy). Unter diesen wählt es die spezifischste Domainübereinstimmung. Ein exakter FQDN, also app.example.com wörtlich aufgeführt, schlägt eine Wildcard wie *.example.com. Der Hostname, den es abgleicht, stammt aus dem SNI-Wert, wenn der Client HTTPS verwendet, oder aus dem Host-Header, wenn der Client reines HTTP verwendet. Passt nichts und ist ein Load-Balancer als Default für diese Advertise Policy markiert, fängt der Default die Anfrage ab; gibt es keinen Default, wird der Hostname überhaupt nicht angenommen.

## Wildcards und die Apex-Domain

Eine Wildcard-Domain ist ein Suffixabgleich: *.example.com deckt foo.example.com ab, aber nicht die Apex-Domain example.com, und ein Wildcard-TLS-Zertifikat deckt nur ein einziges Label ab. Wer sowohl www.example.com (oder eine beliebige Subdomain) als auch das blanke example.com bedienen will, muss deshalb die Apex-Domain als eigene Domain hinzufügen. Das Tool macht den Unterschied zwischen Wildcard und Apex-Domain in jedem Ergebnis ausdrücklich.

## Die Gefahren, auf die das Tool hinweist

Die Domainzuordnung scheitert auf einige wiedererkennbare Arten, und das Tool warnt vor jeder. Von einer Wildcard (*.example.com) und ihrer Apex-Domain (example.com) auf verschiedenen Load-Balancern mit automatischen Zertifikaten rät F5 ausdrücklich ab. Zwei Load-Balancer, die dieselbe exakte Domain beanspruchen, oder zwei, die auf derselben Advertise Policy als Default markiert sind (erlaubt ist nur einer), sind Konflikte. Ein Hostname, der zwei Einträge gleicher Spezifität trifft, ist mehrdeutig. Und ein Hostname mit mehreren Labels, der auf eine Wildcard passt, wird zwar geroutet, kann aber an der Zertifikatsvalidierung scheitern, da das Wildcard-Zertifikat nur ein Label abdeckt.

## Ergebnisse teilen

Unter dem Ergebnis erzeugt **Ergebnisse teilen** einen Link auf diese Seite, und zwar nur, wenn Sie die Schaltfläche wählen. Der Link enthält nach dem `#` die Liste der Load-Balancer so, wie eingefügt, und den Hostnamen. Das Popover nennt zuerst, was der Link enthält, und bietet dann „Link kopieren“ und, sofern der Browser eines bietet, das Teilen-Menü an; die Adresse der Seite bleibt unverändert. Namen und Domains von Load-Balancern können interne Hosts einer Organisation sein: Das Popover bittet Sie, sie zu prüfen. Die Auflösung liest jeden Namen und jede Domain, daher wird nichts herausgeschnitten. Bevor ein Link angeboten wird, wird jedes Feld nach Zugangsdaten durchsucht, die ein Standard definiert: ein privater Schlüssel im PEM-Format, eine Zeile `Authorization` oder `Proxy-Authorization` mit beliebigem Schema ([RFC 9110](https://www.rfc-editor.org/rfc/rfc9110), Abschnitte 11.6.2 und 11.7.2: Der Wert „consists of credentials“), eine Zeile `Cookie` oder `Set-Cookie` mit einem Wert ([RFC 6265](https://www.rfc-editor.org/rfc/rfc6265), Abschnitt 8.4: Server „commonly store a nonce (or "session identifier") in a cookie“), ein JWT ([RFC 7519](https://www.rfc-editor.org/rfc/rfc7519), Abschnitt 1), ein Passwort in einer URL ([RFC 3986](https://www.rfc-editor.org/rfc/rfc3986), Abschnitt 3.2.1), eine AWS-Zugriffsschlüssel-ID oder ein `ENC`-Wert von FortiOS, dazu zwei Dinge, die das Schema von F5 Distributed Cloud selbst definiert: ein Secret vom Typ SecretType, also eine URL in `clear_secret_info` oder ein Ort in `blindfold_secret_info` (die [XC-API-Referenz](https://docs.cloud.f5.com/docs-v2/api/views-http-loadbalancer): „SecretType is used in an object to indicate a sensitive/confidential field“), und ein Matcher für den Header `Authorization` mit literalem Wert; alle abgerufen am 01.11.2026. Findet sich eines davon, gibt es keinen Link: Das Popover nennt die Zeile, und Sie setzen einen Platzhalter an seine Stelle und wählen die Schaltfläche erneut. Ein Wert, dessen Name nur nach einem Secret aussieht (ein JSON-Member `token`, ein `token=` in einer Query, ein Matcher für `X-Api-Key` oder ein Cookie), blockiert den Link nicht; das Popover nennt den ersten solchen Wert, damit Sie ihn prüfen können.

Laut [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (Abschnitt 3.5, abgerufen am 01.11.2026) ist das Fragment „separated from the rest of the URI prior to a dereference“, also vor der Dereferenzierung vom Rest der URI getrennt; daher wird, was nach dem `#` folgt, beim Öffnen des Links nicht an den Server gesendet. Es bleibt in der Adressleiste und im Verlauf dessen, der den Link öffnet, und wer den Link hat, kann es lesen.

- **Länge.** Insgesamt höchstens 16.384 Zeichen, die Grenze, die die Website für jeden Wert nach dem `#` setzt; ist der geteilte Inhalt länger, gibt es keinen Link, und das Popover nennt seine Länge.
- **Öffnen eines Links.** Beide Felder werden gefüllt, als wären sie eingegeben, und die Seite löst den Hostnamen auf. Danach verschwinden die Werte sofort aus der Adresse der Seite, ohne dass eine Anfrage gesendet wird; ein Neuladen oder die Schaltfläche „Teilen“ der Seite überträgt daher nichts.
