## Was das Tool tut

Das Tool erklärt eine OpenAPI- oder Swagger-Spezifikation, also genau das Artefakt, mit dem API Protection von F5 Distributed Cloud (XC) arbeitet. XC importiert eine OpenAPI-Spezifikation (Version 2.0 oder 3.0.x), um daraus sein API-Inventar aufzubauen und ein positives Sicherheitsmodell durchzusetzen, und XC API Discovery erzeugt ein herunterladbares Swagger-JSON, das Sie bearbeiten und erneut importieren können. Fügen Sie diese Spezifikation ein, und das Tool listet jeden Pfad und jede Operation mit Methode, Parametern, Anfrage-Body und Antworten auf und gibt an, ob sie eine Authentifizierung verlangt. Es läuft vollständig in Ihrem Browser.

## Das Inventar, das das Tool erstellt

Für jeden Pfad geht das Tool jede Operation durch, GET, POST, PUT, PATCH, DELETE und die übrigen, und meldet dieselben Details, mit denen XC gültiges Verhalten definiert: die Parameter (Name, Ort und ob sie erforderlich sind), die Content-Types des Anfrage-Bodys, die Antwortcodes und die geltenden Security Schemes. Lokale $ref-Parameter innerhalb des Dokuments löst es auf, sodass ein Parameter, der einmal definiert und in mehreren Operationen referenziert wird, bei jeder Verwendung vollständig erscheint. Die Zusammenfassung oben zählt die Pfade, die Operationen und wie viele davon ohne Authentifizierung, auf Objektebene oder veraltet sind.

## Authentifizierung, korrekt aufgelöst

Ob eine Operation eine Authentifizierung verlangt, steht nicht immer an der Operation selbst. OpenAPI erlaubt eine globale Security-Anforderung, die sich pro Operation überschreiben lässt, und eine Operation mit leerer Security-Liste ist ausdrücklich öffentlich, auch wenn die API eine globale Anforderung hat. Das Tool löst das so auf, wie die Spezifikation es definiert: Eine Operation verwendet ihre eigene Security, sofern vorhanden, sonst die globale, und eine leere Liste bedeutet keine Authentifizierung. Deshalb kann eine Operation selbst in einer API, die meist ein Token verlangt, als nicht authentifiziert erscheinen.

## Die Markierungen und ihr Bezug zu OWASP

Das Tool markiert zwei Dinge, die für die API-Sicherheit zählen. Eine Operation ohne wirksame Security ist ein Risiko vom Typ Broken Authentication: Sie ist ohne Zugangsdaten erreichbar. Ein Endpunkt mit Pfadparameter wie /orders/{id} ist eine Zugriffsstelle auf Objektebene und die klassische Angriffsfläche für Broken Object Level Authorization, den ersten Punkt der OWASP API Security Top 10: Die API muss prüfen, ob der Aufrufer genau dieses Objekt anfassen darf, und nicht nur, ob er angemeldet ist. Das sind Anstöße, Ihr Autorisierungsdesign zu überprüfen, kein Beweis für eine Schwachstelle; aber genau diese Endpunkte sollten Sie zuerst prüfen.

## Ergebnisse teilen

Unter der Zusammenfassung erzeugt **Ergebnisse teilen** einen Link auf diese Seite, und zwar nur, wenn Sie die Schaltfläche wählen und sobald die Seite mindestens eine Operation auflistet. Der Link enthält nach dem `#` die OpenAPI-Datei so, wie eingefügt. Das Popover nennt zuerst, was der Link enthält, und bietet dann „Link kopieren“ und, sofern der Browser eines bietet, das Teilen-Menü an; die Adresse der Seite bleibt unverändert. Eine Datei nennt die Pfade und Server Ihrer API, und ihre Beispiele können echte Werte enthalten: Das Popover bittet Sie, sie zu prüfen. Die Seite liest jeden Pfad, jede Operation und jeden Parameter, daher wird nichts aus dem Link herausgeschnitten. Bevor ein Link angeboten wird, wird die Datei nach Zugangsdaten durchsucht, die ein Standard definiert: ein privater Schlüssel im PEM-Format, eine Zeile `Authorization` oder `Proxy-Authorization` mit beliebigem Schema ([RFC 9110](https://www.rfc-editor.org/rfc/rfc9110), Abschnitte 11.6.2 und 11.7.2: Der Wert „consists of credentials“), eine Zeile `Cookie` oder `Set-Cookie` mit einem Wert ([RFC 6265](https://www.rfc-editor.org/rfc/rfc6265), Abschnitt 8.4: Server „commonly store a nonce (or "session identifier") in a cookie“), ein JWT ([RFC 7519](https://www.rfc-editor.org/rfc/rfc7519), Abschnitt 1), ein Passwort in einer URL ([RFC 3986](https://www.rfc-editor.org/rfc/rfc3986), Abschnitt 3.2.1), eine AWS-Zugriffsschlüssel-ID oder ein `ENC`-Wert von FortiOS, dazu zwei Dinge, die das Schema von F5 Distributed Cloud selbst definiert: ein Secret vom Typ SecretType, also eine URL in `clear_secret_info` oder ein Ort in `blindfold_secret_info` (die [XC-API-Referenz](https://docs.cloud.f5.com/docs-v2/api/views-http-loadbalancer): „SecretType is used in an object to indicate a sensitive/confidential field“), und ein Matcher für den Header `Authorization` mit literalem Wert; alle abgerufen am 01.11.2026. Findet sich eines davon, gibt es keinen Link: Das Popover nennt die Zeile, und Sie setzen einen Platzhalter an seine Stelle und wählen die Schaltfläche erneut. Ein Wert, dessen Name nur nach einem Secret aussieht (ein JSON-Member `token`, ein `token=` in einer Query, ein Matcher für `X-Api-Key` oder ein Cookie), blockiert den Link nicht; das Popover nennt den ersten solchen Wert, damit Sie ihn prüfen können.

Laut [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (Abschnitt 3.5, abgerufen am 01.11.2026) ist das Fragment „separated from the rest of the URI prior to a dereference“, also vor der Dereferenzierung vom Rest der URI getrennt; daher wird, was nach dem `#` folgt, beim Öffnen des Links nicht an den Server gesendet. Es bleibt in der Adressleiste und im Verlauf dessen, der den Link öffnet, und wer den Link hat, kann es lesen.

- **Länge.** Insgesamt höchstens 16.384 Zeichen, die Grenze, die die Website für jeden Wert nach dem `#` setzt; ist der geteilte Inhalt länger, gibt es keinen Link, und das Popover nennt seine Länge.
- **Öffnen eines Links.** Die Datei füllt das Feld wie beim Einfügen, und die Seite liest sie. Danach verschwinden die Werte sofort aus der Adresse der Seite, ohne dass eine Anfrage gesendet wird; ein Neuladen oder die Schaltfläche „Teilen“ der Seite überträgt daher nichts.
