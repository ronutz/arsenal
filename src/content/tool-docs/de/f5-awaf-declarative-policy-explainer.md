## Was das Tool tut

Fügen Sie eine deklarative Sicherheitsrichtlinie für F5 AWAF (Advanced WAF, früher BIG-IP ASM, Application Security Manager) ein, also das JSON `{ "policy": { ... } }`, das Sie in der Versionsverwaltung pflegen, und das Tool gibt sie Ihnen Abschnitt für Abschnitt in verständlicher Sprache wieder: was jede Einstellung ist und, wo es darauf ankommt, was der konkret gesetzte Wert tatsächlich für die Sicherheit der Richtlinie bedeutet. Es ist eine reine Erklärung zum Dekodieren, gestützt auf das von F5 veröffentlichte Schema für deklarative Richtlinien, und es läuft vollständig in Ihrem Browser.

## Das Tool liest eine Richtlinie als Abweichung von ihrem Template

Eine deklarative Richtlinie listet nur ihre Anpassungen gegenüber einem Basis-Template auf. Die wichtigste Regel beim Lesen lautet daher: Ein fehlender Abschnitt bedeutet, dass der Standardwert des Templates gilt, nicht, dass ein Schutz ausgeschaltet ist. Das Tool hält sich durchgehend daran: Es erklärt nur, was die Richtlinie ausdrücklich setzt, erinnert stets daran, dass alles nicht Angezeigte geerbt wird, und meldet einen Schutz nie als deaktiviert, nur weil er fehlt. Jeder Sicherheitshinweis, den es gibt, leitet sich aus einem Wert ab, den die Richtlinie tatsächlich setzt, nie aus einem Fehlen.

## Was das Tool abdeckt

Das Tool erkennt etwa fünfundfünfzig Abschnitte der obersten Ebene, gruppiert in Lesereihenfolge: Identität (`name`, `description`, `template`), Durchsetzung (`enforcementMode`, `signature-settings`, der passive Modus und die Einstellungen in `general` zu Staging und X-Forwarded-For), automatisches Lernen (Policy Builder), Anwendungskontext (Sprache der Anwendung, Groß- und Kleinschreibung, Servertechnologien), die Angriffsfläche des Datenverkehrs (URLs, Parameter, Dateitypen, Methoden, Header, Cookies), die Schutzfunktionen (Blocking-Einstellungen, Data Guard, CSRF, Brute Force, Geolocation-Blocking, verhaltensbasierte Durchsetzung und mehr) sowie Inhaltsprofile (JSON, XML, GraphQL, OpenAPI). Jeder Abschnitt wird nach dem Schematext von F5 selbst beschrieben, und alles, was das Tool nicht erkennt, wird trotzdem als vorhanden vermerkt.

## Die Sicherheitshinweise

Über die Beschreibung der Abschnitte hinaus liest das Tool die Werte, die darüber entscheiden, ob eine Richtlinie tatsächlich schützt. Es warnt, wenn `enforcementMode` auf `transparent` steht, denn dann überwacht die Richtlinie nur und blockiert nichts, auch keine Violations, die zum Blockieren markiert sind. Es weist darauf hin, wenn Angriffssignaturen im Staging sind (sie treffen zu, werden aber noch nicht durchgesetzt), wenn die Richtlinie für die Client-IP `X-Forwarded-For` vertraut, wenn Data Guard ausdrücklich deaktiviert ist und wenn ein durchgesetztes Cookie ohne das Attribut Secure oder HttpOnly gesetzt ist. Jeder dieser Zustände wird beim Überfliegen einer Richtlinie routinemäßig übersehen.

## Grundlagen und Genauigkeit

Die Feldbeschreibungen sind aus dem von F5 veröffentlichten Schema für deklarative Richtlinien sinngemäß übernommen. F5 veröffentlicht die Dokumentation für fünf Versionen, v16.0, v16.1, v17.0, v17.1 und v17.5; das Tool stützt sich auf das Schema von v17.1, das neueste mit einem vollständig veröffentlichten Schema (die Schemaseite für v17.5 ist noch nicht veröffentlicht). Die hier abgedeckten Kernabschnitte sind über die Reihe v16.x bis v17.x stabil. Nichts, was Sie einfügen, wird hochgeladen oder verlässt die Seite; für eine Entscheidung in der Produktion prüfen Sie jede Auswertung gegen das Schema für deklarative Richtlinien Ihrer BIG-IP-Version.

## Ergebnisse teilen

Unter dem Überblick und seinen Sicherheitshinweisen erzeugt **Ergebnisse teilen** einen Link auf diese Seite, und zwar nur, wenn Sie die Schaltfläche wählen. Der Link enthält nach dem `#` die Richtlinie so, wie eingefügt, sobald die Seite sie als Richtlinie gelesen hat. Das Popover nennt zuerst, was der Link enthält, und bietet dann „Link kopieren“ und, sofern der Browser eines bietet, das Teilen-Menü an; die Adresse der Seite bleibt unverändert. Eine Richtlinie kann interne Hosts, URLs, Namen von Parametern und Cookies sowie Adressen nennen, daher fügt das Popover eine Zeile hinzu, die Sie bittet, sie zu lesen, bevor Sie den Link senden.

Das Schema von F5 für deklarative Richtlinien ([v17.1 schema description](https://clouddocs.f5.com/products/waf-declarative-policy/declarative_policy_v17_1.html), abgerufen am 01.11.2026) definiert keine Eigenschaft, die ein Passwort oder einen Schlüssel enthält, aber eine Richtlinie enthält URLs (`webhooks[].url`, `open-api-files[].link`) und alles, was mit ihr eingefügt wurde. Bevor ein Link angeboten wird, wird der Text nach Zugangsdaten durchsucht, die ein Standard definiert: ein privater Schlüssel im PEM-Format, eine Zeile `Authorization` oder `Proxy-Authorization` mit beliebigem Schema ([RFC 9110](https://www.rfc-editor.org/rfc/rfc9110), Abschnitte 11.6.2 und 11.7.2: Der Wert „consists of credentials“), eine Zeile `Cookie` oder `Set-Cookie` mit einem Wert ([RFC 6265](https://www.rfc-editor.org/rfc/rfc6265), Abschnitte 4.1.1, 4.2.1 und 8.4, wonach ein Cookie häufig eine Sitzungskennung enthält), ein JWT ([RFC 7519](https://www.rfc-editor.org/rfc/rfc7519), Abschnitt 1), ein Passwort in einer URL ([RFC 3986](https://www.rfc-editor.org/rfc/rfc3986), Abschnitt 3.2.1), eine AWS-Zugriffsschlüssel-ID oder ein `ENC`-Wert von FortiOS; alle abgerufen am 01.11.2026. Findet sich eines davon, gibt es keinen Link: Das Popover nennt seine Zeile, und Sie setzen einen Platzhalter an seine Stelle und wählen die Schaltfläche erneut. Ein Wert, dessen Name nur nach einem Secret aussieht (ein JSON-Eintrag `token`, ein `password=` in der Query einer URL), blockiert den Link nicht; das Popover nennt den ersten solchen Wert, damit Sie ihn prüfen können. Die URL eines Webhooks wird ebenso genannt, weil der empfangende Dienst sein Token oft darin unterbringt.

Laut [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (Abschnitt 3.5, abgerufen am 01.11.2026) ist das Fragment „separated from the rest of the URI prior to a dereference“, also vor der Dereferenzierung vom Rest der URI getrennt; daher wird, was nach dem `#` steht, beim Öffnen des Links nicht an den Server gesendet. Es bleibt in der Adressleiste und im Verlauf dessen, der den Link öffnet, und wer den Link hat, kann es lesen.

- **Länge.** Insgesamt höchstens 16.384 Zeichen, die Grenze, die die Website für jeden Wert nach dem `#` setzt; ist der geteilte Inhalt länger, gibt es keinen Link, und das Popover nennt seine Länge.
- **Öffnen eines Links.** Die Richtlinie füllt das Feld wie beim Einfügen, und die Seite erklärt sie. Danach verschwinden die Werte sofort aus der Adresse der Seite, ohne dass eine Anfrage gesendet wird; ein Neuladen oder die Schaltfläche „Teilen“ der Seite überträgt daher nichts.
