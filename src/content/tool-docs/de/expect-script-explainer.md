## Was das Tool tut

Das Tool liest ein Skript für [Expect](/glossary/expect) und erklärt es allein anhand seines Texts: was es startet, worauf es wartet und wie, was es eintippt und ob ein Wagenrücklauf die Zeile beendet, wann es die Tastatur an den Benutzer übergibt. Die Befehle werden in der Reihenfolge des Quelltexts mit ihrer Verschachtelung aufgeführt, sodass auch die Rümpfe von `expect`, `if`, `foreach`, `while`, `for`, `switch`, `catch` und `proc` gelesen werden. Aus den Paaren von `expect` und `send` rekonstruiert es den Dialog, den das Skript führt, und meldet Befunde zu zwanzig Regeln, jede an eine Zeile gebunden und jede mit Verweis auf die Manpage `expect(1)` oder den Quellcode von Expect 5.45.4. Das Skript wird mit dem Parser der Website für [Tcl](/glossary/tcl) geparst (die Syntax von Expect ist die von Tcl): nach den Regeln von Tcl 8.4, dazu die Argumentexpansion `{*}` aus Tcl 8.5 und neuer. Es wird nie ausgeführt: Es wird nichts gestartet und nichts gesendet.

Für den umgekehrten Weg, von einem Host, einer Anmeldemethode, einem Gerät und einer Liste von Befehlen zu einem Skript, das jede der folgenden Prüfungen besteht, verwenden Sie den [Generator für Expect-Skripte](/tools/expect-script-builder). Die Datei eines Scripted-Monitors von BIG-IP LTM, deren Zeilen nur aus `send` und `expect` bestehen und die kein Tcl ist, liest [Scripted-Monitore von BIG-IP erklärt](/tools/bigip-scripted-monitor-explainer).

## Wie das Tool die Argumente von expect liest

Die Argumente von `expect`, `expect_user`, `expect_before` und `expect_after` werden so gelesen, wie Expect 5.45.4 sie liest (`expect.c`), nicht so, wie sie aussehen:

- Ein einzelnes Argument in geschweiften Klammern ist nur dann eine Liste aus Mustern und Rümpfen, wenn vor seinem ersten sichtbaren Zeichen ein Zeilenumbruch steht. Andernfalls ist der ganze Block ein einziges Argument: ein einzelnes Glob-Muster. Die CAVEATS der Manpage nennen das eine Heuristik und bieten `-brace`, um die Liste zu erzwingen, und `-nobrace`, um ein einziges Argument zu erzwingen; beide werden entsprechend gelesen.
- Ein Wort, das mit `-` beginnt, ist eine Option, mit vollem Namen oder einer eindeutigen Abkürzung (`-re` für `-regexp`, `-exa` für `-exact`). `-gl`, `-re`, `-ex` und `--` machen das nächste Wort zu einem Muster, wie auch immer es aussieht.
- `eof`, `timeout`, `full_buffer`, `null` und `default` sind Schlüsselwörter, wenn sie genau so geschrieben sind, mit oder ohne Anführungszeichen.
- Das Wort nach einem Muster ist immer dessen Rumpf.

## Was das Tool prüft

- **E1, ein Secret im Klartext (Fehler):** ein Literal, das direkt nach einem Prompt gesendet wird, der nach einem Passwort fragt, oder ein Literal, das einer Variablen zugewiesen wird, deren Name auf ein Passwort, Secret oder Token hindeutet. Der Wert wird in der Ausgabe maskiert. Beziehen Sie Secrets aus der Kommandozeile (`lindex $argv N`), aus der Umgebung (`$env(NAME)`) oder vom Benutzer (`stty -echo`, `expect_user`).
- **E2, der Timeout (Warnung oder Hinweis):** `set timeout -1` ist ein unendlicher Timeout; ein `expect`, das vor jedem `set timeout` lief, hat den Standardwert verwendet. `expect(1)`: „The default timeout period is 10 seconds but may be set, for example to 30, by the command "set timeout 30". An infinite timeout may be designated by the value -1.“
- **E3, ein Muster, das zu früh zutrifft (Warnung oder Hinweis):** `"*"` und `-re ".*"`, die laut `expect(1)` „will flush the output buffer without reading any more output from the process“, also den Ausgabepuffer leeren, ohne weitere Ausgabe des Prozesses zu lesen; Prompts aus einem Zeichen wie `">"`, die auf das erste solche Zeichen irgendwo in der Ausgabe passen; und `"$"` allein, das in einem Glob-Muster der Anker für das Ende ist: Es passt sofort auf einen leeren Puffer und nie auf Text, der bereits wartet (`exp_glob.c` in 5.45.4, mit dem echten `expect` geprüft), wartet also nie auf einen Shell-Prompt. Ein regulärer Ausdruck aus `$` oder `^` allein passt ebenfalls sofort. Muster sind nicht verankert; die Manpage empfiehlt `$`, „if you can exactly describe the characters at the end of a string“, also wenn sich die Zeichen am Ende genau beschreiben lassen; schreiben Sie den Prompt daher mit dem, was davor steht: `-ex "$ "` oder `-re {\$ $}`.
- **E4, das Skript endet mit einem send (Warnung):** Nichts liest die Antwort des Programms. „Upon exiting, all connections to spawned processes are closed.“
- **E5, kein Wagenrücklauf (Hinweis oder Warnung):** ein `send`, dessen String nicht auf `\r` oder `\n` endet; und ein `send {...\r}` in geschweiften Klammern, in dem Tcl nichts ersetzt, sodass das Programm einen Backslash und ein r erhält. `expect(1)`: „Characters are sent immediately although programs with line-buffered input will not read the characters until a return character is sent. A return character is denoted "\r".“
- **E6, ein Zeilenvorschub, wo ein Wagenrücklauf gemeint ist (Hinweis):** Der String endet auf `\n`.
- **E7, kein Timeout-Handler (Hinweis):** expects auf gewöhnliche Muster ohne ein Muster `timeout` (oder `default`). „If no timeout keyword is used, an implicit null action is executed upon timeout“, und das Skript läuft weiter, als hätte das Muster gepasst.
- **E8, `exp_continue` außerhalb eines expect-Rumpfs (Fehler).**
- **E9, Substitution in einem Muster in Anführungszeichen (Warnung oder Hinweis):** `[brackets]` werden als Befehl ausgeführt und `$names` ersetzt, bevor Expect das Muster liest, in der einzeiligen Form ebenso wie im Block in geschweiften Klammern: „In this one case, the usual Tcl substitutions will occur despite the braces.“
- **E10, die Frage nach dem Host-Key (Hinweis):** `ssh` wird ohne `StrictHostKeyChecking=no`, `off` oder `accept-new` gestartet, und kein Muster beantwortet eine Frage `(yes/no)`. Der Standardwert von OpenSSH ist `ask` (ssh_config(5)).
- **E11, `sleep` (Hinweis):** eine feste Wartezeit, wo ein `expect` auf das Ereignis warten würde.
- **E12, `log_user 0` ohne nachfolgendes `log_user 1` (Hinweis).**
- **E13, `set timeout` nach dem ersten expect (Warnung):** Dieses expect lief mit dem Standardwert.
- **E14, nichts gestartet (Hinweis).**
- **E15, `stty -echo` ohne nachfolgendes `stty echo` (Warnung):** Das Idiom der Manpage selbst zum Lesen eines Passworts schaltet das Echo wieder ein, sobald das Passwort gelesen ist.
- **E16, `close` ohne `wait` (Hinweis):** „close does not call wait since there is no guarantee that closing a process connection will cause it to exit.“
- **E17, ein send vor dem ersten expect (Warnung):** „It is a good idea to precede the first send to a process by an expect. expect will wait for the process to start, while send cannot.“
- **E18, `set timeout` in einer Prozedur ohne `global timeout` (Hinweis):** „variables written are always in the local scope (unless a "global" command has been issued)“, daher gilt der Wert nur für die expects dieser Prozedur.
- **E19, ein Block in geschweiften Klammern, als ein Muster gelesen (Warnung):** ein `expect {...}`, dessen erstes Muster in derselben Zeile wie die öffnende Klammer steht, ob der Block in einer Zeile geschrieben ist oder darunter weitergeht. Expect 5.45.4 liest ihn als ein einziges Glob-Muster, den ganzen Text des Blocks, den die Ausgabe fast nie enthält; daher läuft keiner der Zweige darin, nicht einmal der Zweig `timeout`, und es folgt die implizite Null-Aktion. Mit dem echten `expect` geprüft: Ein einzeiliger Block, dessen Text in der Ausgabe vorkam, kehrte nach Ablauf des vollen Timeouts zurück, ohne dass ein Zweig lief. Beginnen Sie den Block mit einem Zeilenumbruch nach der Klammer, oder schreiben Sie `expect -brace {...}`.
- **E20, ein Muster, als Option gelesen (Fehler):** ein Muster, das mit `-` beginnt, etwa `"--More--"`, in Anführungszeichen, in geschweiften Klammern oder in einem Block in geschweiften Klammern. `expect` liest jedes Wort, das mit `-` beginnt, als Option, daher scheitert der Befehl mit `bad flag` (oder `ambiguous flag`), und das Skript endet. `expect(1)`: „Any pattern beginning with a "-" should be protected“, und zwar mit `-gl`; `-ex` und `--` schützen es ebenfalls.
- **Syntax:** wo der Parser anhält (eine fehlende geschweifte Klammer, ein nicht abgeschlossenes Anführungszeichen), mit der eigenen Meldung von Tcl; die Befehle davor werden trotzdem erklärt. Die Argumentexpansion `{*}` (Regel [5] in Tcl(n), Tcl 8.5 und neuer) wird akzeptiert, und die Zusammenfassung nennt die Zeilen, die sie verwenden.

## Die Ausgabe lesen

Die Zusammenfassung gibt an, ob Tcl das ganze Skript lesen kann, zählt die Befunde, nennt die gestarteten Programme, gibt den Timeout an, der beim ersten `expect` gilt (zuerst die Option `-timeout`, dann ein in derselben Prozedur gesetzter Wert, dann das `set timeout` des Skripts, sonst der Standardwert), und sagt, ob das Skript mit `interact` endet, auf `eof` wartet oder nie wartet, bis das Programm endet. Die Tabelle des Dialogs ordnet jedem `expect` auf den Prozess das `send` zu, das darauf antwortet; ein maskierter Wert dort ist ein Secret, das das Skript im Klartext eintippt, und ein ganzer Block, der als ein Muster angezeigt wird, ist die Lesart nach E19. Die Muster werden unter jedem `expect` mit ihrer Art des Abgleichs aufgeführt (standardmäßig Glob, `-re`, `-ex`, `-nocase`), die Schlüsselwörter `eof`, `timeout`, `full_buffer`, `null` und `default` mit dem, wofür jedes steht.

## Grenzen

- Rümpfe werden in der Reihenfolge des Quelltexts gelesen. Das Tool kann nicht wissen, welchen Zweig ein Lauf nimmt, wie oft eine Schleife läuft oder ob eine Prozedur je aufgerufen wird; ein `set timeout` in einer Prozedur, die `global timeout` deklariert, wird dort gelesen, wo die Prozedur definiert ist.
- Strings und Muster, die von einer Variablen abhängen, werden so angezeigt, wie geschrieben (`$env(PW)\r`), nicht mit ihrem Wert. Ein mit `{*}` expandiertes Wort wird als ein Wort gelesen, da es von seinem Wert abhängt, wie viele Wörter daraus werden.
- Die Erkennung von Secrets ist eine Heuristik: ein Literal aus einem Wort, das direkt nach einem Passwort-Prompt gesendet oder in einer entsprechend benannten Variablen gespeichert wird. Ein Passwort, das nach einem Prompt gesendet wird, den das Skript nicht als solchen benennt, wird nicht erkannt.
- `expect_before`, `expect_after` und `expect_user` werden erklärt, aber nicht in den Dialog aufgenommen, da sie nicht von sich aus auf den Prozess warten. `interact`, `expect_tty` und `expect_background` lesen ein einzelnes Argument in geschweiften Klammern mit demselben Test wie `expect`, aber das Tool liest ihre Zweige nicht.
- Nach einem E20 liest das Tool das Wort als das Muster, das der Autor gemeint hat; das echte `expect` hält dort an.
- Backslash-Escapes behalten die Lesart von Tcl 8.4: `\x` nimmt jede folgende Hexziffer, und `\U` ist kein Escape. In Tcl 8.6 und 9.0 nimmt `\x` eine oder zwei Ziffern und `\U` bis zu acht.
- Array-Referenzen wie `$env(HOME)` werden akzeptiert; der Index bleibt als Text erhalten.

Die Portabilitätsansicht des [Regex-Toolkit](/tools/regex) listet die Konstrukte auf, die in den Advanced Regular Expressions von Tcl anders gelesen werden als in JavaScript oder PCRE2.

## Ergebnisse teilen

Unter der Zusammenfassung erzeugt **Ergebnisse teilen** einen Link auf diese Seite, und zwar nur, wenn Sie die Schaltfläche wählen. Der Link enthält nach dem `#` eine Kopie des Skripts, in der jedes Secret, das Regel E1 markiert (ein Literal, das direkt nach einer Passwortabfrage eingetippt oder einer wie ein Passwort benannten Variablen zugewiesen wird), durch die Punkte ersetzt ist, die diese Seite dafür anzeigt, einen pro Zeichen. Die Kopie liest sich gleich: E1 markiert weiterhin dieselbe Zeile mit derselben maskierten Vorschau, und der Dialog, die übrigen Befunde und die Angaben ändern sich nicht. Das Popover nennt zuerst, was der Link enthält, und bietet dann „Link kopieren“ und, sofern der Browser eines bietet, das Teilen-Menü an; die Adresse der Seite bleibt unverändert. Es nennt auch, wie viele Passwörter die Kopie ersetzt hat. Ein Passwort, das mit Escape-Sequenzen geschrieben ist, lässt sich nicht Zeichen für Zeichen ersetzen, daher gibt es dafür keinen Link: Schreiben Sie es ohne Escape-Sequenzen oder, besser, lesen Sie es aus der Umgebung, wie es der Rat von E1 selbst vorsieht. Ein Skript nennt Hosts, Benutzer und Befehle, daher bittet das Popover Sie, es zu lesen, bevor Sie den Link senden. Danach wird die Kopie nach allen anderen Zugangsdaten durchsucht, die ein Standard definiert (ein privater Schlüssel im PEM-Format, eine Zeile `Authorization` in einem send, ein Passwort in einer URL ([RFC 3986](https://www.rfc-editor.org/rfc/rfc3986), Abschnitt 3.2.1), eine AWS-Zugriffsschlüssel-ID, ein `ENC`-Wert von FortiOS): Findet sich eines davon, gibt es keinen Link, und das Popover nennt seine Zeile.

Laut [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (Abschnitt 3.5, abgerufen am 01.11.2026) ist das Fragment „separated from the rest of the URI prior to a dereference“, also vor der Dereferenzierung vom Rest der URI getrennt; daher wird, was nach dem `#` steht, beim Öffnen des Links nicht an den Server gesendet. Es bleibt in der Adressleiste und im Verlauf dessen, der den Link öffnet, und wer den Link hat, kann es lesen.

- **Länge.** Insgesamt höchstens 16.384 Zeichen, die Grenze, die die Website für jeden Wert nach dem `#` setzt; ist der geteilte Inhalt länger, gibt es keinen Link, und das Popover nennt seine Länge.
- **Öffnen eines Links.** Die Kopie füllt das Feld wie beim Einfügen, und die Seite liest sie, rein statisch: Es wird nichts gestartet, ausgeführt oder gesendet. Danach verschwinden die Werte sofort aus der Adresse der Seite, ohne dass eine Anfrage gesendet wird; ein Neuladen oder die Schaltfläche „Teilen“ der Seite überträgt daher nichts.
