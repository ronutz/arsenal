# AFM-DoS-Vektoren und -Profile erklärt

Eine Device-DoS-Konfiguration von BIG-IP AFM (Advanced Firewall Manager) besteht aus hundert kleinen Stellschrauben, die auf drei Arten versagen: Schwellenwerte, die nie auslösen, Schwellenwerte, die still auslösen, und Schwellenwerte, die jemand gesetzt hat, ohne zu wissen, was der Vektor tatsächlich zählt. Das Tool gibt Ihnen die Konfiguration so wieder, wie das Referenzhandbuch sie lesen würde.

Fügen Sie einen Konfigurationsblock `security dos device-config`, einen oder mehrere Blöcke `security dos profile` oder beides ein, genau so, wie tmsh sie auflistet. Jeder Vektoreintrag erscheint als Karte: die Identität des Vektors in der einzeiligen Beschreibung von F5 (das Tool enthält die vollständige Vektortabelle mit 105 Einträgen aus der tmsh-Referenz, einschließlich der sys-db-Tunables), jedes Schwellenwertfeld mit der Semantik aus der Referenz versehen und darunter deterministische Beobachtungen.

Die Semantik ist wichtiger, als es aussieht. Eine Erkennungsschwelle in pps vergleicht einen Einminutendurchschnitt mit einem absoluten Wert; die Prozentvariante vergleicht denselben Einminutendurchschnitt mit einer dynamisch gelernten Baseline über eine Stunde; und das interne Rate Limit wird auf Plattformen, die dafür Hardware haben, in die Hardware programmiert, wobei fehlerhafte Pakete unabhängig davon immer verworfen werden. Das Tool schreibt jede dieser Bedeutungen an dem Feld aus, für das sie gilt.

Die Beobachtungen sind der eigentliche Zweck. Die wichtigste Prüfung gilt der Umkehrung, vor der die Artikelserie von F5 zur Fehlersuche bei SYN-Cookies warnt: Eine Mitigation-Grenze unterhalb der Erkennungsschwelle begrenzt den Datenverkehr, bevor überhaupt ein Angriff erklärt wird, sodass Pakete ohne Angriffs-Log verworfen werden. Das Tool markiert das in beiden Namensfamilien der Attribute, beim Gerät (`default-internal-rate-limit` gegenüber `detection-threshold-pps`) und im Profil (`rate-limit` gegenüber `rate-threshold`), und wiederholt die Prüfung pro Quelle für die Raten der Bad Actors. Dazu kommen: der Modus der automatischen Schwellenwerte, erklärt so, wie ihn das Schulungsmaterial zu DDoS (Distributed Denial of Service) beschreibt (Erkennungsschwellen passen sich an den beobachteten Datenverkehr an; Mitigation-Grenzen greifen immer abhängig vom Stress des Systems, sodass Anomalien ohne Stress zwar einen Alarm auslösen, aber nicht blockieren), manuelle Werte, die im automatischen Modus als wirkungslos markiert werden, `simulate-auto-threshold`, wie von der Referenz verlangt auf den manuellen Modus beschränkt, deaktivierte Erkennung, während eine endliche Grenze still per Policing begrenzt, `enforce disabled` und `detect-only`, die als Monitoring statt Mitigation benannt werden, und verwaiste Bad-Actor-Verknüpfungen in beide Richtungen.

Ein einzelner Vektorname ergibt eine Karte; das Wort `vectors` zeigt den ganzen Katalog, gruppiert in neun Kategorien. Vektoren außerhalb der kuratierten Tabelle werden trotzdem geparst und erhalten die Schwellenwert-Mechanik, mit dem ehrlichen Hinweis, dass sie außerhalb der Tabelle liegen, statt dass etwas geraten wird.

Das Tool erklärt defensive Konfiguration und erzeugt nie Datenverkehr irgendeiner Art. Alles läuft lokal; nichts, was Sie einfügen, verlässt die Seite.

## Ergebnisse teilen

Oben in der Auswertung erzeugt **Ergebnisse teilen** einen Link auf diese Seite, und zwar nur, wenn Sie die Schaltfläche wählen. Der Link enthält nach dem `#` das Feld so, wie eingegeben, und sonst nichts. Das Popover nennt zuerst, was der Link enthält, dann einen eigenen Warnhinweis: DoS-Schwellenwerte zeigen, was Ihre Schutzmaßnahmen durchlassen, lesen Sie sie also, bevor Sie den Link senden. Dann bietet es „Link kopieren“ und, sofern der Browser eines bietet, das Teilen-Menü an; die Adresse der Seite bleibt unverändert.

Die Seite überspringt jeden Konfigurationsblock, den sie nicht erklärt; auch eine ganze Konfigurationsdatei erhält also eine Auswertung, und ein Link dazu würde alles enthalten, was darin steht. Solange der eingefügte Text eine geheime Einstellung enthält, gibt es daher keinen Link, und das Popover nennt die Einstellung: ein tmsh-Attribut namens `password`, `passphrase` oder `secret` oder eines, dessen Name darauf endet (`encrypted-password`, `proxy-ca-passphrase`, `shared-secret`), `bind-pw` oder `community-name`, gefolgt von einem anderen Wert als `none`; oder ein `Authorization`-Header an beliebiger Stelle, etwa im `send`-String eines Monitors. Die [tmsh-Referenz von F5 zu gtm monitor http](https://clouddocs.f5.com/cli/tmsh-reference/latest/modules/gtm/gtm_monitor_http.html) (abgerufen am 27.10.2026) führt `password` neben `send` auf, und [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110) (Abschnitt 11.6.2, abgerufen am 27.10.2026) definiert den Wert von Authorization als Zugangsdaten. Entfernen Sie diese Zeile und wählen Sie die Schaltfläche erneut: Die Seite zeigt diese Werte nie an, daher liest sich der Rest genauso.

Laut [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (Abschnitt 3.5, abgerufen am 27.10.2026) ist das Fragment „separated from the rest of the URI prior to a dereference“, also vor der Dereferenzierung vom Rest der URI getrennt; daher wird der Text beim Öffnen des Links nicht an den Server gesendet. Er bleibt in der Adressleiste und im Verlauf dessen, der den Link öffnet, und wer den Link hat, kann ihn lesen.

- **Länge.** Insgesamt höchstens 16.384 Zeichen, die Grenze, die die Website für jeden Wert nach dem `#` setzt; ist der geteilte Inhalt länger, gibt es keinen Link, und das Popover nennt seine Länge.
- **Öffnen eines Links.** Der Text füllt das Feld wie beim Einfügen, und die Seite liest ihn; es wird nichts gesendet. Danach verschwindet der Wert sofort aus der Adresse der Seite, ohne dass eine Anfrage gesendet wird; ein Neuladen oder die Schaltfläche „Teilen“ der Seite überträgt daher nichts.
