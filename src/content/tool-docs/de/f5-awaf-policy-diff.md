## Was das Tool tut

Fügen Sie zwei deklarative Sicherheitsrichtlinien von F5 AWAF (Advanced WAF, früher BIG-IP ASM, Application Security Manager) ein, einen Stand vorher und einen nachher, und das Tool vergleicht sie und ordnet jede sicherheitsrelevante Änderung als Lockerung oder Verschärfung ein. Es beantwortet die eine Frage, die nach einer Tuning-Sitzung zählt: Hat das eine Lücke geöffnet? Es läuft vollständig in Ihrem Browser und nimmt nie Kontakt zu einem BIG-IP auf.

## Die Unterscheidung, die das Tool trifft

Nicht jede Lockerung ist gefährlich. Eine einzelne zulässige URL oder einen Parameter hinzuzufügen ist eine begrenzte Aufweitung für eine einzelne Entität: der normale, richtige Weg, ein False Positive zu beseitigen. Genauer hinsehen sollte man bei einer Lockerung, die den Schutz für die ganze Richtlinie aufweitet: die Durchsetzung auf Transparent umstellen (dann blockiert die gesamte Richtlinie nicht mehr), eine Violation oder eine Evasion deaktivieren, Data Guard ausschalten, einem vom Client gelieferten Header X-Forwarded-For vertrauen, Signaturen ins Staging verschieben oder eine Wildcard-Entität hinzufügen, die auf viele URLs zugleich passt. Das Tool trennt diese Lockerungen für die ganze Richtlinie von den begrenzten, damit ein Tuning-Vergleich nicht unbemerkt zu einer Verschlechterung der Sicherheit wird.

## Die Bewertung

Ist eine Lockerung für die ganze Richtlinie vorhanden, lautet die Bewertung „Das hat eine Lücke geöffnet“, und diese Änderungen werden zuerst aufgeführt, jede mit einer Bedenklichkeitsstufe. Bleiben alle Aufweitungen auf Entitäten begrenzt, lautet die Bewertung „Nur begrenzte Änderungen“, der sichere Bereich für das Tuning von False Positives. Erhöht jede Änderung den Schutz, lautet sie „Verschärft“. Das Tool listet auch die Verschärfungen auf, sodass Sie das vollständige Bild dessen sehen, was sich zwischen den beiden Richtlinien bewegt hat.

## Was das Tool vergleicht

Es liest die sicherheitsrelevanten Abschnitte, die das deklarative Richtlinienschema von F5 definiert: enforcementMode, das Staging in signature-settings, general.trustXff, data-guard, csrf-protection, die Block-Flags pro Violation unter blocking-settings, die Aktivierung pro Evasion und die Entitätslisten für URLs, Parameter und Dateitypen (wobei ein Name mit einem Sternchen als Wildcard behandelt wird). Das sind dieselben Feldpfade, die auch „Deklarative AWAF-Richtlinien erklärt“ und „AWAF-Umgehungstechniken erklärt“ prüfen.

## Grundlagen

Die Bedeutung der Lockerungen folgt dem Schema von F5 für deklarative WAF-Richtlinien und der ASM-Dokumentation dazu, wie eine Richtlinie im Modus Transparent und ein gelöschtes Block-Flag die Durchsetzung beenden, zusammen mit der Regel aus K70544352, nur dort zu lockern, wo ein False Positive aufgetreten ist, und die Lockerung zu begrenzen. Keine der beiden eingefügten Richtlinien wird hochgeladen oder verlässt die Seite.

## Ergebnisse teilen

Unter der Bewertung erzeugt **Ergebnisse teilen** einen Link auf diese Seite, und zwar nur, wenn Sie die Schaltfläche wählen. Der Link enthält nach dem `#` beide Richtlinien so, wie eingefügt, benannt als `before` und `after` wie die beiden Felder, sobald die Seite sie verglichen hat. Das Popover nennt zuerst, was der Link enthält, und bietet dann „Link kopieren“ und, sofern der Browser eines bietet, das Teilen-Menü an; die Adresse der Seite bleibt unverändert. Richtlinien können interne Hosts, URLs und Adressen nennen, daher bittet das Popover Sie, beide zu lesen, bevor Sie den Link senden. Beide Felder durchlaufen dieselbe Prüfung wie bei „Deklarative AWAF-Richtlinien erklärt“. Bevor ein Link angeboten wird, wird der Text nach Zugangsdaten durchsucht, die ein Standard definiert: ein privater Schlüssel im PEM-Format, eine Zeile `Authorization` oder `Proxy-Authorization` mit beliebigem Schema ([RFC 9110](https://www.rfc-editor.org/rfc/rfc9110), Abschnitte 11.6.2 und 11.7.2: Der Wert „consists of credentials“), eine Zeile `Cookie` oder `Set-Cookie` mit einem Wert ([RFC 6265](https://www.rfc-editor.org/rfc/rfc6265), Abschnitte 4.1.1, 4.2.1 und 8.4, wonach ein Cookie häufig eine Sitzungskennung enthält), ein JWT ([RFC 7519](https://www.rfc-editor.org/rfc/rfc7519), Abschnitt 1), ein Passwort in einer URL ([RFC 3986](https://www.rfc-editor.org/rfc/rfc3986), Abschnitt 3.2.1), eine AWS-Zugriffsschlüssel-ID oder ein `ENC`-Wert von FortiOS; alle abgerufen am 01.11.2026. Findet sich eines davon, gibt es keinen Link: Das Popover nennt seine Zeile, und Sie setzen einen Platzhalter an seine Stelle und wählen die Schaltfläche erneut. Ein Wert, dessen Name nur nach einem Secret aussieht (ein JSON-Eintrag `token`, ein `password=` in der Query einer URL), blockiert den Link nicht; das Popover nennt den ersten solchen Wert, damit Sie ihn prüfen können. Das Popover gibt an, in welchem Feld die Zeile steht.

Laut [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (Abschnitt 3.5, abgerufen am 01.11.2026) ist das Fragment „separated from the rest of the URI prior to a dereference“, also vor der Dereferenzierung vom Rest der URI getrennt; daher wird, was nach dem `#` steht, beim Öffnen des Links nicht an den Server gesendet. Es bleibt in der Adressleiste und im Verlauf dessen, der den Link öffnet, und wer den Link hat, kann es lesen.

- **Länge.** Insgesamt höchstens 16.384 Zeichen, die Grenze, die die Website für jeden Wert nach dem `#` setzt; ist der geteilte Inhalt länger, gibt es keinen Link, und das Popover nennt seine Länge.
- **Öffnen eines Links.** Beide Felder werden wie beim Einfügen gefüllt, und die Seite vergleicht sie wie gewohnt. Ein Link, dem eines der beiden fehlt, wird ignoriert. Danach verschwinden die Werte sofort aus der Adresse der Seite, ohne dass eine Anfrage gesendet wird; ein Neuladen oder die Schaltfläche „Teilen“ der Seite überträgt daher nichts.
