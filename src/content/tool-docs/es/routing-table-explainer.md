## Qué hace

Pega lo que imprimió un host como tabla de enrutamiento y la herramienta te la lee. Reconoce cuatro salidas: Linux iproute2 (`ip route`, `ip route show table all`, `ip -6 route`, `ip -d route`), Linux net-tools (`netstat -rn` y `route -n`, la “Kernel IP routing table”), `netstat -rn` de BSD y macOS (“Routing tables”, “Internet:”, “Internet6:”) y `route print` de Windows con sus tablas IPv4 e IPv6, Active y Persistent. Cada ruta se convierte en una fila de la misma tabla (prefijo de destino, siguiente salto, interfaz, métrica, tipo, tabla), y cada fila se abre en una lectura campo por campo en lenguaje llano. Después, la herramienta enumera las rutas predeterminadas de cada tabla y dice cuál gana, y un segundo cuadro responde a “¿qué ruta usa este destino?” con las reglas que aplica un router. Nada sale del navegador, y no se cambia ni se consulta ninguna ruta.

## Qué significa cada campo

Las lecturas salen de los manuales de los comandos, consultados el 2026-10-19.

- **iproute2.** Primero va el destino; `default` es “equivalent to IP 0/0 or to IPv6 ::/0” (equivalente a esos prefijos de longitud cero), y una dirección sin más es una ruta de host porque “If the length of the prefix is missing, ip assumes a full-length host route” (si falta la longitud del prefijo, ip supone una ruta de host de longitud completa) ([ip-route(8)](https://man7.org/linux/man-pages/man8/ip-route.8.html)). Después vienen `via` (el router de siguiente salto), `dev` (el dispositivo de salida), `proto` (kernel, boot, static, ra y redirect tienen significados fijos; el kernel no interpreta ninguna otra etiqueta, [rtnetlink(7)](https://man7.org/linux/man-pages/man7/rtnetlink.7.html)), `scope` (host, link, global), `src` (la dirección de origen preferida), `metric` (“routes with lower values are preferred”, se prefieren las rutas con valores más bajos), `table`, el flag de siguiente salto `onlink` y opciones como `pref`, `mtu` y `nhid`. Una palabra de tipo al principio dice qué hace la ruta: unicast reenvía, local y broadcast pertenecen a la tabla propia del host, y blackhole, unreachable, prohibit y throw no reenvían. Las líneas `nexthop` sangradas se asocian a la ruta de arriba como sus saltos multipath, con su `weight`.
- **net-tools.** Destination junto con Genmask es el prefijo (“‘0.0.0.0’ for the default route”, así aparece la ruta predeterminada), Gateway es “The gateway address or ‘*’ if none set” (la dirección de la puerta de enlace, o un asterisco si no hay ninguna), y las letras de Flags son las que [route(8)](https://man7.org/linux/man-pages/man8/route.8.html) enumera en OUTPUT: U up, H host, G use gateway, R, D, M, A, C y ! para reject. `route -n` imprime Metric, Ref y Use; `netstat -rn` imprime en su lugar MSS, Window e irtt.
- **BSD y macOS.** Las letras de Flags se decodifican a partir de [netstat(1) de FreeBSD](https://man.freebsd.org/cgi/man.cgi?query=netstat&sektion=1) (U, G, H, S, B, b, D, L, M, R, X, 1, 2, 3) y del netstat.1 de Apple, que añade C, c, I, i, m, r, W, Y y g; una letra que solo enumera macOS se marca como tal. Una puerta de enlace `link#N` es una ruta directa, y una puerta de enlace como `0:e0:b5:36:cf:4f` es una dirección de capa de enlace. Estas salidas no llevan métrica.
- **Windows.** Las Active Routes son las rutas en uso; las Persistent Routes son configuración guardada ([Microsoft Learn, KB 2966111](https://learn.microsoft.com/en-us/troubleshoot/windows-client/networking/incorrect-default-gateways-in-persistent-routes)). En la tabla IPv4, Netmask da la longitud del prefijo, Gateway es una dirección de siguiente salto o `On-link`, Interface es la dirección del adaptador local y, entre rutas al mismo destino, “the route with the lowest metric is selected” (se elige la de métrica más baja) ([Microsoft Learn, The IP routing table](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-server-2003/cc779122(v=ws.10))). En la tabla IPv6, If es un número de interfaz de la Interface List; una puerta de enlace que salta a la línea siguiente se une a su fila.

Todo lo que la herramienta no entiende se muestra, nunca se descarta: un token que no puede leer se queda en su ruta bajo “No entendido”, y una línea que no es ni una ruta ni una estructura conocida (encabezados, líneas separadoras, títulos de sección, un prompt `$ ip route` copiado con la salida) se enumera con su número de línea.

## Rutas predeterminadas y la búsqueda

Una ruta predeterminada es una ruta con longitud de prefijo cero. Cuando una tabla tiene varias, todas tienen la misma longitud, así que decide la métrica y gana la más baja; la herramienta nombra la ganadora o dice por qué no puede hacerlo (métricas iguales, o una salida sin ninguna métrica comparable, como el netstat de BSD o las Persistent Routes de Windows que muestran `Default`).

La búsqueda aplica las reglas de poda del [RFC 1812, sección 5.2.4.3](https://www.rfc-editor.org/rfc/rfc1812.txt): la coincidencia básica conserva las rutas cuyo prefijo contiene el destino, la coincidencia más larga conserva la más larga de ellas y, entre longitudes iguales, gana la métrica más baja. Muestra las candidatas, las supervivientes y la regla que decidió. Para iproute2, lee las tablas en el orden de las tres reglas de política predeterminadas: local, después main y después default ([ip-rule(8)](https://man7.org/linux/man-pages/man8/ip-rule.8.html)); cualquier otra tabla, como una `table 100`, aparece como no consultada, porque solo llegaría a ella una regla de política propia. Una ruta `throw` ganadora pasa la búsqueda a la tabla siguiente, como describe ip-route(8). En Windows solo se consultan las Active Routes. Las rutas cuyo destino no es una dirección con longitud (un nombre impreso sin `-n`, una abreviatura, un valor ocultado) aparecen como excluidas.

## Lo que no puede saber

- `ip route show table 100` no imprime la palabra `table` en sus líneas, así que el listado pegado de una sola tabla se lee como la tabla main, la predeterminada del listado.
- iproute2 no imprime la métrica cuando es cero: en la captura en la que se basan los ejemplos, `route -n` mostraba Metric 0 para una ruta que `ip route` imprimía sin ella, y la herramienta compara esa ruta como métrica 0.
- La “Kernel IPv6 routing table” de net-tools de Linux se conserva como no entendida, porque route(8) solo documenta las columnas de IPv4; pega en su lugar `ip -6 route`.
- Las reglas de política distintas de las tres predeterminadas no aparecen en la salida de una tabla de enrutamiento, así que la herramienta no puede seguirlas.

## Ejemplos

El botón Ejemplo carga un `ip route show` real, capturado el 2026-10-19 en un host con la dirección 192.0.2.2, y pregunta por 192.0.2.77: la ruta predeterminada 0.0.0.0/0 y la conectada 192.0.2.0/24 la contienen, y la /24 gana por coincidencia más larga, así que el paquete se entrega directamente (on-link) en eth0. Los vectores de referencia añaden, del mismo host, `ip route show table all` (donde 192.0.2.200 está dentro de una /25 de la tabla 100, pero ninguna regla llega a la tabla 100 y lo entrega la /24 de main), su `ip -d route show table 100` (dos rutas predeterminadas con métricas 100 y 200, y rutas blackhole, unreachable, prohibit y throw), su `netstat -rn` y su `route -n`, el ejemplo de multipath de dieciséis vías de FRRouting, un `route print` de Windows 10 (ff02::1 coincide con dos rutas ff00::/8 y la métrica 331 gana a 5256), el ejemplo de rutas persistentes de Microsoft y las tablas `netstat -nr` y `netstat -r` del FreeBSD Handbook.

## Compartir resultados

En la parte superior de la lectura, **Compartir resultados** genera un enlace a esta página, solo cuando lo presionas, que lleva la tabla tal como se pegó (`#input=...`) y, si escribiste uno, el destino (`&destination=192.0.2.77`); no se lleva qué lectura campo por campo está abierta. Antes de que copies nada, la ventana emergente añade una advertencia: una tabla de enrutamiento nombra direcciones internas, puertas de enlace e interfaces, así que léela antes de enviar el enlace. Todo lo que lleva el enlace va después del `#`, que según el [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (sección 3.5, consultado el 2026-10-27) queda “separated from the rest of the URI prior to a dereference” (separado del resto del URI antes de resolverlo): el navegador no lo envía al servidor cuando se abre el enlace, pero se queda en la barra de direcciones y en el historial de quien lo abra, y cualquiera que tenga el enlace puede leerlo.

- **Longitud.** Un enlace lleva como máximo 16.384 caracteres, el límite que el sitio aplica a todo valor después del `#`; si es más largo, no hay enlace, y la ventana emergente indica la longitud que tendría.
- **Al abrir un enlace.** La tabla rellena el cuadro como lo haría un pegado, el destino rellena su campo (y se vacía cuando el enlace no lleva ninguno), y la página vuelve a analizar y a buscar. La página rechaza un destino mal formado con su propio mensaje, como si lo escribieras. Se acepte o no, los valores salen después de la propia dirección de la página al instante, sin ninguna solicitud, así que al recargar, con un marcador o con el propio botón Compartir de la página no se lleva nada que no hayas decidido compartir.

## API

El mismo motor responde a la operación `/api/v1/routing-table-explainer` de la API HTTP del sitio, descrita campo por campo en el contrato OpenAPI de la [página de la API](/api), con ejemplos tomados de los vectores de referencia. El contrato también indica si este sitio sirve la API.

- **Solicitud.** O bien la salida como texto, que solo se analiza, o bien un objeto JSON `{"text": "<the printout>", "lookup": "<an IPv4 or IPv6 address>"}`, que se analiza y en el que después se hace la búsqueda.
- **Respuesta.** `parse` contiene `format` (`iproute2`, `netstat-linux`, `netstat-bsd`, `windows` o `unknown`), `routes` (cada una con `index`, `line`, `raw`, `section`, `family`, `destination`, `prefix`, `prefixLength`, `isDefault`, `type`, `gateway`, `onLink`, `interface`, `metric`, `metricText`, `protocol`, `scope`, `src`, `flags`, `nhFlags`, `nexthops`, `attributes`, `unparsed` y `notes`), `interfaces` (la Interface List de Windows), `defaults` (por tabla: `section`, `consulted`, `candidates`, `winner` y `reason`), `unparsedLines`, `structureLines`, `lineCount` y `warnings`. `lookup` es null, o contiene `destination`, `family`, `stages` (cada una con `section`, `candidates`, `longest`, `survivors`, `winner`, `outcome` y `decidedBy`), `skipped`, `unusable`, `winner`, `action` y `decidedBy`. Para la captura de ejemplo con la búsqueda de 192.0.2.77, la respuesta es la ruta con `index` 1 (192.0.2.0/24, que la página muestra como n.º 2), acción `on-link`, decidida por `longest-prefix`.
- **Errores.** HTTP 400, `invalid_input`, con el mensaje del motor: una búsqueda que no es una sola dirección IPv4 o IPv6, o una solicitud que empieza por `{` pero no es el objeto JSON anterior. Un texto que no es una tabla de enrutamiento no se rechaza: `format` es `unknown` y las líneas aparecen como no entendidas.
