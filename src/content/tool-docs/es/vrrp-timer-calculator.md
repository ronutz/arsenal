## Qué hace

El protocolo de redundancia de router virtual (VRRP, Virtual Router Redundancy Protocol) permite que varios routers de una LAN compartan una misma dirección de puerta de enlace predeterminada. Uno de ellos, el Active Router, reenvía el tráfico de la dirección virtual y envía un ADVERTISEMENT en cada intervalo; los demás, los Backups, esperan, y el primero que deja de oír ADVERTISEMENT toma el control. Cuánto dura esa espera, quién gana y qué dirección MAC ven los hosts lo fija todo el estándar, y esta calculadora lo obtiene con exactitud, en tres modos:

- **Temporizadores.** Para la prioridad de un router y el intervalo de anuncio: Skew_Time y el tiempo que espera un Backup antes de declarar caído al Active Router, con la aritmética a la vista, y cuándo toma el control un Backup con esa prioridad tras un fallo silencioso y tras un apagado limpio.
- **Elección.** Para entre dos y ocho routers, cada uno con un nombre, una prioridad, una dirección principal y si es propietario de la dirección virtual, con Preempt_Mode activado o desactivado: quién pasa a ser el Active Router y por qué, quién toma el control cuando falla en silencio o se apaga de forma limpia y cuánto tarda, qué pasa cuando vuelve, y los temporizadores de cada router.
- **Dirección MAC virtual.** Para un identificador de router virtual (VRID, Virtual Router Identifier) y una familia de direcciones: la dirección MAC del router virtual (Virtual Router MAC address) en tres notaciones.

Las reglas son las del [RFC 9568](https://www.rfc-editor.org/rfc/rfc9568.txt), VRRP versión 3 para IPv4 e IPv6 (abril de 2024), que deja obsoleto el RFC 5798, que a su vez había dejado obsoleto el RFC 3768 ([RFC 9568](https://www.rfc-editor.org/rfc/rfc9568.txt), Abstract). Una opción en la parte superior del formulario selecciona en su lugar VRRPv2, con las reglas del [RFC 3768](https://www.rfc-editor.org/rfc/rfc3768.txt) (abril de 2004, que quedó obsoleto con el RFC 5798 y ahora con el RFC 9568), para el equipamiento más antiguo que todavía lo ejecuta. Todo se calcula en tu navegador, y no se redondea nada.

## Nombres: Active o Master

El RFC 9568 renombró el router que reenvía: “The term for the VRRP Router assuming forwarding responsibility has been changed to ‘Active Router’ to be consistent with IETF inclusive terminology” (para ajustarse a la terminología inclusiva del IETF) ([RFC 9568](https://www.rfc-editor.org/rfc/rfc9568.txt), sección 1.1). Su tiempo de espera es Active_Down_Interval, que mide el Active_Down_Timer. El RFC 3768, y el RFC 5798 antes de que el RFC 9568 lo sustituyera, dicen Master, Master_Down_Interval y Master_Down_Timer, y la salida de muchos routers todavía lo hace. La página usa las palabras de cada versión: Active Router y Active_Down_Interval para VRRPv3, Master y Master_Down_Interval para VRRPv2.

## Temporizadores: las entradas

- **Versión de VRRP**: VRRPv3 (RFC 9568) o VRRPv2 (RFC 3768).
- **Prioridad**: un número entero de 1 a 255. “The priority value for the VRRP Router that owns the IPvX address associated with the Virtual Router MUST be 255 (decimal)”, y “VRRP Routers backing up a Virtual Router MUST use priority values between 1-254 (decimal). The default priority value for VRRP Routers backing up a Virtual Router is 100 (decimal)” ([RFC 9568](https://www.rfc-editor.org/rfc/rfc9568.txt), sección 5.2.4): el propietario de la dirección debe tener 255, y los routers que respaldan al router virtual, de 1 a 254, con 100 de forma predeterminada. Cuatro valores predefinidos rellenan el campo: 255 (el propietario), 254, 100 (el predeterminado) y 1.
- **Intervalo de anuncio**: en VRRPv3, centisegundos, o un tiempo con unidad: `100`, `1 s`, `250 ms`, `0.5 s`. El campo tiene 12 bits de centisegundos ([RFC 9568](https://www.rfc-editor.org/rfc/rfc9568.txt), sección 5.2.7), y la errata verificada 8301 hace explícito el rango configurable: “Configurable value in the range 1-4095 (centiseconds). Default is 100 centiseconds (1 second)” ([erratas del RFC 9568](https://www.rfc-editor.org/errata/rfc9568)). En VRRPv2, segundos enteros de 1 a 255: el campo Adver Int tiene 8 bits y, según el RFC, “indicates the time interval (in seconds) between ADVERTISEMENTS. The default is 1 second” (indica el intervalo, en segundos, entre ADVERTISEMENT; el predeterminado es 1 segundo) ([RFC 3768](https://www.rfc-editor.org/rfc/rfc3768.txt), secciones 5.1 y 5.3.7). En blanco significa el valor predeterminado de la versión. Escribe los decimales con punto.

## Temporizadores: qué calcula

En VRRPv3, las fórmulas del [RFC 9568](https://www.rfc-editor.org/rfc/rfc9568.txt), sección 6.1, en centisegundos:

```text
Skew_Time            = (((256 - Priority) * Active_Adver_Interval) / 256)
Active_Down_Interval = (3 * Active_Adver_Interval) + Skew_Time
```

Active_Adver_Interval es el intervalo que un Backup lee en los ADVERTISEMENT del Active Router; su “initial value is the same as Advertisement_Interval” (su valor inicial es el mismo que Advertisement_Interval), la configuración propia del Backup (sección 6.1), y un Backup pasa al valor anunciado cada vez que acepta un ADVERTISEMENT (sección 6.4.2). La página muestra las dos fórmulas con tus números: con prioridad 100 y 100 cs, (256 - 100) x 100 = 15.600, entre 256 da 60,9375 cs, y 3 x 100 + 60,9375 da 360,9375 cs, es decir, 3,609375 segundos.

En VRRPv2, las fórmulas del [RFC 3768](https://www.rfc-editor.org/rfc/rfc3768.txt), sección 6.1, en segundos:

```text
Skew_Time            = ( (256 - Priority) / 256 )
Master_Down_Interval = (3 * Advertisement_Interval) + Skew_time
```

Las dos versiones se diferencian en algo más que la unidad. En VRRPv3, el skew es una fracción del intervalo; en VRRPv2 es una fracción de un segundo, sea cual sea el intervalo. Con el valor predeterminado de 1 segundo dan las mismas cifras, pero a 3 segundos un Backup VRRPv2 con prioridad 100 espera 9,609375 s, mientras que un Backup VRRPv3 a 300 cs espera 1082,8125 cs (10,828125 s). Por eso las dos nunca se mezclan en un mismo cálculo: con VRRPv2 se rechaza un intervalo en centisegundos o en milisegundos, igual que una fracción de segundo.

**Valores exactos.** Cada temporizador es un número entero de 1/256 de la unidad de la versión, así que tiene un decimal exacto, y la página lo imprime entero: 0,78125 cs con prioridad 254, 99,609375 cs con prioridad 1. “El RFC no fija ningún redondeo” es un dato sobre el estándar, no un atajo de esta herramienta: cada implementación mantiene sus temporizadores con su propia resolución, así que la pantalla de un router puede mostrar una cifra redondeada.

**Cuándo toma el control un Backup con esta prioridad.**

- **Tras un fallo silencioso.** El Active Router se detiene, y el Active_Down_Timer de un Backup, “Timer that fires when a VRRP Advertisement has not been received for Active_Down_Interval” (el temporizador que vence cuando no se ha recibido ningún Advertisement de VRRP durante Active_Down_Interval) ([RFC 9568](https://www.rfc-editor.org/rfc/rfc9568.txt), sección 6.2), vence un Active_Down_Interval después del último ADVERTISEMENT que oyó. Contado desde el propio fallo, eso es entre un intervalo menos que Active_Down_Interval (el fallo ocurrió justo antes de que tocara el siguiente ADVERTISEMENT) y el Active_Down_Interval completo (ocurrió justo después de uno): de 2,609375 s a 3,609375 s con prioridad 100 y 1 s.
- **Tras un apagado limpio.** Un Active Router que se apaga envía “an ADVERTISEMENT with Priority = 0” (sección 6.4.3), y un Backup que lo recibe fija su temporizador en Skew_Time (“to Skew_Time”, sección 6.4.2): 0,609375 s con prioridad 100 y 1 s.

No se incluyen los retardos de propagación y de procesamiento, ni el tiempo que tardan los switches y los hosts en seguir a la dirección MAC virtual hasta su nuevo puerto.

**Prioridad 255.** Los temporizadores del propietario se calculan, pero en una red que funciona nunca los espera: al arrancar, un router con prioridad 255 envía un ADVERTISEMENT y hace al instante la transición “to the {Active} state” (sección 6.4.1), y se impone (preempt) a cualquier prioridad menor “independent of the setting of this flag” (independientemente de cómo esté ese indicador) (sección 6.1). Solo esperaría como Backup si un segundo router también reclamara la 255, y “only a single VRRP Router on the link SHOULD be configured with priority 255” (solo un router VRRP del enlace debería configurarse con prioridad 255) (sección 8.3.2).

**Intervalos inferiores al segundo.** Por debajo de 100 cs, la página añade la advertencia del propio RFC 9568: un retardo de cola mayor que el intervalo puede hacer que un Backup se promueva a sí mismo y vuelva atrás, y “this process can repeat many times per second, causing a significant disruption of traffic” (este proceso puede repetirse muchas veces por segundo y causar una interrupción importante del tráfico) (sección 2.5).

## Elección: las entradas

- **Versión de VRRP** e **Intervalo de anuncio**, como arriba; el intervalo es el mismo en todos los routers.
- **Preempt_Mode**: activado (el valor predeterminado) o desactivado, igual en todos los routers. “Controls whether a (starting or restarting) higher-priority Backup Router preempts a lower-priority Active Router. Values are True to allow preemption and False to prohibit preemption. Default is True” (controla si un Backup de mayor prioridad que arranca o rearranca se impone a un Active Router de menor prioridad; True lo permite, False lo impide, y el valor predeterminado es True) ([RFC 9568](https://www.rfc-editor.org/rfc/rfc9568.txt), sección 6.1).
- **De dos a ocho routers**, cada uno con:
  - un **nombre**: hasta 32 letras, dígitos, puntos, guiones o guiones bajos, sin espacios; un nombre en blanco se lee R1, R2, etc.;
  - una **prioridad**, de 1 a 254, o 255 para el propietario;
  - su **dirección principal**: en IPv4, “an IPv4 address selected from the set of real interface addresses” (una dirección IPv4 elegida entre las direcciones reales de las interfaces), y “In IPv6, the link-local address of the interface over which the packet is transmitted is used” (en IPv6 se usa la dirección link-local de la interfaz por la que se transmite el paquete) ([RFC 9568](https://www.rfc-editor.org/rfc/rfc9568.txt), sección 1.7), así que una dirección principal IPv6 tiene que estar en fe80::/10 ([RFC 4291](https://www.rfc-editor.org/rfc/rfc4291.txt), sección 2.5.6);
  - **Propietario de la dirección virtual**: marcado en el router cuya dirección real de interfaz es la dirección virtual. Al marcarlo, la prioridad pasa a 255.

## Elección: las reglas que aplica

La página recorre la máquina de estados del RFC 9568 (sección 6.4) a lo largo de cuatro momentos, con todos los routers arrancando a la vez y cada ADVERTISEMENT llegando al instante:

1. **Al inicio.** El propietario envía un ADVERTISEMENT y hace al instante la transición “to the {Active} state”; todos los demás routers arrancan como Backup con su Active_Down_Timer fijado en Active_Down_Interval (sección 6.4.1). Sin propietario, la prioridad más alta tiene el Active_Down_Interval más corto, así que su temporizador vence primero y pasa a ser el Active Router; los demás aceptan su ADVERTISEMENT, cuya prioridad es mayor que la suya, y siguen como Backup (sección 6.4.2).
2. **Un fallo silencioso del Active Router.** El mejor Backup restante toma el control cuando vence su propio temporizador, con los tiempos del modo Temporizadores.
3. **Un apagado limpio del Active Router.** Su ADVERTISEMENT con prioridad 0 fija el temporizador de cada Backup en su propio Skew_Time, y el mejor Backup restante, con el skew más corto, es el primero en tomar el control.
4. **Su regreso.** El propietario vuelve a ser Active al instante, diga lo que diga Preempt_Mode. Cualquier otro router arranca como Backup: un Backup reinicia su temporizador al recibir un ADVERTISEMENT “If Preempt_Mode is False, or if the Priority in the ADVERTISEMENT is greater than or equal to the local Priority” (si Preempt_Mode es False, o si la prioridad del ADVERTISEMENT es mayor o igual que la local), y en caso contrario lo descarta (sección 6.4.2). Así que, con Preempt_Mode activado y una prioridad mayor, ignora los ADVERTISEMENT del Active Router actual, su propio temporizador vence un Active_Down_Interval después de arrancar y toma el control; el Active Router actual, al recibir una prioridad mayor, vuelve a Backup (sección 6.4.3). Con Preempt_Mode desactivado, o con la misma prioridad que el Active Router actual, sigue como Backup.

**Empates.** Dos Backups con la misma prioridad máxima agotan su tiempo a la vez y los dos pasan a Active. Un Active Router vuelve a Backup cuando “the Priority in the ADVERTISEMENT is equal to the local Priority and the primary IPvX address of the sender is greater than the local primary IPvX address (based on an unsigned integer comparison of the IPvX addresses in network byte order)” (la prioridad del ADVERTISEMENT es igual a la local y la dirección IPvX principal del remitente es mayor que la local, comparadas como enteros sin signo en el orden de bytes de la red) (sección 6.4.3), así que la dirección principal más alta sigue como Active. La comparación es numérica: 192.0.2.10 gana a 192.0.2.9, y fe80::1:0 gana a fe80::ff. La dirección solo deshace un empate entre Active Routers, y por eso un router que vuelve con la misma prioridad que el Active Router actual sigue como Backup aunque su dirección sea más alta. Cuando dos routers comparten prioridad, la página lo advierte, porque el RFC 9568 pide que “all Virtual Routers SHOULD be configured with different priorities and with sufficient differences in the priorities” (todos los routers virtuales deberían configurarse con prioridades distintas y con diferencias suficientes entre ellas) (sección 8.3.2).

El resultado es el veredicto (quién es Active y por qué), los cuatro momentos en orden con la regla y el tiempo de cada uno, y una tabla de los routers en orden de elección con el Skew_Time y el Active_Down_Interval de cada uno.

## Dirección MAC virtual

“IPv4 case: 00-00-5E-00-01-{VRID} (in hex, in network byte order)” y “IPv6 case: 00-00-5E-00-02-{VRID} (in hex, in network byte order)”: “The first three octets are derived from the IANA's Organizationally Unique Identifier (OUI)” (los tres primeros octetos proceden del identificador único de organización de la IANA), los dos siguientes son el bloque asignado a VRRP para la familia, y el último es el VRID ([RFC 9568](https://www.rfc-editor.org/rfc/rfc9568.txt), sección 7.3). El VRID es un “Configurable value in the range 1-255 (decimal). There is no default” (sin valor predeterminado) (sección 6.1). La página escribe la dirección de tres formas: con guiones, como la escribe el RFC (00-00-5E-00-01-0A); con dos puntos (00:00:5e:00:01:0a); y en tres grupos de cuatro separados por puntos (0000.5e00.010a). También da el último octeto en hexadecimal y adónde se envían los ADVERTISEMENT: a 224.0.0.18 en IPv4 y a ff02::12 en IPv6, protocolo IP 112 (secciones 5.1.1 y 5.1.2). VRRPv2 usa el mismo bloque IPv4 ([RFC 3768](https://www.rfc-editor.org/rfc/rfc3768.txt), sección 7.3) y no tiene ninguno para IPv6.

El Active Router responde con esta dirección MAC a las solicitudes ARP y a las Neighbor Solicitations de la dirección virtual: “The Active Router MUST NOT respond with its physical MAC address” (el Active Router no debe responder con su dirección MAC física), lo que “allows the host to always use the same MAC address, regardless of the current Active Router” (permite al host usar siempre la misma dirección MAC, sea cual sea el Active Router del momento) (secciones 8.1.2 y 8.2.2).

## Qué rechaza, y por qué

- **La prioridad 0.** Nunca se configura: “The priority value zero (0) has special meaning, indicating that the current Active Router has stopped participating in VRRP. This is used to trigger Backup Routers to quickly transition to the Active Router without having to wait for the current Active_Down_Interval” (el valor cero tiene un significado especial: indica que el Active Router actual ha dejado de participar en VRRP, y sirve para que los Backups pasen rápidamente a Active Router sin esperar al Active_Down_Interval en curso) ([RFC 9568](https://www.rfc-editor.org/rfc/rfc9568.txt), sección 5.2.4). La página lo indica y pide un valor de 1 a 254, o 255 para el propietario.
- **Una prioridad mayor que 255**, que el campo de 8 bits no puede contener, y cualquier cosa que no sea un número entero.
- **Un propietario cuya prioridad no es 255**, y **la prioridad 255 en un router que no está marcado como propietario** (la sección 6.1 la reserva).
- **Dos propietarios.** Solo SHOULD (debería) existir uno (sección 8.3.2). Tal como se publicó, la sección 7.1 hace que un router descarte cualquier ADVERTISEMENT cuando él mismo es el propietario, así que dos propietarios siguen los dos como Active; la errata verificada 8298 cambia esa comprobación para que gane la dirección principal más alta. El resultado depende del texto que siga cada implementación, así que la página no adivina.
- **Un VRID 0 o mayor que 255**, y un VRID en hexadecimal: el VRID se introduce en decimal.
- **Un intervalo de 0**, que la errata verificada 8301 descarta porque un intervalo cero hace que todos los Backups agoten su tiempo a la vez; **más de 4095 cs** (40,95 s) en VRRPv3 o **más de 255 s** en VRRPv2; y **una fracción de la unidad de la versión** (255 ms son 25,5 cs).
- **La aritmética de VRRPv2 y VRRPv3 mezclada**: un intervalo en centisegundos o milisegundos con VRRPv2, e IPv6 con VRRPv2, que “is intended for use with IPv4 routers only” (está pensado solo para routers IPv4) ([RFC 3768](https://www.rfc-editor.org/rfc/rfc3768.txt), sección 1.2).
- **Routers que mezclan IPv4 e IPv6** (un router virtual es de una sola familia, Abstract del RFC 9568), **una dirección principal IPv6 que no es link-local**, **dos routers con la misma dirección principal** (se comparan por valor, así que fe80::1 y fe80:0:0:0:0:0:0:1 son la misma), dos routers con el mismo nombre, menos de dos o más de ocho routers, y una dirección con longitud de prefijo o con zona.

## Ejemplos resueltos

Los Ejemplos son el laboratorio de VRRP del capítulo 4.2 del curso abierto [LAN Switch Operations and Maintenance](/materials/lan-switch-operations-and-maintenance): VRID 10 en la VLAN 10, la puerta de enlace virtual 10.1.10.1, SW-CORE-01 con prioridad 110 y 10.1.10.2, y SW-CORE-02 con prioridad 100 y 10.1.10.3, preempt activado y un intervalo de un segundo.

- **Temporizadores**, prioridad 100 a 100 cs: Skew_Time 60,9375 cs (0,609375 s), Active_Down_Interval 360,9375 cs (3,609375 s). Un enlace cortado mueve la puerta de enlace entre 2,609375 s y 3,609375 s después del fallo, los “unos 3,6 s” del laboratorio; un apagado ordenado la mueve 0,609375 s después del ADVERTISEMENT con prioridad 0, los “unos 0,6 s” del laboratorio.
- **Elección**: SW-CORE-01 tiene la prioridad más alta y pasa a ser el Active Router 357,03125 cs (3,5703125 s) después de que arranquen los dos; si falla, SW-CORE-02 toma el control como arriba; cuando SW-CORE-01 vuelve con preempt activado, recupera el rol 3,5703125 s después de arrancar. Con preempt desactivado sigue como Backup, que es el consejo con el que cierra el laboratorio.
- **Dirección MAC virtual**, VRID 10, IPv4: 00-00-5E-00-01-0A, la dirección que aprenden los hosts del laboratorio para 10.1.10.1.
- **La tabla del artículo**, a 100 cs: la prioridad 254 espera 300,78125 cs, la 200 espera 321,875 cs y la 1 espera 399,609375 cs; a 1 cs, un Backup con prioridad 254 espera 3,0078125 cs, unos 30 milisegundos.
- **Los límites**: a 4095 cs, un Backup con prioridad 1 espera 16.364,00390625 cs (163,6400390625 s); un Backup VRRPv2 con prioridad 1 y 255 s espera 765,99609375 s.
- **Un empate**: dos routers con prioridad 100 y las direcciones 192.0.2.2 y 192.0.2.3 pasan los dos a Active al cabo de 3,609375 s, y 192.0.2.3 sigue como Active; si falla, 192.0.2.2 toma el control, y cuando 192.0.2.3 vuelve sigue como Backup, con preempt o sin él.

## Qué no hace

No habla con ningún router: las prioridades, las direcciones y el intervalo son los tuyos. Supone que todos los routers tienen el mismo intervalo y el mismo Preempt_Mode, que arrancan a la vez y que los ADVERTISEMENT llegan sin retardo. Quedan fuera el tracking (bajar una prioridad cuando falla un uplink), los retardos de preempt, Accept_Mode, el ARP gratuito y lo rápido que los switches vuelven a aprender la dirección MAC, la interoperabilidad entre VRRPv2 y VRRPv3 (RFC 9568, sección 8.4) y HSRP. No se incluyen los valores predeterminados ni los comandos de los fabricantes: para eso, lee la documentación del fabricante y las diapositivas de fabricantes del curso. Para recorrer paso a paso una secuencia de fallos y regresos, usa el laboratorio de elección del artículo [Redundancia del primer salto](/learn/first-hop-redundancy-vrrp-and-hsrp).

## Compartir resultados

Debajo del veredicto, **Compartir resultados** genera un enlace a esta página, solo cuando lo presionas, que lleva después del `#` el modo, la versión y los campos del modo que se muestra, tal como se escribieron: siempre `mode` (`timers`, `election` o `mac`) y `version` (`3` o `2`); en el modo Temporizadores, `priority`, e `interval` si se escribió; en el modo Elección, `routers`, un router por línea escrito como `<name> <priority> <address>`, con ` owner` detrás del propietario y `*` para un campo en blanco, `preempt` (`1` o `0`) e `interval` si se escribió; en el modo Dirección MAC virtual, `vrid` y `family` (`ipv4` o `ipv6`). Los campos de los otros modos no van en el enlace. En el modo Elección, la ventana emergente añade una advertencia: los nombres de los routers y las direcciones principales describen una red privada, así que léelos antes de enviar el enlace.

Según el [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (sección 3.5, consultado el 2026-11-02), el fragmento queda “separated from the rest of the URI prior to a dereference” (separado del resto del URI antes de resolverlo), así que estos valores no se envían al servidor cuando se abre el enlace; se quedan en la barra de direcciones y en el historial de quien lo abra, y cualquiera que tenga el enlace puede leerlos.

- **Longitud.** Un enlace lleva como máximo 16.384 caracteres, el límite que el sitio aplica a todo valor después del `#`; estos campos son mucho más cortos.
- **Al abrir un enlace.** El modo, la versión y los campos del modo se establecen como si los escribieras (un intervalo que el enlace no lleva queda en blanco, lo que significa el valor predeterminado; si falta `preempt`, significa activado), los otros modos conservan sus valores y la página calcula. Se ignora un enlace con un modo, una versión, un valor de `preempt` o una familia desconocidos, un campo de otro modo, un campo obligatorio que falta, un valor en dos líneas (salvo la lista de routers) o una lista de routers que no tenga de dos a ocho líneas de tres o cuatro palabras. Se acepte o no, los valores salen después de la propia dirección de la página al instante, sin ninguna solicitud, así que al recargar, con un marcador o con el propio botón Compartir de la página no se lleva nada que no hayas decidido compartir.

## Procedencia

El motor es aritmética fija y una lectura fija de la máquina de estados, sin reloj, sin red y sin aleatoriedad. Incluye 133 vectores de referencia (conjunto `vrrp-timer-calculator-golden-2026-11-02`): 26 filas de temporizadores (las prioridades 1, 100, 200, 254 y 255 con el intervalo predeterminado, a 1 cs y a 4095 cs, y VRRPv2 a 1 s y a 255 s), 14 elecciones, 12 direcciones MAC virtuales, los tres Ejemplos, las formas de escribir el intervalo y los valores predeterminados, las frases que llevan las reglas y 51 rechazos. Cada cifra esperada y cada resultado de elección se obtuvo con una implementación independiente, no ejecutando este motor: los temporizadores, con las fórmulas del RFC en las fracciones exactas de Python, y las elecciones, con una simulación de eventos discretos de la máquina de estados del RFC 9568 (temporizadores, ADVERTISEMENT, prioridad 0, preempt y el desempate por dirección) a lo largo de los cuatro momentos, con la propia comparación de direcciones de Python. Las erratas se leyeron el mismo día: el RFC 9568 tiene seis erratas verificadas, de las que la 8301 (el rango de 1 a 4095) y la 8298 (dos propietarios) condicionan esta herramienta y las demás (7947 y 7949, sobre el ARP gratuito, y 8299 y 8300, sobre las comprobaciones en recepción) no cambian ningún temporizador; el RFC 3768 no tiene ninguna.

El mismo motor responde a `/api/v1/vrrp-timer-calculator` en la API HTTP del sitio; el contrato está en la [página de la API](/api), que también indica si este sitio sirve la API.

- **Solicitud.** Un objeto JSON. Temporizadores: `{"mode": "timers", "version": 3, "priority": 100, "interval": "100"}`; `version` (3 de forma predeterminada) e `interval` (el predeterminado si falta) son opcionales, y un intervalo sin unidad está en la unidad de la versión. Elección: `{"mode": "election", "version": 3, "interval": "100", "preempt": true, "routers": [{"name": "SW-CORE-01", "priority": 110, "address": "10.1.10.2"}, {"name": "SW-CORE-02", "priority": 100, "address": "10.1.10.3"}]}`; `preempt` (true de forma predeterminada), `name` y `owner` (false de forma predeterminada) son opcionales, y se puede omitir la `priority` de un propietario. Dirección MAC virtual: `{"mode": "mac", "vrid": 10, "family": "ipv4"}`.
- **Respuesta, temporizadores.** `mode`, `version`, `unit` (`cs` o `s`), `names` (`rfc`, `interval`, `down`, `downTimer`, `activeRole`, `activeState`), `priority`, `owner`, `interval`, `intervalSeconds`, `intervalDefault`, `skewTime`, `skewTimeSeconds`, `downInterval`, `downIntervalSeconds`, `skewNumerator`, `arithmetic` (`skew`, `down`: las fórmulas con los valores, como `Skew_Time = ((256 - 100) * 100) / 256 = 15600 / 256 = 60.9375 cs`), `failover` (`silentFrom`, `silentTo`, `shutdown` y sus `...Seconds`; null para la prioridad 255), `warnings` y `notes`. Cada tiempo es un texto decimal exacto, con el punto como separador decimal.
- **Respuesta, elección.** `mode`, `version`, `unit`, `names`, `family`, `preempt`, `preemptDefault`, `interval`, `intervalSeconds`, `intervalDefault`, `routers` (cada uno: `index`, `name`, `priority`, `address`, `owner`, `rank`, `startState`, `skewTime`, `skewTimeSeconds`, `downInterval`, `downIntervalSeconds`), `ranking`, `active`, `activeReason` (`owner`, `priority` o `address-tie`), `steps` (cuatro: `event` `start`, `failure`, `shutdown` o `return`; `outcome`; `active`, `activeName`, `subject`, `tied`, `after`, `afterSeconds`, `from`, `fromSeconds`, `text`), `verdictText`, `warnings` y `notes`.
- **Respuesta, dirección MAC virtual.** `mode`, `version`, `family`, `vrid`, `vridHex`, `block`, `hyphen`, `colon`, `dotted`, `multicastGroup`, `ipProtocol` y `notes`.
- **Errores.** HTTP 400, `invalid_input`, con el mensaje del motor, por ejemplo `Priority 0 is never configured: RFC 9568 reserves it for the Active Router to indicate it is relinquishing responsibility for the Virtual Router. ...`.
