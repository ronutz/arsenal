## Qué hace

Pega un archivo de configuración automática de proxy (PAC, Proxy Auto-Config) y la herramienta lo lee sin ejecutarlo nunca: las directivas de proxy que puede devolver, las funciones auxiliares de PAC que usa, un conjunto de comprobaciones de estructura y de corrección, y si parece un archivo de direccionamiento (steering) de Netskope Cloud Explicit Proxy. Un archivo PAC es la pequeña función de JavaScript, `FindProxyForURL(url, host)`, a la que un navegador o un cliente de reenvío llama en cada solicitud para decidir si ir directo o a través de un proxy. La herramienta explica esa lógica de decisión. Se ejecuta por completo en tu navegador y se basa en la referencia de PAC de MDN y en la documentación de Explicit Proxy de Netskope.

## Nunca ejecuta el archivo

Esta es la propiedad de seguridad importante. La herramienta no evalúa el JavaScript del PAC. Lee el texto de forma léxica: recorre el código fuente carácter a carácter para equilibrar llaves y paréntesis (sin tener en cuenta lo que haya dentro de cadenas y comentarios), recoge los literales de cadena para encontrar las directivas de proxy y cuenta los nombres de funciones auxiliares a los que se llama. Nunca llama a `eval`, nunca ejecuta `FindProxyForURL`, nunca abre un socket y nunca descarga nada.

## Las directivas de proxy

Cada cadena que devuelve un archivo PAC es una o varias directivas separadas por punto y coma, que se prueban de izquierda a derecha como failover. La herramienta extrae cada cadena devuelta y explica sus partes: `DIRECT` (conexión directa al destino, sin proxy), `PROXY host:port` (usar ese proxy HTTP), `SOCKS host:port` (usar ese servidor SOCKS) y las palabras clave más recientes `HTTP`, `HTTPS`, `SOCKS4` y `SOCKS5`, para un tipo concreto de proxy. Una cadena como `PROXY p1:8080; PROXY p2:8080; DIRECT` se marca como cadena de failover, y se señala cualquier parte que no sea una de las palabras clave válidas (una errata habitual).

## Las funciones auxiliares

Los archivos PAC deciden con un conjunto fijo de funciones auxiliares, y la herramienta explica cada una que encuentra y, sobre todo, marca las tres que obligan a hacer una consulta DNS: `isInNet`, `isResolvable` y `dnsResolve`. Estas consultan el servidor DNS y pueden bloquear, así que MDN recomienda poner primero las comprobaciones de cadenas, más baratas, como `isPlainHostName` y `dnsDomainIs`, y recurrir a las funciones que consultan el DNS solo cuando nada más ha decidido. La herramienta también señala los puntos delicados que destaca la documentación: `shExpMatch` usa comodines de shell (`*` y `?`), no expresiones regulares; `myIpAddress` puede no ser fiable en equipos con varias interfaces (multihomed) y puede recurrir a una dirección de loopback; y los navegadores modernos basados en Chromium quitan la ruta y la consulta de las URL `https://` antes de llamar al PAC, así que una coincidencia con la ruta de una URL HTTPS puede no funcionar.

## Reconocimiento de Netskope

Cuando el archivo dirige el tráfico a un host de proxy explícito de `goskope.com` (normalmente `eproxy-<tenant>.goskope.com` en el puerto 8081), la herramienta lo reconoce como un archivo de direccionamiento de Netskope Cloud Explicit Proxy y explica el patrón: los nombres de host no calificados y los hosts del proveedor de identidad se devuelven como `DIRECT` para que no pasen por el proxy, Netskope usa cookies sustitutas (cookie surrogates) para la identidad del usuario, el marcador del tenant hay que sustituirlo por tu tenant real, y el cliente tiene que confiar en la CA raíz de Netskope para que funcione la inspección TLS.

## Alcance y fundamento

Analiza y explica; nunca evalúa el archivo, abre un socket ni descarga nada, y la misma entrada siempre produce la misma salida. Es un lector estructural y léxico, no un analizador completo de JavaScript ni un banco de pruebas de PAC: no te dirá a qué proxy se resuelve una URL concreta (para eso habría que ejecutar la función). Cada dato sale de la referencia Proxy Auto-Configuration de MDN, del artículo de Wikipedia sobre la configuración automática de proxy (para las extensiones IPv6 de Microsoft de las funciones auxiliares) y de la documentación de Cloud Explicit Proxy de Netskope. Nada de lo que pegas sale de la página.

## Compartir resultados

Al principio de la lectura, **Compartir resultados** genera un enlace a esta página, solo cuando lo presionas, que lleva después del `#` el archivo tal como se pegó, una vez que la página ha leído un archivo (la referencia que se muestra con el cuadro vacío no es un resultado). Su ventana emergente dice primero qué lleva el enlace y después ofrece Copiar enlace y, si el navegador lo tiene, el menú Compartir del sistema; la dirección de la página no cambia. Un archivo PAC nombra hosts internos, y uno de Netskope nombra tu tenant: la página [Cloud Explicit Proxy](https://docs.netskope.com/en/explicit-proxy/) de Netskope (consultada el 2026-11-01) hace que el archivo devuelva `PROXY eproxy-<Tenant Name>:8081`. La ventana emergente te pide que los revises. La página lee cada directiva y cada llamada a una función auxiliar, así que no se recorta nada. Antes de ofrecer un enlace, se busca en el archivo una credencial definida por un estándar: una clave privada PEM, una línea `Authorization` o `Proxy-Authorization` con cualquier esquema ([RFC 9110](https://www.rfc-editor.org/rfc/rfc9110), secciones 11.6.2 y 11.7.2: el valor “consists of credentials”, consiste en credenciales), una línea `Cookie` o `Set-Cookie` con valor ([RFC 6265](https://www.rfc-editor.org/rfc/rfc6265), sección 8.4: los servidores “commonly store a nonce (or ‘session identifier’) in a cookie”, suelen guardar en una cookie un nonce o identificador de sesión), un JWT ([RFC 7519](https://www.rfc-editor.org/rfc/rfc7519), sección 1), una contraseña en una URL ([RFC 3986](https://www.rfc-editor.org/rfc/rfc3986), sección 3.2.1), un ID de clave de acceso de AWS o un valor `ENC` de FortiOS; todos consultados el 2026-11-01. Si aparece uno, no hay enlace: la ventana emergente indica su línea, y tú lo sustituyes por un marcador de posición y vuelves a presionar. Un valor cuyo nombre solo parece el de un secreto (un miembro JSON `token`, un `token=` en una cadena de consulta) no bloquea el enlace; la ventana emergente indica el primero para que puedas revisarlo.

Según el [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (sección 3.5, consultado el 2026-11-01), el fragmento queda “separated from the rest of the URI prior to a dereference” (separado del resto del URI antes de resolverlo), así que lo que va después del `#` no se envía al servidor cuando se abre el enlace; se queda en la barra de direcciones y en el historial de quien lo abra, y cualquiera que tenga el enlace puede leerlo.

- **Longitud.** Como máximo 16.384 caracteres en total, el límite que el sitio aplica a todo valor después del `#`; si lo compartido es más largo, no hay enlace, y la ventana emergente indica su longitud.
- **Al abrir un enlace.** El archivo rellena el cuadro como lo haría un pegado, y la página lo lee (nunca lo ejecuta). Después, los valores salen de la dirección de la página al instante, sin ninguna solicitud, así que al recargar, o con el propio botón Compartir de la página, no se lleva nada.
