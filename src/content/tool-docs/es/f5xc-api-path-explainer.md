## Qué hace

Esta herramienta explica una especificación OpenAPI o Swagger, justo el artefacto con el que trabaja F5 Distributed Cloud (XC) API Protection. XC importa una especificación OpenAPI (versión 2.0 o 3.0.x) para construir su inventario de API y aplicar un modelo de seguridad positivo, y XC API Discovery genera un JSON de Swagger descargable que puedes editar y volver a importar. Pega esa especificación y la herramienta enumera cada ruta y cada operación con su método, sus parámetros, el cuerpo de la solicitud, las respuestas y si exige autenticación. Se ejecuta por completo en tu navegador.

## El inventario que genera

Para cada ruta, la herramienta recorre todas las operaciones (GET, POST, PUT, PATCH, DELETE y las demás) y muestra los mismos datos que XC usa para definir el comportamiento válido: los parámetros (nombre, ubicación y si son obligatorios), los tipos de contenido del cuerpo de la solicitud, los códigos de respuesta y los esquemas de seguridad que se aplican. Resuelve los parámetros $ref locales dentro del documento, así que un parámetro definido una vez y referenciado en varias operaciones se muestra completo en cada uso. El resumen de la parte superior cuenta las rutas, las operaciones y cuántas no tienen autenticación, son de nivel de objeto o están obsoletas.

## La autenticación, bien resuelta

Que una operación exija autenticación no siempre se indica en la propia operación. OpenAPI permite definir un requisito de seguridad global y sobrescribirlo en cada operación, y una operación con una lista de seguridad vacía es pública de forma explícita, aunque la API tenga un requisito global. La herramienta lo resuelve tal como lo define la especificación: una operación usa su propia seguridad si la tiene y, si no, la global; una lista vacía significa que no hay autenticación. Por eso una operación puede aparecer sin autenticación incluso en una API que en general exige un token.

## Las alertas y su relación con OWASP

La herramienta señala dos cosas que importan para la seguridad de una API. Una operación sin seguridad efectiva es un riesgo de Broken Authentication (autenticación rota): se puede alcanzar sin credenciales. Un endpoint con un parámetro de ruta, como /orders/{id}, es un punto de acceso a nivel de objeto y la superficie clásica de Broken Object Level Authorization (autorización rota a nivel de objeto), el primer puesto del OWASP API Security Top 10: la API debe comprobar que quien llama tiene permiso para tocar ese objeto concreto, no solo que inició sesión. Son avisos para que verifiques tu diseño de autorización, no la prueba de una vulnerabilidad, pero son justo los endpoints que conviene revisar primero.

## Compartir resultados

Debajo del resumen, **Compartir resultados** genera un enlace a esta página, solo cuando lo presionas, que lleva después del `#` el archivo OpenAPI tal como se pegó, una vez que la página enumera al menos una operación. Su ventana emergente dice primero qué lleva el enlace y después ofrece Copiar enlace y, si el navegador lo tiene, el menú Compartir del sistema; la dirección de la página no cambia. Un archivo nombra las rutas y los servidores de tu API, y sus ejemplos pueden contener valores reales: la ventana emergente te pide que los revises. La página lee cada ruta, cada operación y cada parámetro, así que no se recorta nada del enlace. Antes de ofrecer un enlace, se busca en el archivo una credencial definida por un estándar: una clave privada PEM, una línea `Authorization` o `Proxy-Authorization` con cualquier esquema ([RFC 9110](https://www.rfc-editor.org/rfc/rfc9110), secciones 11.6.2 y 11.7.2: el valor “consists of credentials”, consiste en credenciales), una línea `Cookie` o `Set-Cookie` con valor ([RFC 6265](https://www.rfc-editor.org/rfc/rfc6265), sección 8.4: los servidores “commonly store a nonce (or ‘session identifier’) in a cookie”, suelen guardar en una cookie un nonce o identificador de sesión), un JWT ([RFC 7519](https://www.rfc-editor.org/rfc/rfc7519), sección 1), una contraseña en una URL ([RFC 3986](https://www.rfc-editor.org/rfc/rfc3986), sección 3.2.1), un ID de clave de acceso de AWS o un valor `ENC` de FortiOS, y dos cosas que define el propio esquema de F5 Distributed Cloud: un secreto SecretType, es decir, una URL `clear_secret_info` o una ubicación `blindfold_secret_info` (la [referencia de la API de XC](https://docs.cloud.f5.com/docs-v2/api/views-http-loadbalancer): “SecretType is used in an object to indicate a sensitive/confidential field”, se usa en un objeto para indicar un campo sensible o confidencial), y un comparador del encabezado `Authorization` con un valor literal; todos consultados el 2026-11-01. Si aparece uno, no hay enlace: la ventana emergente indica su línea, y tú lo sustituyes por un marcador de posición y vuelves a presionar. Un valor cuyo nombre solo parece el de un secreto (un miembro JSON `token`, un `token=` en una cadena de consulta, un comparador de `X-Api-Key` o de cookie) no bloquea el enlace; la ventana emergente indica el primero para que puedas revisarlo.

Según el [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (sección 3.5, consultado el 2026-11-01), el fragmento queda “separated from the rest of the URI prior to a dereference” (separado del resto del URI antes de resolverlo), así que lo que va después del `#` no se envía al servidor cuando se abre el enlace; se queda en la barra de direcciones y en el historial de quien lo abra, y cualquiera que tenga el enlace puede leerlo.

- **Longitud.** Como máximo 16.384 caracteres en total, el límite que el sitio aplica a todo valor después del `#`; si lo compartido es más largo, no hay enlace, y la ventana emergente indica su longitud.
- **Al abrir un enlace.** El archivo rellena el cuadro como lo haría un pegado y la página lo lee. Después, los valores salen de la dirección de la página al instante, sin ninguna solicitud, así que al recargar, o con el propio botón Compartir de la página, no se lleva nada.
