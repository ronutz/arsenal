## Qué hace

Esta herramienta responde una pregunta precisa de F5 Distributed Cloud (XC): con varios balanceadores de carga HTTP y sus listas de dominios, ¿cuál atiende un nombre de host concreto? Pega los balanceadores de carga como un array JSON y un nombre de host de prueba, y el comprobador indica qué balanceador y qué entrada de dominio ganan, muestra por qué y señala los riesgos de configuración que hacen fallar la coincidencia de dominios. Se ejecuta por completo en tu navegador.

## Cómo elige XC un balanceador de carga

Cuando llega una solicitud, XC ya ha reducido las opciones a los balanceadores de carga que comparten la dirección IP y el puerto de destino (la advertise policy). Entre ellos, elige la coincidencia de dominio más específica. Un FQDN exacto (app.example.com escrito tal cual) gana a un comodín como *.example.com. El nombre de host con el que compara sale del valor SNI cuando el cliente usa HTTPS, o del encabezado Host cuando usa HTTP sin cifrar. Si nada coincide y hay un balanceador de carga marcado como Default para esa advertise policy, el Default recoge la solicitud; si no hay Default, nadie recoge ese nombre de host.

## Los comodines y el apex

Un dominio comodín es una coincidencia por sufijo: *.example.com cubre foo.example.com, pero no cubre el dominio apex example.com, y un certificado TLS comodín solo cubre una etiqueta. Por eso, para atender tanto www.example.com (o cualquier subdominio) como example.com a secas, hay que añadir el apex como dominio propio. La herramienta deja explícita la diferencia entre comodín y apex en cada resultado.

## Los riesgos que señala

La coincidencia de dominios falla de unas pocas formas reconocibles, y la herramienta avisa de cada una. Configurar a la vez un comodín (*.example.com) y su apex (example.com) en balanceadores de carga distintos que usan certificados automáticos es algo que F5 desaconseja de forma expresa. Dos balanceadores de carga que reclaman el mismo dominio exacto, o dos marcados como Default en la misma advertise policy (solo se permite uno), son conflictos. Un nombre de host que coincide con dos entradas con la misma especificidad es ambiguo. Y un nombre de host de varias etiquetas que coincide con un comodín se enrutará, pero puede fallar en la validación del certificado, porque el certificado comodín solo cubre una etiqueta.

## Compartir resultados

Debajo de la resolución, **Compartir resultados** genera un enlace a esta página, solo cuando lo presionas, que lleva después del `#` la lista de balanceadores de carga tal como se pegó y el nombre de host. Su ventana emergente dice primero qué lleva el enlace y después ofrece Copiar enlace y, si el navegador lo tiene, el menú Compartir del sistema; la dirección de la página no cambia. Los nombres de los balanceadores de carga y los dominios pueden ser hosts internos de una organización: la ventana emergente te pide que los revises. La resolución lee cada nombre y cada dominio, así que no se recorta nada. Antes de ofrecer un enlace, se busca en cada campo una credencial definida por un estándar: una clave privada PEM, una línea `Authorization` o `Proxy-Authorization` con cualquier esquema ([RFC 9110](https://www.rfc-editor.org/rfc/rfc9110), secciones 11.6.2 y 11.7.2: el valor “consists of credentials”, consiste en credenciales), una línea `Cookie` o `Set-Cookie` con valor ([RFC 6265](https://www.rfc-editor.org/rfc/rfc6265), sección 8.4: los servidores “commonly store a nonce (or ‘session identifier’) in a cookie”, suelen guardar en una cookie un nonce o identificador de sesión), un JWT ([RFC 7519](https://www.rfc-editor.org/rfc/rfc7519), sección 1), una contraseña en una URL ([RFC 3986](https://www.rfc-editor.org/rfc/rfc3986), sección 3.2.1), un ID de clave de acceso de AWS o un valor `ENC` de FortiOS, y dos cosas que define el propio esquema de F5 Distributed Cloud: un secreto SecretType, es decir, una URL `clear_secret_info` o una ubicación `blindfold_secret_info` (la [referencia de la API de XC](https://docs.cloud.f5.com/docs-v2/api/views-http-loadbalancer): “SecretType is used in an object to indicate a sensitive/confidential field”, se usa en un objeto para indicar un campo sensible o confidencial), y un comparador del encabezado `Authorization` con un valor literal; todos consultados el 2026-11-01. Si aparece uno, no hay enlace: la ventana emergente indica su línea, y tú lo sustituyes por un marcador de posición y vuelves a presionar. Un valor cuyo nombre solo parece el de un secreto (un miembro JSON `token`, un `token=` en una cadena de consulta, un comparador de `X-Api-Key` o de cookie) no bloquea el enlace; la ventana emergente indica el primero para que puedas revisarlo.

Según el [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (sección 3.5, consultado el 2026-11-01), el fragmento queda “separated from the rest of the URI prior to a dereference” (separado del resto del URI antes de resolverlo), así que lo que va después del `#` no se envía al servidor cuando se abre el enlace; se queda en la barra de direcciones y en el historial de quien lo abra, y cualquiera que tenga el enlace puede leerlo.

- **Longitud.** Como máximo 16.384 caracteres en total, el límite que el sitio aplica a todo valor después del `#`; si lo compartido es más largo, no hay enlace, y la ventana emergente indica su longitud.
- **Al abrir un enlace.** Los dos campos se rellenan como si los hubieras escrito, y la página resuelve. Después, los valores salen de la dirección de la página al instante, sin ninguna solicitud, así que al recargar, o con el propio botón Compartir de la página, no se lleva nada.
