## O que faz

Esta ferramenta é um linter para objetos de configuração do F5 Distributed Cloud (XC). Cole um objeto origin_pool, http_loadbalancer, ou app_firewall - da visão JSON do Console ou da API - e ela sinaliza configurações que são arriscadas, surpreendentes, ou prováveis erros, cada uma com uma severidade e uma explicação curta fundamentada na documentação da F5. Roda inteiramente no seu navegador, e não introduz nenhum schema novo: cada regra reusa as estruturas de objeto verificadas para as outras ferramentas desta família.

## O que ela verifica

Para um origin pool, o linter sinaliza TLS para o origin com verificação do servidor pulada (a conexão é criptografada mas o certificado do origin não é validado), SNI desabilitado, texto puro para o origin, um health check ausente, e um único origin server sem redundância. Para um HTTP load balancer, ela sinaliza nenhum WAF anexado, um listener HTTP puro sem HTTPS, HTTPS configurado sem um redirect de HTTP para HTTPS, uma rota que desabilita o WAF, uma rota catch-all colocada antes de outras rotas (que nunca conseguem dar match sob avaliação por primeiro match), e um domínio wildcard misturado com seu apex. Para um WAF, ela sinaliza modo de monitoramento (detecta mas não bloqueia) e threat campaigns desabilitados.

## Severidade e fundamentação

Cada finding carrega uma severidade - alta, aviso, ou info - e a lista é ordenada com a mais séria primeiro. Alta é reservada para uma configuração que enfraquece materialmente a segurança, como pular a verificação do origin. Aviso cobre configurações que geralmente estão erradas, como nenhum WAF ou uma rota sombreada. Info cobre coisas que vale saber mas frequentemente são intencionais, como um único origin. Cada regra cita a fonte da F5 na qual se baseia, então um flag é um ponto de partida para uma decisão em vez de um veredito - algumas dessas configurações são a escolha certa no contexto, e o linter diz por que cada uma importa para que você decida.

## O que ela não é

O linter lê um objeto por vez e raciocina apenas sobre o que está dentro dele. Ele não consegue ver se um WAF referenciado por nome está ele mesmo em modo de monitoramento, ou se um origin pool referenciado por uma rota carrega um peso - esses vivem em outros objetos. É uma primeira passada rápida sobre as próprias configurações de um único objeto, não uma auditoria completa de configuração.

## Compartilhar resultado

Abaixo dos achados, o botão **Compartilhar resultado** cria um link para esta página, só quando você clica, que leva uma cópia do objeto depois do `#`, nunca o objeto como foi colado. Um objeto de origin pool, load balancer ou WAF pode conter segredos que o linter nunca lê. O schema do F5 Distributed Cloud os marca: SecretType, "used in an object to indicate a sensitive/confidential field" (usado num objeto para indicar um campo confidencial), guarda o segredo em claro (`clear_secret_info.url`: "For string:/// scheme, Secret needs to be encoded Base64 format", o segredo vai codificado em Base64) ou cifrado pelo Blindfold (`blindfold_secret_info.location`) ([referência de API do XC](https://docs.cloud.f5.com/docs-v2/api/views-http-loadbalancer), lida em 2026-11-01): a chave privada de um certificado, o `secret_value` de um header ou cookie, a chave de um cliente mTLS. O `value` simples de um header ou cookie que um load balancer adiciona ("Exclusive with [secret_value]") também é um lugar comum para o segredo compartilhado de uma origem. O linter lê quais configurações existem e alguns nomes e domínios, nunca esses valores. Por isso a cópia troca cada segredo SecretType e cada valor de header ou cookie adicionado por `[redacted]`, e mantém todo o resto como foi colado. Antes de oferecer o link, a página lê a cópia de novo e precisa dar o mesmo resultado no linter, senão não há link; depois a cópia passa por uma busca de credenciais que ainda estejam lá (uma chave privada fora de SecretType, o valor de um matcher do header `Authorization`, um JWT, uma senha numa URL, como nas outras ferramentas do site): qualquer uma impede o link, e o popover diz a linha; um valor cujo nome só parece de segredo é citado no popover.

O popover diz primeiro o que o link leva e então oferece Copiar link e, onde o navegador tiver, a tela de compartilhamento do sistema; o endereço da página não muda. Ele também diz quantos valores foram trocados, e que o objeto cita os pools, os hosts e os domínios dele, e pode citar o tenant e o namespace. Quando a cópia trocou só valores de header ou de cookie (nenhum deles um valor de `Authorization` ou de um nome que pareça de segredo, e nada mais no objeto uma credencial), uma opção logo abaixo da primeira linha, **Incluir no link os valores de header e cookie trocados**, permite mandá-los mesmo assim: ela vem desmarcada toda vez que o popover abre; marcada, o link leva o objeto como foi colado, e o popover avisa que valores de header e cookie podem conter tokens ou o segredo compartilhado de uma origem. A opção nunca aparece ao lado de um segredo SecretType, nem quando uma credencial já impediu o link.

A [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (seção 3.5, lida em 2026-11-01) diz que o fragmento é "separated from the rest of the URI prior to a dereference" (separado do resto do URI antes de o recurso ser buscado), então o que vem depois do `#` não é enviado ao servidor quando o link é aberto; fica na barra de endereço e no histórico de quem abre, e qualquer pessoa com o link consegue lê-lo.

- **Tamanho.** No máximo 16.384 caracteres no total, o limite que o site usa para todo valor depois do `#`; um compartilhamento maior não ganha link, e o popover diz o tamanho.
- **Ao abrir um link.** A cópia (ou, com a opção marcada, o objeto) preenche a caixa como se tivesse sido colada, e a página passa o linter. Os valores então saem do endereço da página na hora, sem nenhuma requisição, então recarregar a página ou usar o botão Compartilhar da própria página não leva nada.
