## O que faz

Esta ferramenta responde a uma pergunta precisa do F5 Distributed Cloud (XC): dados vários HTTP load balancers e suas listas de domínio, qual deles serve um hostname específico? Cole os load balancers como um array JSON e um hostname de teste, e o resolver nomeia o load balancer e a entrada de domínio vencedores, mostra o porquê, e sinaliza os perigos de configuração que fazem o match de domínio dar errado. Roda inteiramente no seu navegador.

## Como o XC escolhe um load balancer

Quando uma requisição chega, o XC já estreitou as coisas para os load balancers que compartilham o IP e porta de destino (a advertise policy). Entre esses, ele escolhe o match de domínio mais específico. Um FQDN exato - app.example.com listado literalmente - vence um wildcard como *.example.com. O hostname no qual ele casa vem do valor SNI quando o cliente usa HTTPS, ou do header Host quando o cliente usa HTTP puro. Se nada dá match e um load balancer está marcado como o Default para aquela advertise policy, o Default pega a requisição; se não há Default, o hostname não é capturado de forma alguma.

## Wildcards e o apex

Um domínio wildcard é um match de sufixo: *.example.com cobre foo.example.com, mas não cobre o apex example.com, e um certificado TLS wildcard só cobre um único label. É por isso que servir tanto www.example.com (ou qualquer subdomínio) quanto o example.com puro precisa que o apex seja adicionado como seu próprio domínio. A ferramenta torna a distinção wildcard-versus-apex explícita em cada resultado.

## Os perigos que ela sinaliza

O match de domínio quebra de algumas formas reconhecíveis, e a ferramenta avisa sobre cada uma. Configurar tanto um wildcard (*.example.com) quanto seu apex (example.com) em load balancers diferentes que usam certificados automáticos é algo que a F5 especificamente desaconselha. Dois load balancers reivindicando o mesmo domínio exato, ou dois marcados como Default na mesma advertise policy (só um é permitido), são conflitos. Um hostname que dá match em duas entradas com especificidade igual é ambíguo. E um hostname multi-label que dá match em um wildcard vai rotear mas pode falhar a validação do certificado, já que o certificado wildcard cobre apenas um label.

## Compartilhar resultado

Abaixo da resolução, o botão **Compartilhar resultado** cria um link para esta página, só quando você clica, que leva a lista de load balancers como foi colada e o hostname depois do `#`. O popover diz primeiro o que o link leva e então oferece Copiar link e, onde o navegador tiver, a tela de compartilhamento do sistema; o endereço da página não muda. Os nomes e os domínios dos load balancers podem ser hosts internos de uma organização: o popover pede para você conferir. A resolução lê cada nome e domínio, então nada é cortado. Antes de oferecer o link, cada campo passa por uma busca de credenciais que um padrão define: uma chave privada PEM, uma linha `Authorization` ou `Proxy-Authorization` com qualquer esquema ([RFC 9110](https://www.rfc-editor.org/rfc/rfc9110), seções 11.6.2 e 11.7.2: o valor "consists of credentials", consiste em credenciais), uma linha `Cookie` ou `Set-Cookie` com valor ([RFC 6265](https://www.rfc-editor.org/rfc/rfc6265), seção 8.4: os servidores "commonly store a nonce (or "session identifier") in a cookie", costumam guardar num cookie um identificador de sessão), um JWT ([RFC 7519](https://www.rfc-editor.org/rfc/rfc7519), seção 1), uma senha numa URL ([RFC 3986](https://www.rfc-editor.org/rfc/rfc3986), seção 3.2.1), um access key ID da AWS ou um valor `ENC` do FortiOS, e duas coisas que o próprio schema do F5 Distributed Cloud define: um segredo SecretType, uma URL de `clear_secret_info` ou uma location de `blindfold_secret_info` (a [referência de API do XC](https://docs.cloud.f5.com/docs-v2/api/views-http-loadbalancer): "SecretType is used in an object to indicate a sensitive/confidential field"), e um matcher do header `Authorization` com um valor literal; todas lidas em 2026-11-01. Qualquer um deles impede o link: o popover diz a linha, e você troca o valor por um placeholder e clica de novo. Um valor cujo nome só parece de segredo (um membro JSON `token`, um `token=` numa query, um matcher de `X-Api-Key` ou de cookie) não impede o link; o popover cita o primeiro para você conferir.

A [RFC 3986](https://www.rfc-editor.org/rfc/rfc3986) (seção 3.5, lida em 2026-11-01) diz que o fragmento é "separated from the rest of the URI prior to a dereference" (separado do resto do URI antes de o recurso ser buscado), então o que vem depois do `#` não é enviado ao servidor quando o link é aberto; fica na barra de endereço e no histórico de quem abre, e qualquer pessoa com o link consegue lê-lo.

- **Tamanho.** No máximo 16.384 caracteres no total, o limite que o site usa para todo valor depois do `#`; um compartilhamento maior não ganha link, e o popover diz o tamanho.
- **Ao abrir um link.** Os dois campos são preenchidos como se tivessem sido digitados, e a página resolve. Os valores então saem do endereço da página na hora, sem nenhuma requisição, então recarregar a página ou usar o botão Compartilhar da própria página não leva nada.
